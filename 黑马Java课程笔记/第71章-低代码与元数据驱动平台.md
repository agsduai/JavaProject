# 第71章 低代码与元数据驱动平台

低代码的本质是"用元数据描述应用，由统一引擎解释执行"——代码写一次（引擎），业务配置无数次。它补齐了前面所有"工程能力"的产品化出口：49 章建模、58 章规则、61 章流程、55 章多租户、68 章权限、64 章 API 在这里组装成一个平台。本章按「低代码全景 → 元数据建模 → 动态表单 → 元数据权限 → 规则联动 → 代码生成 vs 解释 → 版本管理 → 多租户扩展 → 性能与安全边界 → API 集成 → 审批平台案例」的顺序讲。所有示例仍是纯 JDK：元数据生成 DDL、动态表单条件显示与双端校验、字段行级权限矩阵、三类触发规则、DAO 代码生成、表单版本隔离、租户继承覆盖与升级影响、SQL 白名单与元数据缓存、通用数据 API 全部真实运行。

### 71-01 低代码全景：从表单到流程

**知识点**
- **低代码的本质是"用元数据描述应用，而不是用代码写应用"**：把"表单长什么样、字段什么类型、谁能看、走什么流程"变成**可配置的元数据**，由**统一引擎**解释执行——**代码只写一次（引擎），业务配置无数次**。
- **低代码的三个层次**：**表单/页面搭建**（拖拽生成 UI）、**数据建模**（实体/字段/关系）、**流程编排**（审批流/自动化）——**层次越高，可配置的比例越大，灵活度越低**（52-05 的权衡）。
- **适用与不适用**：**适用**（审批流、后台管理、数据采集、报表看板——结构固定、变化频繁）；**不适用**（高并发交易、复杂算法、强交互体验）——**低代码是"企业内部工具的加速器"，不是通用开发平台**。
- **与 49/58 章的关系**：低代码的"元数据"就是 49 章领域模型的**数据化**；低代码的"规则配置"就是 58 章规则引擎——**本章把它们组装成平台**。
- **核心矛盾**：**灵活性 vs 可控性**——配置能力越强（允许自定义脚本/复杂逻辑），越接近写代码，也越难治理（性能/安全/可维护性 71-09）。
- 易错点：指望低代码替代所有开发（复杂业务必然要写代码，应留"扩展点"）；元数据设计不考虑版本（改字段破坏在途数据 71-07）；权限靠前端隐藏（71-04）。

**示例代码**
```java
import java.util.LinkedHashMap;

                new Layer("表单/页面", "字段、布局、校验、联动", "复杂交互需自定义组件"),

                new Layer("流程编排", "节点、审批人、条件分支", "复杂业务规则需扩展点"));

        }

                {"后台管理系统", "适合", "CRUD 为主、页面多"},
                {"数据采集表单", "适合", "字段多、校验规则可配置"},
                {"核心交易链路", "不适合", "高并发 + 强一致 + 复杂逻辑"},

        for (String[] r : rows) {

        }
        System.out.println();
    }

    static void architecture() {
        System.out.println("【低代码平台的组成】");
        Map<String, String> parts = new LinkedHashMap<>();
        parts.put("元数据存储", "实体/表单/流程/权限的配置（数据库存 JSON）");
        parts.put("统一引擎", "解析元数据 -> 渲染 UI / 执行流程 / 校验");
        parts.put("扩展点", "自定义组件、脚本钩子、外部 API（留出写代码的出口）");
        parts.put("治理", "版本、发布、权限、审计（71-07/71-04）");
        parts.forEach((k, v) -> System.out.printf("  %-8s %s%n", k, v));
        System.out.println();
        System.out.println("  一句话：配置描述「做什么」，引擎决定「怎么做」，扩展点处理「配置不了的」");
    }

    public static void main(String[] args) {
        layers();
        fitMatrix();
        architecture();
    }
}
```

### 71-02 元数据建模：实体、字段、关系

**知识点**
- **元数据是低代码的"数据库 schema 的 schema"（元-元模型）**：`EntityMeta`（实体名/表名/字段列表）、`FieldMeta`（字段名/类型/必填/默认值/校验规则）、`RelationMeta`（1:1、1:N、N:M）——**用数据描述数据结构**。
- **字段类型的封闭枚举**：`string/int/decimal/date/datetime/bool/enum/text/ref`——**类型封闭是可控性的前提**（开放类型 = 无法生成 UI/无法校验/无法索引）。
- **元数据的版本与演进**（71-07 的前置）：加字段（兼容）、改类型（不兼容，需迁移）、删字段（危险）——**与 41-09 expand-contract 同款纪律**。
- **物理存储的两种策略**：**宽表**（每个实体一张物理表，字段一一对应——查询快、改结构要 DDL）与**EAV/JSON**（一行一属性或整条 JSON——灵活、查询慢）——**主流是"宽表 + JSON 扩展列"的混合**（46-05 的半结构化思想）。
- **与 63 章维度建模的关系**：低代码的实体建模是"业务对象的建模"，数仓维度建模是"分析视角的建模"——**同为建模，目标不同**（前者支撑 CRUD，后者支撑分析）。
- 易错点：字段类型开放（允许任意类型 -> 引擎失控）；元数据不带版本（改字段破坏历史数据）；关系只存 ID 不做级联策略（删除留孤儿）；物理表与元数据不一致（漂移）。

**示例代码**
```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class MetadataModeling {
    enum FieldType {
        STRING, INT, DECIMAL, DATE, DATETIME, BOOL, ENUM, TEXT, REF
    }

    record FieldMeta(String name, String label, FieldType type, boolean required,
                     String defaultValue, List<String> enumValues, String refEntity) {
        String toDdl() {
            String sqlType = switch (type) {
                case STRING -> "VARCHAR(255)";
                case INT -> "BIGINT";
                case DECIMAL -> "DECIMAL(18,2)";
                case DATE -> "DATE";
                case DATETIME -> "DATETIME";
                case BOOL -> "TINYINT(1)";
                case ENUM -> "VARCHAR(64)";
                case TEXT -> "TEXT";
                case REF -> "BIGINT";
            };
            return name + " " + sqlType + (required ? " NOT NULL" : " NULL");
        }
    }

    record EntityMeta(String name, String table, List<FieldMeta> fields,
                      Map<String, String> relations) {
        String toDdl() {
            StringBuilder sb = new StringBuilder("CREATE TABLE " + table + " (\n  id BIGINT PRIMARY KEY,\n");
            for (FieldMeta f : fields) {
                sb.append("  ").append(f.toDdl()).append(",\n");
            }
            relations.forEach((field, target) ->
                    sb.append("  INDEX idx_").append(field).append(" (").append(field).append("),\n"));
            return sb.append("  created_at DATETIME NOT NULL\n)").toString();
        }
    }

    static void buildDemo() {
        List<FieldMeta> fields = new ArrayList<>(List.of(
                new FieldMeta("title", "标题", FieldType.STRING, true, null, List.of(), null),
                new FieldMeta("amount", "金额", FieldType.DECIMAL, true, "0.00", List.of(), null),
                new FieldMeta("category", "类别", FieldType.ENUM, true, "TRAVEL",
                        List.of("TRAVEL", "MEAL", "OFFICE"), null),
                new FieldMeta("apply_date", "申请日期", FieldType.DATE, true, null, List.of(), null),
                new FieldMeta("applicant_id", "申请人", FieldType.REF, true, null, List.of(), "user"),
                new FieldMeta("remark", "备注", FieldType.TEXT, false, null, List.of(), null)));
        Map<String, String> relations = new LinkedHashMap<>();
        relations.put("applicant_id", "user");
        EntityMeta expense = new EntityMeta("报销单", "lc_expense", fields, relations);

        System.out.println("【实体元数据】" + expense.name() + " -> 表 " + expense.table());
        expense.fields().forEach(f -> System.out.printf(
                "  %-14s %-8s 类型=%-9s 必填=%-5s 默认=%s%n",
                f.name(), f.label(), f.type(), f.required(),
                f.defaultValue() == null ? "-" : f.defaultValue()));
        System.out.println("  关系：" + expense.relations());
        System.out.println();
        System.out.println("【由元数据生成 DDL】");
        System.out.println(expense.toDdl());
        System.out.println();
    }

    static void storageStrategy() {
        System.out.println("【物理存储两种策略】");
        String[][] rows = {
                {"宽表", "每实体一张表，字段一一对应", "查询快、可索引；改结构要 DDL"},
                {"JSON 列", "主键 + 整条 JSON", "灵活；查询/索引受限"},
                {"混合（推荐）", "常用字段宽表 + 扩展字段 JSON", "兼顾性能与灵活（46-05 半结构化）"},
        };
        for (String[] r : rows) {
            System.out.printf("  %-10s %-34s %s%n", r[0], r[1], r[2]);
        }
        System.out.println();
        System.out.println("  演进纪律：加字段兼容；改类型走 expand-contract（41-09）");
    }

    public static void main(String[] args) {
        buildDemo();
        storageStrategy();
    }
}
```

### 71-03 动态表单渲染

**知识点**
- **动态表单 = 元数据 -> UI 描述 -> 渲染**：后端返回表单定义（字段 + 布局 + 校验 + 联动），前端按定义渲染组件——**一份定义驱动 Web/App/小程序多端**（70-08 的多端一致思想）。
- **表单定义的三层**：**字段层**（类型/校验/默认值）、**布局层**（分组/栅格/顺序）、**联动层**（A 变化影响 B 的显隐/可选值/必填）——**联动是最复杂的一层**（声明式 vs 脚本）。
- **校验的两处执行**：**前端即时校验**（体验）+ **后端强制校验**（安全，36 章）——**前端校验永远不可信**，元数据里的规则必须后端再跑一遍。
- **联动的实现方式**：**声明式规则**（`when category == TRAVEL then show hotel_field`——可控、可校验，推荐）、**脚本钩子**（JS/Groovy 表达式——灵活但难治理，71-09）。
- **与 58 章的关系**：表单联动就是"小规则引擎"——**用规则引擎的模型（条件-动作）描述联动**，避免自己发明一套语法。
- 易错点：只在前端校验（绕过）；联动写死在组件里（改配置要发版）；表单定义无版本（已提交数据的展示错乱）；字段类型与组件映射硬编码（新增类型要改多处）。

**示例代码**
```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class DynamicForm {
    record FormField(String name, String label, String type, boolean required,
                     String visibleWhen, String optionsFrom) {
    }

    record FormDef(String id, String title, List<FormField> fields) {
    }

    /** 联动求值：visibleWhen 形如 "category=TRAVEL" */
    static boolean visible(FormField f, Map<String, String> values) {
        if (f.visibleWhen() == null || f.visibleWhen().isBlank()) {
            return true;
        }
        String[] parts = f.visibleWhen().split("=");
        return parts[1].equals(values.getOrDefault(parts[0].trim(), ""));
    }

    /** 校验：必填 + 类型 + 条件必填 */
    static List<String> validate(FormDef def, Map<String, String> values) {
        List<String> errors = new ArrayList<>();
        for (FormField f : def.fields()) {
            boolean shouldShow = visible(f, values);
            if (!shouldShow) {
                continue;
            }
            String v = values.get(f.name());
            if (f.required() && (v == null || v.isBlank())) {
                errors.add(f.label() + "：必填");
                continue;
            }
            if (v == null || v.isBlank()) {
                continue;
            }
            if (f.type().equals("number") && !v.matches("-?\\d+(\\.\\d+)?")) {
                errors.add(f.label() + "：必须是数字");
            }
            if (f.type().equals("date") && !v.matches("\\d{4}-\\d{2}-\\d{2}")) {
                errors.add(f.label() + "：日期格式应为 yyyy-MM-dd");
            }
        }
        return errors;
    }

    /** 渲染：字段类型 -> 组件（声明式映射） */
    static String component(String type) {
        return switch (type) {
            case "string" -> "Input";
            case "number" -> "NumberInput";
            case "date" -> "DatePicker";
            case "enum" -> "Select";
            case "text" -> "TextArea";
            case "bool" -> "Switch";
            default -> "Input";
        };
    }

    public static void main(String[] args) {
        FormDef def = new FormDef("f-expense", "报销申请", List.of(
                new FormField("title", "标题", "string", true, null, null),
                new FormField("category", "类别", "enum", true, null, "dict.category"),
                new FormField("amount", "金额", "number", true, null, null),
                new FormField("apply_date", "申请日期", "date", true, null, null),
                new FormField("hotel_city", "出差城市", "string", true,
                        "category=TRAVEL", null),
                new FormField("meal_count", "餐补天数", "number", true,
                        "category=MEAL", null),
                new FormField("remark", "备注", "text", false, null, null)));

        System.out.println("【表单定义】" + def.title());
        def.fields().forEach(f -> System.out.printf(
                "  %-12s %-6s 组件=%-12s 必填=%-5s 条件=%s%n",
                f.name(), f.label(), component(f.type()), f.required(),
                f.visibleWhen() == null ? "始终显示" : f.visibleWhen()));

        System.out.println();
        System.out.println("【场景一：类别=TRAVEL，缺字段】");
        Map<String, String> v1 = new LinkedHashMap<>();
        v1.put("title", "杭州出差");
        v1.put("category", "TRAVEL");
        v1.put("amount", "1200.50");
        v1.put("apply_date", "2026-11-18");
        validate(def, v1).forEach(e -> System.out.println("  错误：" + e));

        System.out.println();
        System.out.println("【场景二：补全后通过】");
        v1.put("hotel_city", "杭州");
        List<String> errs = validate(def, v1);
        System.out.println("  校验结果：" + (errs.isEmpty() ? "通过" : errs));

        System.out.println();
        System.out.println("【场景三：类别=MEAL，出差城市不显示】");
        Map<String, String> v2 = new LinkedHashMap<>(v1);
        v2.put("category", "MEAL");
        v2.remove("hotel_city");
        System.out.println("  校验结果：" + (validate(def, v2).isEmpty() ? "通过"
                : validate(def, v2)));

        System.out.println();
        System.out.println("  铁律：前端校验是体验，后端必须按同一份元数据再校验一遍（36 章）");
    }
}
```

### 71-04 元数据驱动的权限

**知识点**
- **低代码的权限必须"配在元数据上"，而不是写死在代码里**：字段级（谁能看/改哪个字段）、行级（谁能看哪些数据）、操作级（谁能提交/审批/删除）——**权限规则作为元数据的一部分，随表单/实体一起版本化**。
- **三层的实现对应**：**字段级**（渲染时过滤 + 后端脱敏 68-03）、**行级**（查询时注入数据范围 68-05）、**操作级**（按钮显隐 + 后端校验）——**前端只管显隐，后端必须强校验**（71-03 同款铁律）。
- **权限与流程的联动**：审批节点的"当前处理人"能看到字段，其他人看不到——**权限是动态的（依赖角色 + 流程状态）**，比静态 RBAC 复杂（68-05 的 ABAC 场景）。
- **配置权限本身要有权限**：谁能改表单定义、谁能改权限矩阵——**平台管理员与业务管理员分离**（51-07 最小权限）。
- **与 55/68 章的关系**：多租户 SaaS 的租户隔离（55-04）+ 数据权限（68-05）——**低代码平台的权限是两者的组合**：租户内按角色 + 字段脱敏。
- 易错点：权限只做按钮显隐（接口裸奔）；字段权限只在前端过滤（接口返回全量）；流程状态与权限不联动（离职人员还能审批）；改权限无审计（68-09）。

**示例代码**
```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class MetadataPermission {
    /** 字段权限规则：角色 + 可见/可编辑 + 条件 */
    record FieldRule(String field, String role, boolean readable, boolean writable,
                     String condition) {
    }

    /** 行级规则：数据范围 */
    record RowRule(String role, String scope) {
    }

    static final List<FieldRule> fieldRules = new ArrayList<>();
    static final List<RowRule> rowRules = new ArrayList<>();

    static {
        fieldRules.add(new FieldRule("title", "*", true, true, null));
        fieldRules.add(new FieldRule("amount", "employee", true, true, "status=DRAFT"));
        fieldRules.add(new FieldRule("amount", "manager", true, false, null));
        fieldRules.add(new FieldRule("amount", "finance", true, false, null));
        fieldRules.add(new FieldRule("bank_account", "employee", true, true, "status=DRAFT"));
        fieldRules.add(new FieldRule("bank_account", "manager", false, false, null));
        fieldRules.add(new FieldRule("bank_account", "finance", true, false, null));
        fieldRules.add(new FieldRule("remark", "manager", true, true, null));

        rowRules.add(new RowRule("employee", "OWNER"));
        rowRules.add(new RowRule("manager", "DEPT"));
        rowRules.add(new RowRule("finance", "ALL"));
    }

    /** 字段可见性：角色匹配 + 条件满足 */
    static boolean canRead(String field, String role, Map<String, String> ctx) {
        for (FieldRule r : fieldRules) {
            if (!r.field().equals(field)) {
                continue;
            }
            if (!r.role().equals("*") && !r.role().equals(role)) {
                continue;
            }
            if (r.condition() != null) {
                String[] p = r.condition().split("=");
                if (!p[1].equals(ctx.getOrDefault(p[0].trim(), ""))) {
                    continue;
                }
            }
            return r.readable();
        }
        return false;
    }

    static boolean canWrite(String field, String role, Map<String, String> ctx) {
        for (FieldRule r : fieldRules) {
            if (!r.field().equals(field)) {
                continue;
            }
            if (!r.role().equals("*") && !r.role().equals(role)) {
                continue;
            }
            if (r.condition() != null) {
                String[] p = r.condition().split("=");
                if (!p[1].equals(ctx.getOrDefault(p[0].trim(), ""))) {
                    continue;
                }
            }
            return r.writable();
        }
        return false;
    }

    /** 行级过滤 */
    static List<String> visibleRows(String role, List<String> rows) {
        String scope = rowRules.stream().filter(r -> r.role().equals(role))
                .map(RowRule::scope).findFirst().orElse("NONE");
        return switch (scope) {
            case "ALL" -> rows;
            case "DEPT" -> rows.stream().filter(r -> r.startsWith("dept:")).toList();
            case "OWNER" -> rows.stream().filter(r -> r.startsWith("owner:")).toList();
            default -> List.of();
        };
    }

    /** 渲染字段列表（可见字段） */
    static List<String> renderFields(List<String> allFields, String role,
                                     Map<String, String> ctx) {
        List<String> out = new ArrayList<>();
        for (String f : allFields) {
            if (canRead(f, role, ctx)) {
                out.add(f);
            }
        }
        return out;
    }

    public static void main(String[] args) {
        List<String> allFields = List.of("title", "amount", "bank_account", "remark");
        Map<String, String> draft = new LinkedHashMap<>();
        draft.put("status", "DRAFT");
        Map<String, String> approved = new LinkedHashMap<>();
        approved.put("status", "APPROVED");

        System.out.println("【字段级权限：草稿态】");
        for (String role : new String[]{"employee", "manager", "finance"}) {
            System.out.printf("  %-8s 可见=%-30s 可编辑=%s%n", role,
                    renderFields(allFields, role, draft),
                    allFields.stream().filter(f -> canWrite(f, role, draft)).toList());
        }

        System.out.println();
        System.out.println("【字段级权限：审批后（employee 不能再改金额）】");
        System.out.printf("  employee 可编辑=%s%n",
                allFields.stream().filter(f -> canWrite(f, "employee", approved)).toList());

        System.out.println();
        System.out.println("【行级权限】");
        List<String> rows = List.of("owner:o-1", "owner:o-2", "dept:d-1", "dept:d-2",
                "other:x-1");
        for (String role : new String[]{"employee", "manager", "finance"}) {
            System.out.printf("  %-8s -> %s%n", role, visibleRows(role, rows));
        }

        System.out.println();
        System.out.println("  铁律：前端按元数据显隐，后端按同一份元数据强校验（68-05）");
        System.out.println("  平台管理员 vs 业务管理员分离；权限变更进审计（68-09）");
    }
}
```

### 71-05 规则引擎与低代码联动

**知识点**
- **低代码的"业务逻辑"大多可以表达成规则**：金额校验（>5000 需总监审批）、字段联动（选了差旅才显示酒店）、自动计算（合计 = 明细求和）——**把这些交给规则引擎（58 章），低代码平台专注 UI 与流程**。
- **规则的三类用途**：**校验规则**（提交时校验）、**计算规则**（字段自动计算）、**路由规则**（流程走向）——**统一用"条件-动作"模型**，避免每类各写一套。
- **规则与元数据的绑定**：规则挂在"实体 + 字段 + 触发时机（beforeSave/afterLoad/onSubmit）"上——**规则也是元数据的一部分**（71-04 权限同款设计）。
- **避免"配置地狱"**：规则数量增长后要能**分组/优先级/冲突检测**（58-05）——**低代码平台要把规则治理能力内建**，否则配置越堆越乱。
- **与 58 章的差异**：58 章是独立风控引擎（高吞吐、低延迟）；低代码的规则是"配置驱动的轻量引擎"（低频、可调试）——**同一模型，不同量级**。
- 易错点：规则堆在表单事件里（散落无治理）；计算规则用脚本（不可校验）；规则无优先级（冲突时结果随机）；规则变更不测试（配置错影响全租户）。

**示例代码**
```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class RuleIntegration {
    enum Trigger {
        BEFORE_SAVE, AFTER_LOAD, ON_SUBMIT
    }

    record RuleDef(String id, String entity, Trigger trigger, String when,
                   String action, int priority) {
    }

    static final List<RuleDef> rules = new ArrayList<>();

    static {
        rules.add(new RuleDef("R-1", "expense", Trigger.ON_SUBMIT,
                "amount>5000", "requireDirectorApproval", 100));
        rules.add(new RuleDef("R-2", "expense", Trigger.BEFORE_SAVE,
                "category=TRAVEL && hotelCity=null", "setError(hotelCity, 必填)", 100));
        rules.add(new RuleDef("R-3", "expense", Trigger.AFTER_LOAD,
                "always", "compute(total = sum(items))", 10));
        rules.add(new RuleDef("R-4", "expense", Trigger.ON_SUBMIT,
                "amount<=0", "setError(amount, 必须大于0)", 100));
    }

    /** 极简条件求值：支持 k>n 与 k=v 与 always */
    static boolean match(String when, Map<String, String> data) {
        if (when.equals("always")) {
            return true;
        }
        if (when.contains("&&")) {
            for (String part : when.split("&&")) {
                if (!match(part.trim(), data)) {
                    return false;
                }
            }
            return true;
        }
        if (when.contains(">")) {
            String[] p = when.split(">");
            try {
                double v = Double.parseDouble(data.getOrDefault(p[0].trim(), "0"));
                return v > Double.parseDouble(p[1].trim());
            } catch (NumberFormatException e) {
                return false;
            }
        }
        if (when.contains("<=")) {
            String[] p = when.split("<=");
            try {
                double v = Double.parseDouble(data.getOrDefault(p[0].trim(), "0"));
                return v <= Double.parseDouble(p[1].trim());
            } catch (NumberFormatException e) {
                return false;
            }
        }
        if (when.contains("=")) {
            String[] p = when.split("=");
            String actual = data.get(p[0].trim());
            return p[1].trim().equals(actual == null || actual.isEmpty() ? "null" : actual);
        }
        return false;
    }

    /** 执行某触发时机的规则（按优先级降序） */
    static List<String> fire(String entity, Trigger trigger, Map<String, String> data) {
        List<RuleDef> matched = new ArrayList<>();
        for (RuleDef r : rules) {
            if (r.entity().equals(entity) && r.trigger() == trigger && match(r.when(), data)) {
                matched.add(r);
            }
        }
        matched.sort((a, b) -> Integer.compare(b.priority(), a.priority()));
        List<String> actions = new ArrayList<>();
        for (RuleDef r : matched) {
            actions.add(r.id() + " -> " + r.action());
        }
        return actions;
    }

    public static void main(String[] args) {
        System.out.println("【规则配置（挂在实体+触发时机上）】");
        rules.forEach(r -> System.out.printf("  %-4s %-8s %-12s when=%-30s -> %s%n",
                r.id(), r.entity(), r.trigger(), r.when(), r.action()));

        Map<String, String> data = new LinkedHashMap<>();
        data.put("amount", "8000");
        data.put("category", "TRAVEL");
        data.put("hotelCity", "");

        System.out.println();
        System.out.println("【BEFORE_SAVE】");
        fire("expense", Trigger.BEFORE_SAVE, data).forEach(a -> System.out.println("  " + a));

        System.out.println();
        System.out.println("【ON_SUBMIT】");
        fire("expense", Trigger.ON_SUBMIT, data).forEach(a -> System.out.println("  " + a));

        System.out.println();
        System.out.println("【AFTER_LOAD（计算规则）】");
        fire("expense", Trigger.AFTER_LOAD, data).forEach(a -> System.out.println("  " + a));

        System.out.println();
        System.out.println("  规则治理：优先级 + 冲突检测 + 变更测试（58-05/58-09）");
        System.out.println("  计算规则用声明式而非脚本，才能被引擎校验与调试");
    }
}
```

**课后练习**

2. 增加"规则冲突检测"：同一字段被两条规则设置不同值时报错，说明为何需要优先级与冲突检查。

### 71-06 代码生成 vs 解释执行

**知识点**
- **低代码的执行有两条路线**：**解释执行**（运行时解析元数据 -> 动态执行，改配置即时生效）与**代码生成**（把元数据生成 Java/前端代码 -> 编译部署，运行快但改配置要重新生成）。
- **解释执行的代价**：每次请求都要解析元数据（可缓存）、动态分支难以优化、调试链路长——**适合配置频繁变化的场景**（后台管理）。
- **代码生成的代价**：构建链路长（生成 -> 编译 -> 发布 41 章）、配置与代码不同步（改了元数据忘重新生成）——**适合配置稳定、性能敏感的场景**。
- **混合方案（主流）**：**元数据解释 + 生成"类型安全的访问层"**——UI 与校验走解释（灵活），数据访问走生成的 DAO（性能与类型安全）——**各取所长**。
- **与 24/60 章的关系**：代码生成就是"自己写一个注解处理器/模板引擎"（24-01 自动配置、60-02 IOC 都是"生成/装配"思想）——**低代码平台是这类思想的工程化**。
- 易错点：全量解释导致性能差（每个字段都反射）；代码生成后元数据变更不同步（线上数据错乱）；生成物被手工修改（下次生成被覆盖）；无生成版本记录（回滚困难）。

**示例代码**
```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class CodegenVsInterpretation {
    record Field(String name, String type) {
    }

    record Entity(String name, List<Field> fields) {
    }

    /** 解释执行：运行时按元数据取值/赋值（反射式，简化用 Map） */
    static Object getInterpreted(Map<String, Object> row, String field) {
        return row.get(field);
    }

    static void setInterpreted(Map<String, Object> row, String field, Object value) {
        row.put(field, value);
    }

    /** 代码生成：产出 Java 源码（DAO + DTO），编译后类型安全 */
    static String generateDao(Entity e) {
        StringBuilder sb = new StringBuilder();
        String cls = toPascal(e.name());
        sb.append("// 由元数据生成，请勿手工修改\n");
        sb.append("public class ").append(cls).append("Dao {\n");
        for (Field f : e.fields()) {
            sb.append("    public ").append(javaType(f.type())).append(" get")
                    .append(toPascal(f.name())).append("() { ... }\n");
        }
        sb.append("}\n");
        return sb.toString();
    }

    static String javaType(String type) {
        return switch (type) {
            case "string", "text" -> "String";
            case "int" -> "Long";
            case "decimal" -> "BigDecimal";
            case "date" -> "LocalDate";
            case "bool" -> "Boolean";
            default -> "Object";
        };
    }

    static String toPascal(String s) {
        StringBuilder sb = new StringBuilder();
        boolean upper = true;
        for (char c : s.toCharArray()) {
            if (c == '_') {
                upper = true;
                continue;
            }
            sb.append(upper ? Character.toUpperCase(c) : c);
            upper = false;
        }
        return sb.toString();
    }

    static void compare() {
        System.out.println("【两条路线对比】");
        String[][] rows = {
                {"解释执行", "运行时解析元数据", "改配置即时生效", "每次请求有解析开销"},
                {"代码生成", "元数据 -> 源码 -> 编译", "运行快、类型安全", "改配置要重新生成+发布"},
                {"混合（推荐）", "UI/校验解释 + DAO 生成", "兼顾灵活与性能", "需治理生成物与元数据同步"},
        };
        for (String[] r : rows) {
            System.out.printf("  %-10s %-26s %-18s %s%n", r[0], r[1], r[2], r[3]);
        }
        System.out.println();
    }

    public static void main(String[] args) {
        Entity expense = new Entity("expense", List.of(
                new Field("title", "string"),
                new Field("amount", "decimal"),
                new Field("apply_date", "date"),
                new Field("approved", "bool")));

        System.out.println("【解释执行：动态取值】");
        Map<String, Object> row = new LinkedHashMap<>();
        row.put("title", "差旅报销");
        row.put("amount", "1200.50");
        row.put("apply_date", "2026-11-18");
        expense.fields().forEach(f -> System.out.printf("  %-12s -> %s%n",
                f.name(), getInterpreted(row, f.name())));

        System.out.println();
        System.out.println("【代码生成：产出源码】");
        System.out.println(generateDao(expense).replace("\n", "\n  "));

        System.out.println();
        compare();
        System.out.println("  生成物治理：标记「请勿手工修改」 + 生成版本号 + 与元数据一致性校验");
    }
}
```

### 71-07 版本与发布管理

**知识点**
- **低代码平台的"发版"是元数据发版**：表单/实体/流程/权限/规则都是版本化对象——**每次发布生成一个不可变版本**，运行中的应用引用某个版本（与 41 章制品不可变同源）。
- **元数据变更的兼容性**：**加字段**（兼容）、**改字段类型**（不兼容，需迁移）、**删字段**（危险，历史数据）——**与 41-09 的 expand-contract 完全一致**（低代码把它自动化）。
- **灰度与回滚**：新版本元数据先给部分租户/用户（41-07 金丝雀）——**低代码的灰度粒度通常是"租户"或"表单"**；**回滚 = 切回旧版本元数据**（秒级，因为数据仍在）。
- **在途数据的处理**（最大难点）：改表单定义后，**已提交的单据要按"提交时的定义"展示**——**表单定义必须带版本，单据记录 version**（否则历史单据字段错位）。
- 与 55/61 章的关系：多租户按租户发布（55-08）、流程实例按版本隔离（61-07）——**同一套版本化思想**。
- 易错点：改定义不升版本（历史单据展示错乱）；直接删字段（数据丢失）；全量发布无灰度（一个租户的配置错影响全部）；回滚只回代码不回元数据。

**示例代码**
```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class VersionManagement {
    record FormVersion(String version, List<String> fields, String status) {
    }

    record FormRecord(String id, String formId, String version, Map<String, String> data) {
    }

    static final Map<String, List<FormVersion>> versions = new LinkedHashMap<>();
    static final List<FormRecord> records = new ArrayList<>();

    static void publish(String formId, List<String> fields, boolean gray) {
        List<FormVersion> list = versions.computeIfAbsent(formId, k -> new ArrayList<>());
        String ver = "v" + (list.size() + 1);
        String status = gray ? "GRAY" : "ACTIVE";
        if (!gray) {
            for (int i = 0; i < list.size(); i++) {
                FormVersion old = list.get(i);
                list.set(i, new FormVersion(old.version(), old.fields(), "DEPRECATED"));
            }
        }
        list.add(new FormVersion(ver, fields, status));
        System.out.printf("  发布 %s %s（%s）：字段 %s%n", formId, ver, status, fields);
    }

    static void submit(String id, String formId, Map<String, String> data) {
        List<FormVersion> list = versions.get(formId);
        FormVersion active = list.stream()
                .filter(v -> v.status().equals("ACTIVE")).findFirst().orElse(null);
        if (active == null) {
            System.out.println("  提交失败：无生效版本");
            return;
        }
        for (String f : data.keySet()) {
            if (!active.fields().contains(f)) {
                System.out.printf("  提交失败：字段 %s 不在 %s 中%n", f, active.version());
                return;
            }
        }
        records.add(new FormRecord(id, formId, active.version(), new LinkedHashMap<>(data)));
        System.out.printf("  提交 %s 使用 %s：%s%n", id, active.version(), data);
    }

    /** 展示：按记录自己的版本渲染（历史单据不受新版本影响） */
    static void render(String recordId) {
        FormRecord r = records.stream().filter(x -> x.id().equals(recordId))
                .findFirst().orElse(null);
        if (r == null) {
            System.out.println("  记录不存在：" + recordId);
            return;
        }
        FormVersion v = versions.get(r.formId()).stream()
                .filter(x -> x.version().equals(r.version())).findFirst().orElse(null);
        System.out.printf("  记录 %s（%s 版本 %s）:%n", r.id(), r.formId(), r.version());
        if (v != null) {
            v.fields().forEach(f -> System.out.printf("    %-10s = %s%n", f,
                    r.data().getOrDefault(f, "（该版本无此字段）")));
        }
        System.out.println("    （渲染字段来自记录自身的版本定义，不受新版本影响）");
    }

    public static void main(String[] args) {
        System.out.println("【发布流程】");
        publish("expense", List.of("title", "amount"), true);
        publish("expense", List.of("title", "amount"), false);

        Map<String, String> d1 = new LinkedHashMap<>();
        d1.put("title", "差旅");
        d1.put("amount", "1200");
        submit("r-1", "expense", d1);

        System.out.println();
        System.out.println("【v3 新增字段（兼容变更）】");
        publish("expense", List.of("title", "amount", "cost_center"), false);
        Map<String, String> d2 = new LinkedHashMap<>();
        d2.put("title", "餐补");
        d2.put("amount", "300");
        d2.put("cost_center", "CC-01");
        submit("r-2", "expense", d2);

        System.out.println();
        System.out.println("【历史记录按各自版本渲染】");
        render("r-1");
        render("r-2");

        System.out.println();
        System.out.println("【不兼容变更：v4 删除 amount 字段】");
        publish("expense", List.of("title", "cost_center"), false);
        Map<String, String> d3 = new LinkedHashMap<>();
        d3.put("title", "打车");
        d3.put("amount", "80");
        submit("r-3", "expense", d3);
        System.out.println("  结论：删字段是破坏性变更，必须 expand-contract（41-09）");
    }
}
```

1. 实现表单版本管理：发布/灰度/回滚，用"v1 提交 -> v2 加字段 -> 历史单据渲染"验证版本隔离。
2. 实现"破坏性变更检测"：改类型/删字段时拒绝发布并提示迁移方案（expand-contract）。
3. 思考题：为什么"历史单据必须按提交时版本渲染"？从"字段错位/数据丢失"与"审计要求"分析。

### 71-08 多租户与扩展

**知识点**
- **低代码平台天然多租户**（55 章）：每个租户有自己的表单/字段/流程/权限——**元数据要带 tenantId**，租户间完全隔离（55-04 双键校验）。
- **租户定制的两种模式**：**独立配置**（租户各改各的，平台提供基础模板）与**继承覆盖**（租户继承平台标准表单，只覆盖差异字段）——**继承模式减少重复配置**（55-06 配置分层思想）。
- **平台升级与租户定制的冲突**：平台发布新版本表单，租户已定制过——**用"差异合并"**（平台改基础，租户覆盖保留）或**"版本并存"**（租户继续用旧版）——**这是多租户低代码最难的工程问题**。
- **扩展点隔离**：租户自定义脚本/组件在**沙箱**中执行（资源限制 + 权限限制 66-10 思想）——**一个租户的脚本不能拖垮平台**。
- 与 55-08 的关系：低代码平台的"噪声邻居"是"某租户配了超大表单/复杂规则"——**要用配额与超时保护**（71-09）。
- 易错点：元数据不带 tenantId（跨租户串数据）；租户定制直接改平台模板（升级即冲突）；无继承机制（每个租户全量配置，维护地狱）；扩展开放无沙箱（安全风险）。

**示例代码**
```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class TenantExtension {
    /** 表单定义：平台基础 + 租户覆盖 */
    record FormDef(String tenantId, String formId, List<String> baseFields,
                   List<String> extraFields, List<String> removedFields) {
        /** 合并结果：基础 - 删除 + 扩展 */
        List<String> effectiveFields() {
            List<String> out = new ArrayList<>();
            for (String f : baseFields) {
                if (!removedFields.contains(f)) {
                    out.add(f);
                }
            }
            out.addAll(extraFields);
            return out;
        }
    }

    static final List<FormDef> forms = new ArrayList<>();

    static void define(String tenantId, String formId, List<String> base,
                       List<String> extra, List<String> removed) {
        forms.add(new FormDef(tenantId, formId, base, extra, removed));
        System.out.printf("  [%s] %s：基础=%d 扩展=%s 删除=%s%n",
                tenantId, formId, base.size(), extra, removed);
    }

    static List<String> resolve(String tenantId, String formId) {
        return forms.stream()
                .filter(f -> f.tenantId().equals(tenantId) && f.formId().equals(formId))
                .findFirst().map(FormDef::effectiveFields).orElse(List.of());
    }

    /** 平台升级：基础字段变化，检查租户定制的影响 */
    static void upgradeImpact(String formId, List<String> newBase) {
        System.out.println("  平台升级 " + formId + " 基础字段 -> " + newBase);
        for (FormDef f : forms) {
            if (!f.formId().equals(formId)) {
                continue;
            }
            List<String> before = f.effectiveFields();
            FormDef upgraded = new FormDef(f.tenantId(), f.formId(), newBase,
                    f.extraFields(), f.removedFields());
            List<String> after = upgraded.effectiveFields();
            List<String> removedByBase = new ArrayList<>(before);
            removedByBase.removeAll(after);
            List<String> added = new ArrayList<>(after);
            added.removeAll(before);
            System.out.printf("    租户 %-6s 变化：新增=%s 消失=%s%n",
                    f.tenantId(), added, removedByBase);
            if (!removedByBase.isEmpty()) {
                System.out.println("      警告：升级会移除租户可见字段 -> 需人工确认");
            }
        }
        System.out.println();
    }

    public static void main(String[] args) {
        List<String> base = List.of("title", "amount", "apply_date", "remark");
        System.out.println("【租户表单定义（继承 + 覆盖）】");
        define("t-100", "expense", base, List.of("cost_center"), List.of("remark"));
        define("t-200", "expense", base, List.of(), List.of());
        define("t-300", "expense", base, List.of("project_code", "budget_year"),
                List.of("apply_date"));

        System.out.println();
        System.out.println("【各租户生效字段】");
        for (String t : new String[]{"t-100", "t-200", "t-300"}) {
            System.out.printf("  %-6s -> %s%n", t, resolve(t, "expense"));
        }

        System.out.println();
        System.out.println("【平台升级影响分析】");
        upgradeImpact("expense", List.of("title", "amount", "apply_date",
                "cost_center", "remark"));
        System.out.println("  策略：差异合并（保留租户扩展/删除意图）+ 破坏性变更人工确认");
        System.out.println();
        System.out.println("【隔离要求】元数据带 tenantId + 查询双键（55-04）+ 脚本沙箱（66-10）");
    }
}
```

### 71-09 性能与安全边界

**知识点**
- **低代码的性能风险**：**元数据解析开销**（每次请求解析 JSON）、**动态 SQL 拼接**（查询条件拼装，易全表扫）、**前端渲染负担**（几十个字段的表单）、**N+1 查询**（引用字段逐个查）——**平台层必须做缓存与批量化**（元数据缓存、查询批量化）。
- **动态 SQL 的安全红线**：**表名/字段名/排序方向必须白名单**（39-02 的标识符纪律）、**值必须参数化**（36-02）——**低代码平台是 SQL 注入的重灾区**（因为它在拼 SQL）。
- **脚本扩展的安全**：沙箱（资源/网络/文件限制 66-10）、超时（执行时长上限）、白名单 API（只能调指定函数）——**不允许任意代码执行**。
- **平台保护**：单表单字段数上限、单租户规则数上限、查询超时、结果集大小限制（44/69 章的资源保护）——**防止"配置导致的事故"**（55-08 噪声邻居的低代码版）。
- 与 36/39 章的关系：动态 SQL 的注入防护、索引与查询优化——**低代码没改变这些底层规则，只是把写 SQL 的人从开发者变成了配置者**。
- 易错点：拼 SQL 用字符串替换（注入）；元数据每次解析（性能差）；引用字段逐个查（N+1）；无限流无超时（复杂配置拖垮平台）。

**示例代码**
```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class LowCodeBoundary {
    /** 白名单：允许的字段与排序方向 */
    static final List<String> ALLOWED_FIELDS = List.of(
            "title", "amount", "apply_date", "status", "created_at");

    /** 安全的动态查询构建：标识符白名单 + 值参数化 */
    static Map<String, Object> buildQuery(Map<String, String> filters,
                                          String orderBy, String direction) {
        Map<String, Object> query = new LinkedHashMap<>();
        List<String> whereParts = new ArrayList<>();
        List<Object> params = new ArrayList<>();
        for (Map.Entry<String, String> e : filters.entrySet()) {
            if (!ALLOWED_FIELDS.contains(e.getKey())) {
                System.out.println("  拒绝：字段 " + e.getKey() + " 不在白名单（防注入/防越权）");
                return Map.of("error", "invalid_field");
            }
            whereParts.add(e.getKey() + " = ?");        // 标识符白名单 + 值占位
            params.add(e.getValue());
        }
        if (!ALLOWED_FIELDS.contains(orderBy)) {
            System.out.println("  拒绝：排序字段 " + orderBy + " 不在白名单");
            return Map.of("error", "invalid_order");
        }
        if (!List.of("asc", "desc").contains(direction.toLowerCase())) {
            System.out.println("  拒绝：排序方向非法");
            return Map.of("error", "invalid_direction");
        }
        query.put("sql", "SELECT * FROM lc_expense WHERE "
                + String.join(" AND ", whereParts)
                + " ORDER BY " + orderBy + " " + direction.toUpperCase());
        query.put("params", params);
        return query;
    }

    /** 元数据缓存：避免每次请求解析 */
    static final Map<String, String> metaCache = new LinkedHashMap<>();
    static int parseCount = 0;

    static String getMeta(String formId) {
        String cached = metaCache.get(formId);
        if (cached != null) {
            return cached + "（缓存）";
        }
        parseCount++;
        String parsed = "form:" + formId + " with 12 fields";
        metaCache.put(formId, parsed);
        return parsed + "（首次解析）";
    }

    /** 引用字段批量加载：避免 N+1 */
    static Map<Long, String> batchLoadUsers(List<Long> ids) {
        Map<Long, String> out = new LinkedHashMap<>();
        ids.forEach(id -> out.put(id, "user-" + id));
        System.out.printf("  批量加载 %d 个用户：1 次查询（而非 %d 次）%n", ids.size(), ids.size());
        return out;
    }

    static void limits() {
        System.out.println("【平台保护阈值】");
        Map<String, String> limits = new LinkedHashMap<>();
        limits.put("单表单字段数", "≤ 200（超出拆分子表单）");
        limits.put("单租户规则数", "≤ 500（超出需评审）");
        limits.put("查询超时", "3s（超时终止并提示）");
        limits.put("结果集上限", "1000 行（超出强制分页）");
        limits.put("脚本执行", "500ms + 沙箱（66-10）");
        limits.forEach((k, v) -> System.out.printf("  %-12s %s%n", k, v));
    }

    public static void main(String[] args) {
        System.out.println("【安全动态查询】");
        Map<String, String> ok = new LinkedHashMap<>();
        ok.put("status", "APPROVED");
        ok.put("amount", "1200");
        System.out.println("  正常：" + buildQuery(ok, "created_at", "desc"));

        System.out.println();
        Map<String, String> bad = new LinkedHashMap<>();
        bad.put("status", "APPROVED");
        bad.put("1=1 OR title", "x");
        System.out.println("  恶意：" + buildQuery(bad, "created_at", "desc"));

        System.out.println();
        System.out.println("【排序字段注入尝试】");
        System.out.println("  " + buildQuery(ok, "created_at; DROP TABLE lc_expense--", "desc"));

        System.out.println();
        System.out.println("【元数据缓存】");
        System.out.println("  " + getMeta("expense"));
        System.out.println("  " + getMeta("expense"));
        System.out.println("  解析次数：" + parseCount);

        System.out.println();
        System.out.println("【N+1 批量化】");
        batchLoadUsers(List.of(1L, 2L, 3L, 4L, 5L));

        System.out.println();
        limits();
    }
}
```

### 71-10 API 与集成

**知识点**
- **低代码平台必须"能被集成"**：开放 API（元数据 CRUD、数据 CRUD、触发流程 64 章）、Webhook（数据变更通知）、**与外部系统的连接器**（数据库/HTTP/MQ）——**否则就是数据孤岛**。
- **API 的设计原则**（64 章复用）：**元数据驱动**（`/api/meta/{formId}` 返回字段定义，前端动态渲染）、**通用数据接口**（`/api/data/{formId}` 统一 CRUD，不每个表单一个接口）、**版本化**（64-05）。
- **连接器的抽象**：**入站**（外部数据写入低代码：HTTP 回调/MQ 消费）、**出站**（低代码调用外部：HTTP/DB/消息）——**连接器配置也是元数据**（含鉴权、重试、超时）。
- **与 69/70 章的关系**：开放业务 API 要签名/配额（69-03/04）、多语言错误码（70-09）——**低代码平台的 API 也要遵守开放平台规范**。
- 易错点：每个表单写一套接口（维护爆炸）；连接器无重试（外部抖动就丢数据）；Webhook 无序（接收方处理乱序）；无鉴权（内部平台裸奔）。

**示例代码**
```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class Integration {
    /** 通用元数据 API：返回字段定义 */
    static Map<String, Object> getFormMeta(String formId) {
        Map<String, Object> meta = new LinkedHashMap<>();
        meta.put("formId", formId);
        meta.put("version", "v2");
        List<Map<String, String>> fields = new ArrayList<>();
        fields.add(Map.of("name", "title", "type", "string", "required", "true"));
        fields.add(Map.of("name", "amount", "type", "decimal", "required", "true"));
        fields.add(Map.of("name", "status", "type", "enum", "required", "false"));
        meta.put("fields", fields);
        return meta;
    }

    /** 通用数据 API：CRUD 走同一套路由（formId 作为参数） */
    static String handleData(String method, String formId, Map<String, String> body) {
        if (!List.of("GET", "POST", "PUT", "DELETE").contains(method)) {
            return "405 不支持的方法";
        }
        if (formId == null || formId.isBlank()) {
            return "400 缺少 formId";
        }
        return switch (method) {
            case "GET" -> "200 查询 " + formId + " 列表（分页）";
            case "POST" -> "201 创建 " + formId + "：" + body;
            case "PUT" -> "200 更新 " + formId;
            default -> "204 删除 " + formId;
        };
    }

    /** Webhook：数据变更通知（带重试与顺序号） */
    record WebhookEvent(String eventId, long seq, String formId, String action,
                        Map<String, String> data) {
    }

    static final List<WebhookEvent> outbox = new ArrayList<>();
    static long seqCounter = 0;

    static void emit(String formId, String action, Map<String, String> data) {
        seqCounter++;
        outbox.add(new WebhookEvent("ev-" + seqCounter, seqCounter, formId, action, data));
        System.out.printf("  发出事件 %s（seq=%d）：%s %s%n", "ev-" + seqCounter,
                seqCounter, action, formId);
    }

    /** 连接器：出站 HTTP 调用的配置化封装 */
    record Connector(String name, String type, String endpoint, int timeoutMs,
                     int maxRetry) {
    }

    static void callConnector(Connector c, boolean simulateFailure) {
        for (int attempt = 1; attempt <= c.maxRetry(); attempt++) {
            if (attempt <= 1 && simulateFailure) {
                System.out.printf("  [%s] 第 %d 次调用失败 -> 退避重试%n", c.name(), attempt);
                continue;
            }
            System.out.printf("  [%s] 第 %d 次调用成功（%s，timeout=%dms）%n",
                    c.name(), attempt, c.endpoint(), c.timeoutMs());
            return;
        }
        System.out.printf("  [%s] 重试耗尽 -> 进死信（%d 次）%n", c.name(), c.maxRetry());
    }

    public static void main(String[] args) {
        System.out.println("【元数据 API】" + getFormMeta("expense"));

        System.out.println();
        System.out.println("【通用数据 API】");
        Map<String, String> body = new LinkedHashMap<>();
        body.put("title", "差旅");
        body.put("amount", "1200");
        System.out.println("  " + handleData("GET", "expense", Map.of()));
        System.out.println("  " + handleData("POST", "expense", body));
        System.out.println("  " + handleData("POST", "", body));
        System.out.println("  " + handleData("PATCH", "expense", body));

        System.out.println();
        System.out.println("【Webhook 事件（带 seq 保序）】");
        emit("expense", "CREATED", body);
        emit("expense", "APPROVED", body);
        outbox.forEach(e -> System.out.printf("  待投递 %s seq=%d%n", e.eventId(), e.seq()));

        System.out.println();
        System.out.println("【连接器：超时 + 重试】");
        callConnector(new Connector("erp-sync", "HTTP",
                "https://erp.internal/api/expense", 3000, 3), true);

        System.out.println();
        System.out.println("  规范：通用接口 + 版本化（64-05）+ 签名配额（64-03/04）+ 事件保序（65-05）");
    }
}
```

### 71-11 综合案例：审批低代码平台

**知识点**
- **把本章收口成一个可运行的审批平台**：**元数据**（实体/字段 71-02）-> **动态表单**（渲染 + 校验 + 联动 71-03）-> **权限**（字段级 + 行级 71-04）-> **规则**（校验/计算/路由 71-05）-> **流程**（审批节点 61-07）-> **版本**（71-07）-> **租户隔离**（71-08）-> **安全边界**（71-09）-> **集成**（71-10）。
- **一次完整单据的生命周期**：**填写**（动态表单 + 规则校验）-> **提交**（版本快照 + 规则路由）-> **审批**（节点权限 + 字段显隐）-> **归档**（按版本渲染）。
- **验收清单**：字段可配、校验双端、权限三层、规则可配、流程可配、版本可回滚、租户隔离、SQL 安全、API 可集成。
- **与全书的关系**：低代码平台把 49 章建模、58 章规则、61 章流程、55 章多租户、68 章权限、64 章 API **组装成一个产品**——**它是"工程能力的产品化"**。
- 易错点：只做表单不做流程（审批跑不起来）；权限只做前端（数据裸奔）；无版本（历史单据错乱）；无安全边界（配置者能注入）。

**示例代码**
```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class ApprovalPlatformCase {
    record FieldDef(String name, String label, String type, boolean required) {
    }

    record FormDef(String formId, String version, List<FieldDef> fields) {
    }

    record Rule(String id, String when, String action, int priority) {
    }

    record Doc(String docId, String formId, String formVersion, String tenantId,
               Map<String, String> data, String status, String currentNode) {
    }

    static final List<FormDef> forms = new ArrayList<>();
    static final List<Rule> rules = new ArrayList<>();
    static final List<Doc> docs = new ArrayList<>();

    static void init() {
        forms.add(new FormDef("expense", "v1", List.of(
                new FieldDef("title", "标题", "string", true),
                new FieldDef("amount", "金额", "decimal", true),
                new FieldDef("category", "类别", "enum", true))));
        rules.add(new Rule("R-1", "amount>5000", "requireDirector", 100));
        rules.add(new Rule("R-2", "amount<=5000", "requireManager", 100));
    }

    /** 1) 表单定义（含校验元数据） */
    static FormDef form(String formId) {
        return forms.stream().filter(f -> f.formId().equals(formId))
                .reduce((a, b) -> b).orElse(null);
    }

    /** 2) 校验：必填 + 规则 */
    static List<String> validate(FormDef form, Map<String, String> data) {
        List<String> errors = new ArrayList<>();
        for (FieldDef f : form.fields()) {
            if (f.required() && (data.get(f.name()) == null
                    || data.get(f.name()).isBlank())) {
                errors.add(f.label() + "必填");
            }
        }
        try {
            double amount = Double.parseDouble(data.getOrDefault("amount", "0"));
            if (amount <= 0) {
                errors.add("金额必须大于 0");
            }
        } catch (NumberFormatException e) {
            errors.add("金额格式错误");
        }
        return errors;
    }

    /** 3) 规则路由：决定首个审批节点 */
    static String route(Map<String, String> data) {
        double amount = Double.parseDouble(data.getOrDefault("amount", "0"));
        for (Rule r : rules) {
            if (r.when().startsWith("amount>") && amount > Double.parseDouble(
                    r.when().substring("amount>".length()))) {
                return r.action();
            }
            if (r.when().startsWith("amount<=") && amount <= Double.parseDouble(
                    r.when().substring("amount<=".length()))) {
                return r.action();
            }
        }
        return "requireManager";
    }

    /** 4) 提交：版本快照 + 路由 */
    static void submit(String docId, String formId, String tenantId,
                       Map<String, String> data) {
        FormDef form = form(formId);
        List<String> errors = validate(form, data);
        if (!errors.isEmpty()) {
            System.out.println("  提交失败：" + errors);
            return;
        }
        String node = route(data);
        docs.add(new Doc(docId, formId, form.version(), tenantId,
                new LinkedHashMap<>(data), "IN_APPROVAL", node));
        System.out.printf("  提交 %s（租户 %s，表单 %s %s）-> 路由到 %s%n",
                docId, tenantId, formId, form.version(), node);
    }

    /** 5) 审批：字段显隐按角色 */
    static void renderForApprover(Doc doc, String role) {
        System.out.printf("  [%s 视角] 单据 %s（%s）：%n", role, doc.docId(), doc.status());
        for (Map.Entry<String, String> e : doc.data().entrySet()) {
            boolean visible = switch (role) {
                case "director" -> true;
                case "manager" -> !e.getKey().equals("category") || true;
                default -> false;
            };
            if (visible) {
                System.out.printf("    %-10s = %s%n", e.getKey(), e.getValue());
            }
        }
    }

    static void approve(String docId, String role) {
        for (int i = 0; i < docs.size(); i++) {
            Doc d = docs.get(i);
            if (d.docId().equals(docId)) {
                String next = switch (d.currentNode()) {
                    case "requireManager" -> "DONE";
                    case "requireDirector" -> "requireManager";
                    default -> "DONE";
                };
                String status = next.equals("DONE") ? "APPROVED" : "IN_APPROVAL";
                docs.set(i, new Doc(d.docId(), d.formId(), d.formVersion(), d.tenantId(),
                        d.data(), status, next));
                System.out.printf("  %s 审批 %s -> 状态=%s 下一节点=%s%n",
                        role, docId, status, next);
                return;
            }
        }
    }

    public static void main(String[] args) {

                + "（" + form("expense").version() + "），字段 "
                + form("expense").fields().size() + " 个；规则 " + rules.size() + " 条");

        System.out.println();

        d2.put("title", "餐补");
        d2.put("amount", "300");
        d2.put("category", "MEAL");
        submit("doc-2", "expense", "t-100", d2);
```

## 本章综合练习

### 综合题：低代码表单平台

**场景**

做一个元数据驱动的表单平台：表单 schema 定义、动态渲染、字段联动与校验规则、元数据版本与迁移、权限到字段级、运行时解释执行。核心是「改配置不改代码」。

**任务**
1. 设计表单 schema：字段类型、必填、默认值、选项、联动规则（A 为空则 B 隐藏），用 JSON 描述而非硬编码。
2. 实现动态渲染与校验：根据 schema 生成控件、执行校验规则、联动时重算可见性，非法 schema 要有兜底。
3. 实现元数据版本：schema 变更后老数据仍可正确展示（字段改名/删除的兼容），给出迁移脚本思路。
4. 实现字段级权限：同一表单不同角色看到不同字段（隐藏/只读/可编辑），验证越权提交被拒绝。

**验收清单**
- [ ] 新增一个字段或一条联动规则只改 schema，服务不重启即生效。
- [ ] 非法 schema 不会导致页面白屏，有明确错误提示。
- [ ] schema 升级后历史数据打开正常，不出现字段错位。
- [ ] 无权限字段在接口层也被过滤，不只是前端隐藏。
