# 第29章 微服务入门

第28章解决了"服务之间怎么异步通信"，本章解决"服务为什么要拆开、拆开之后怎么找到彼此、怎么扛住对方挂掉"。微服务的本质不是技术栈升级，而是把一个大系统拆成多个能独立部署、独立扩容、独立故障的单元，代价是**分布式复杂度**：IP 会变、调用会超时、事务不再原子、一条链路散落在多个服务的日志里。本章按真实落地顺序讲：拆分原则与边界 → 注册中心与服务发现 → 远程调用与超时 → 负载均衡与重试 → 网关鉴权限流 → 配置中心 → 熔断降级隔离 → 分布式事务 → 链路追踪 → 下单链路综合案例。所有示例仍是纯 JDK：注册中心用内存 Map 模拟心跳与剔除，网关用令牌桶真算限流，熔断器真跑 CLOSED/OPEN/HALF_OPEN 三态迁移，不需要装 Nacos、Sentinel 或 SkyWalking。

### 29-01 从单体到微服务：拆与不拆

**知识点**
- **单体应用**：一个进程、一个数据库、一次部署。优点是简单——本地方法调用、事务天然一致、排查一条日志链；缺点是耦合——改一个模块要全量回归、扩一个热点功能要整体扩容、一个死循环拖垮全站、技术栈被锁死。
- **微服务**：按业务能力拆成多个独立部署的服务，各自有进程、数据库、发布节奏。优点是可以独立扩缩容、故障隔离、团队并行；代价是**分布式复杂度**——远程调用会超时、网络会分区、事务不再原子、链路变长排查变难。
- 康威定律：系统架构会向组织沟通结构收敛。团队没拆开就强行拆服务，只会得到"分布式单体"——服务拆了但每次发版还得一起发。
- 判断标准不是"大不大"而是"变化频率是否不同、扩缩容需求是否不同、故障是否应该隔离"。日活几千的内部系统，单体 + 模块化往往是最优解。
- 演进路径：单体（模块化分包）→ 抽出第一个真正独立的服务（通常是用户/认证或消息通知）→ 按瓶颈逐步拆 → 配套注册中心、网关、配置中心、链路追踪。
- 易错：一上来就按技术分层拆（controller 服务、service 服务、dao 服务），这会让一次请求跨 3 个服务，延迟翻倍还没有任何隔离收益。

**示例代码**
```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class MonolithToMicro {
    record Module(String name, int changePerMonth, int qps, boolean critical) { }

    public static void main(String[] args) {
        List<Module> modules = new ArrayList<>();
        modules.add(new Module("用户与认证", 2, 300, true));
        modules.add(new Module("商品", 6, 2000, true));
        modules.add(new Module("订单", 8, 800, true));
        modules.add(new Module("积分", 1, 100, false));
        modules.add(new Module("消息通知", 1, 150, false));
        modules.add(new Module("报表导出", 3, 5, false));

        System.out.println("=== 单体：所有模块一个进程 ===");
        int totalQps = 0;
        for (Module m : modules) {
            totalQps += m.qps();
        }
        System.out.println("  总 QPS " + totalQps + "，扩缩容只能整体进行");
        System.out.println("  报表导出（5 QPS）跑满 CPU 时，商品（2000 QPS）一起变慢");

        System.out.println();
        System.out.println("=== 拆分判断：变化频率 / 流量特征 / 故障隔离 ===");
        System.out.printf("  %-12s %-10s %-10s %-10s %s%n", "模块", "月变更", "QPS", "核心链路", "建议");
        for (Module m : modules) {
            String advice;
            if (m.qps() >= 1500 || m.changePerMonth() >= 6) {
                advice = "优先拆（流量或变更频率独立）";
            } else if (!m.critical() && m.qps() < 200) {
                advice = "可后拆（旁路，故障不该影响主链路）";
            } else {
                advice = "先留在单体，模块化分包即可";
            }
            System.out.printf("  %-12s %-10d %-10d %-10s %s%n",
                    m.name(), m.changePerMonth(), m.qps(), m.critical() ? "是" : "否", advice);
        }

        System.out.println();
        System.out.println("=== 拆分后的调用代价 ===");
        int localCallUs = 1;
        int remoteCallMs = 5;
        System.out.println("  本地方法调用约 " + localCallUs + "us，跨服务 HTTP 调用约 " + remoteCallMs + "ms");
        System.out.println("  一次请求跨 3 个服务 = " + (3 * remoteCallMs) + "ms 纯网络开销（还没算业务）");
        System.out.println("  -> 拆得越细，越要用聚合/批量调用把往返次数压下来");

        System.out.println();
        System.out.println("=== 反面案例：按技术分层拆 ===");
        Map<String, String> bad = new LinkedHashMap<>();
        bad.put("controller-service", "只做参数校验和转发");
        bad.put("service-service", "只做业务编排");
        bad.put("dao-service", "只做数据访问");
        for (Map.Entry<String, String> e : bad.entrySet()) {
            System.out.println("  " + e.getKey() + "：" + e.getValue());
        }
        System.out.println("  一次请求跨 3 跳，任何一层扩容都要连带扩容，事务无法保证，纯亏");
    }
}
```

### 29-02 服务拆分原则与边界

**知识点**
- **按业务能力拆（DDD 限界上下文）**：一个服务对应一个业务领域，拥有自己的数据和规则。订单服务管订单，商品服务管商品，不要出现"订单服务直接改商品表"。
- **数据库私有**：每个服务独占自己的库/表，跨服务只能通过 API。共享数据库是微服务最大的反模式——表结构一改，所有服务一起挂。
- 拆分粒度：一个服务应该能被**一个小团队（5~8 人）**完整负责，包含从接口到存储的全部。太细会导致调用链爆炸，太粗失去隔离收益。
- 聚合边界看"一致性要求"：必须强一致的放在同一个服务同一个库（订单 + 订单明细）；可以最终一致的拆开（订单 + 积分）。
- 服务接口要**面向业务**而不是面向表：`POST /orders` 而不是 `insertOrderRow`。接口一旦发布就是契约，改动要考虑兼容。
- 易错：把"代码分层"当成"服务拆分"；两个服务共用一个数据库连接池；拆分后仍然跨库 join。

**示例代码**
```java
import java.util.ArrayList;
import java.util.HashMap;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class ServiceSplit {
    /** 一个服务：名字 + 拥有的表 + 对外能力 */
    record Service(String name, List<String> tables, List<String> apis) { }

    public static void main(String[] args) {
        List<Service> services = new ArrayList<>();
        services.add(new Service("user-service",
                List.of("t_user", "t_user_address"),
                List.of("GET /users/{id}", "POST /users", "GET /users/{id}/addresses")));
        services.add(new Service("item-service",
                List.of("t_item", "t_item_sku", "t_category"),
                List.of("GET /items/{id}", "GET /items?page=", "POST /items")));
        services.add(new Service("order-service",
                List.of("t_order", "t_order_item", "t_order_status_log"),
                List.of("POST /orders", "GET /orders/{id}", "POST /orders/{id}/cancel")));
        services.add(new Service("points-service",
                List.of("t_points_account", "t_points_log"),
                List.of("POST /points/earn", "GET /points/{userId}")));

        System.out.println("=== 服务边界：每个服务独占自己的表 ===");
        Map<String, String> owner = new HashMap<>();
        boolean conflict = false;
        for (Service s : services) {
            System.out.println("  " + s.name());
            for (String t : s.tables()) {
                if (owner.containsKey(t)) {
                    System.out.println("    ! 表 " + t + " 同时属于 " + owner.get(t) + " 和 " + s.name() + "（共享数据库，反模式）");
                    conflict = true;
                }
                owner.put(t, s.name());
                System.out.println("    " + t);
            }
        }
        System.out.println("  表归属冲突=" + conflict);

        System.out.println();
        System.out.println("=== 对外能力（面向业务，不面向表）===");
        for (Service s : services) {
            for (String api : s.apis()) {
                System.out.println("  " + s.name() + "  " + api);
            }
        }

        System.out.println();
        System.out.println("=== 跨服务调用：只能走 API，不能跨库 join ===");
        Map<String, String> flow = new LinkedHashMap<>();
        flow.put("1. order-service 收到下单请求", "本地事务：写 t_order + t_order_item（强一致，同库）");
        flow.put("2. 调 item-service 扣库存", "HTTP POST /items/{id}/deduct，失败则整单失败");
        flow.put("3. 发 order.created 事件", "points-service 异步加积分（最终一致，可补偿）");
        for (Map.Entry<String, String> e : flow.entrySet()) {
            System.out.println("  " + e.getKey() + " => " + e.getValue());
        }

        System.out.println();
        System.out.println("=== 一致性边界判断 ===");
        System.out.println("  必须强一致（同服务同库）：订单主表 + 订单明细 + 状态流水");
        System.out.println("  可以最终一致（跨服务异步）：订单 -> 积分、订单 -> 物流单、订单 -> 搜索索引");
        System.out.println("  判据：业务能否容忍「几秒内不一致」，能容忍就不要用分布式事务硬扛");
    }
}
```

### 29-03 注册中心与服务发现

**知识点**
- 微服务实例的 IP 和端口是**动态的**（容器重建、弹性扩容都会变），硬编码地址必然失效。注册中心解决"服务 B 现在有哪些可用实例"。
- 流程：服务启动 → 向注册中心**注册**（服务名 + IP + 端口 + 元数据）→ 定期**心跳**续约 → 消费者**拉取/订阅**实例列表 → 本地缓存 + 变更推送。
- 健康检查两种模式：**客户端心跳**（服务自己上报，简单但可能"假活"）与**服务端探测**（注册中心主动探活，更准但有延迟）。
- 主流实现：Nacos（注册 + 配置二合一，国内主流）、Eureka（AP，自我保护模式）、Consul（CP，强一致）、ZooKeeper（CP，临时节点）。
- CAP 取舍：注册中心通常选 **AP**——网络分区时宁可返回稍旧的实例列表，也不能让整个调用链不可用。短暂的不一致由客户端重试和熔断兜底。
- 易错：消费者每次调用都查一次注册中心（应本地缓存 + 订阅推送）；实例下线后本地缓存不刷新（要靠推送或定时全量拉取）；把注册中心当配置中心用。

**示例代码**
```java
import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

public class RegistryDiscovery {
    /** 一个服务实例 */
    static class Instance {
        final String host;
        final int port;
        long lastHeartbeat;
        boolean healthy = true;

        Instance(String host, int port, long now) {
            this.host = host;
            this.port = port;
            this.lastHeartbeat = now;
        }

        String addr() {
            return host + ":" + port;
        }
    }

    /** 极简注册中心 */
    static class Registry {
        final Map<String, List<Instance>> services = new HashMap<>();
        static final long TTL = 30_000;

        void register(String service, Instance ins, long now) {
            services.computeIfAbsent(service, k -> new ArrayList<>()).add(ins);
            System.out.println("  注册 " + service + " -> " + ins.addr());
        }

        void heartbeat(String service, String addr, long now) {
            for (Instance i : services.getOrDefault(service, List.of())) {
                if (i.addr().equals(addr)) {
                    i.lastHeartbeat = now;
                }
            }
        }

        /** 剔除超过 TTL 未续约的实例 */
        int evict(long now) {
            int removed = 0;
            for (Map.Entry<String, List<Instance>> e : services.entrySet()) {
                List<Instance> list = e.getValue();
                for (int i = list.size() - 1; i >= 0; i--) {
                    if (now - list.get(i).lastHeartbeat > TTL) {
                        System.out.println("  剔除失联实例 " + e.getKey() + " -> " + list.get(i).addr());
                        list.remove(i);
                        removed++;
                    }
                }
            }
            return removed;
        }

        List<Instance> discover(String service) {
            List<Instance> list = new ArrayList<>();
            for (Instance i : services.getOrDefault(service, List.of())) {
                if (i.healthy) {
                    list.add(i);
                }
            }
            return list;
        }
    }

    public static void main(String[] args) {
        Registry registry = new Registry();
        long now = 0;
        System.out.println("=== 服务启动时注册 ===");
        registry.register("item-service", new Instance("10.0.0.11", 8081, now), now);
        registry.register("item-service", new Instance("10.0.0.12", 8081, now), now);
        registry.register("item-service", new Instance("10.0.0.13", 8081, now), now);

        System.out.println();
        System.out.println("=== 消费者发现实例（本地缓存，不是每次调用都查）===");
        List<Instance> cached = registry.discover("item-service");
        System.out.println("  本地缓存实例：" + cached.stream().map(Instance::addr).toList());

        System.out.println();
        System.out.println("=== 心跳续约：10.0.0.11 和 12 正常，13 挂掉 ===");
        now += 20_000;
        registry.heartbeat("item-service", "10.0.0.11:8081", now);
        registry.heartbeat("item-service", "10.0.0.12:8081", now);
        registry.evict(now);
        System.out.println("  当前可用：" + registry.discover("item-service").stream().map(Instance::addr).toList());

        System.out.println();
        System.out.println("=== TTL 到期后剔除失联实例 ===");
        now += 20_000;
        registry.heartbeat("item-service", "10.0.0.11:8081", now);
        registry.heartbeat("item-service", "10.0.0.12:8081", now);
        int removed = registry.evict(now);
        System.out.println("  本轮剔除 " + removed + " 个，可用实例："
                + registry.discover("item-service").stream().map(Instance::addr).toList());

        System.out.println();
        System.out.println("=== 扩容：新实例加入，推送变更 ===");
        registry.register("item-service", new Instance("10.0.0.14", 8081, now), now);
        System.out.println("  消费者收到推送，缓存刷新为："
                + registry.discover("item-service").stream().map(Instance::addr).toList());
        System.out.println("  CAP 取舍：注册中心选 AP，分区时宁可给旧列表也不能整体不可用");
    }
}
```

### 29-04 远程调用：RPC 与 HTTP

**知识点**
- **RPC（Dubbo/gRPC）**：基于接口的代理调用，像调本地方法；序列化用 Protobuf/Hessian，二进制、体积小、性能高；强契约（接口 + DTO）。
- **HTTP（REST/OpenFeign）**：文本协议（JSON），跨语言、可读、易调试、网关友好；性能略低，但生态和可观测性更好。
- 选择：内部高频调用、追求性能用 RPC；对外 API、跨团队、跨语言用 HTTP。很多公司两者并存。
- 一次远程调用的组成：**建连/复用**（连接池）、**序列化**、**网络传输**、**反序列化**。耗时里最容易被忽略的是建连——没有连接池时每次 TCP 三次握手 + TLS 握手能占掉大半。
- 超时必须显式设置，且要小于上游的超时（超时预算逐层递减），否则上游先断开、下游还在白干。
- 重试只能用于**幂等**接口，且要限制次数 + 退避，否则雪崩时重试会放大流量 3 倍。
- 易错：不设超时（默认无限等，线程池耗尽）；把非幂等的 `POST /orders` 加入自动重试，用户被扣两次钱；传输大对象（整个聚合根）而不是只传需要的字段。

**示例代码**
```java
import java.util.ArrayList;
import java.util.List;

public class RemoteCall {
    /** 模拟一次调用的耗时分解 */
    static class CallProfile {
        long connectUs;
        long serializeUs;
        long networkUs;
        long deserializeUs;

        long totalUs() {
            return connectUs + serializeUs + networkUs + deserializeUs;
        }

        @Override
        public String toString() {
            return String.format("建连=%dus 序列化=%dus 网络=%dus 反序列化=%dus 合计=%dus",
                    connectUs, serializeUs, networkUs, deserializeUs, totalUs());
        }
    }

    static CallProfile httpCall(boolean reuseConnection, int payloadKb) {
        CallProfile p = new CallProfile();
        p.connectUs = reuseConnection ? 5 : 2000;          // 无连接池要三次握手
        p.serializeUs = payloadKb * 12L;                    // JSON 文本，体积大
        p.networkUs = payloadKb * 8L;
        p.deserializeUs = payloadKb * 10L;
        return p;
    }

    static CallProfile rpcCall(boolean reuseConnection, int payloadKb) {
        CallProfile p = new CallProfile();
        p.connectUs = reuseConnection ? 3 : 1500;
        p.serializeUs = payloadKb * 2L;                     // 二进制，体积小
        p.networkUs = payloadKb * 4L;
        p.deserializeUs = payloadKb * 2L;
        return p;
    }

    public static void main(String[] args) {
        System.out.println("=== 同一次调用：HTTP vs RPC ===");
        System.out.println("  HTTP " + httpCall(true, 20));
        System.out.println("  RPC  " + rpcCall(true, 20));

        System.out.println();
        System.out.println("=== 连接池的影响（最容易忽略的一项）===");
        System.out.println("  无连接池 HTTP " + httpCall(false, 20));
        System.out.println("  有连接池 HTTP " + httpCall(true, 20));
        long saved = httpCall(false, 20).totalUs() - httpCall(true, 20).totalUs();
        System.out.println("  单次省 " + saved + "us；1000 QPS 下每秒省 " + saved * 1000 / 1000 + "ms 的线程占用");

        System.out.println();
        System.out.println("=== 大对象传输的代价 ===");
        int[] sizes = {5, 20, 100, 500};
        for (int kb : sizes) {
            CallProfile h = httpCall(true, kb);
            System.out.println("  payload " + kb + "KB -> HTTP " + h.totalUs() / 1000 + "ms，RPC "
                    + rpcCall(true, kb).totalUs() / 1000 + "ms");
        }
        System.out.println("  建议：只传需要的字段，列表接口分页，别把整个聚合根丢过去");

        System.out.println();
        System.out.println("=== 超时预算：逐层递减 ===");
        List<int[]> budget = new ArrayList<>();
        budget.add(new int[]{3000, 800, 300});
        System.out.println("  网关 3000ms > 订单服务 800ms > 商品服务 300ms");
        System.out.println("  上游必须比下游长，否则上游已断开、下游还在白干");
        for (int[] b : budget) {
            System.out.println("  层超时 " + b[0] + " / " + b[1] + " / " + b[2] + "ms");
            break;
        }

        System.out.println();
        System.out.println("=== 重试只能用于幂等接口 ===");
        System.out.println("  GET  /items/1       可重试");
        System.out.println("  PUT  /items/1       可重试（幂等）");
        System.out.println("  POST /orders        不可自动重试（会重复下单），需幂等键");
        System.out.println("  重试放大：3 次重试 + 上游超时 = 下游流量变成 4 倍");
    }
}
```

### 29-05 负载均衡与重试策略

**知识点**
- 客户端负载均衡（Spring Cloud LoadBalancer、Dubbo）在调用方本地选实例，少一跳、更快；服务端负载均衡（Nginx、LVS）集中转发，运维简单。
- 常见算法：**轮询**（均匀，适合实例同质）、**加权轮询**（按机器配置分配）、**最少连接/最小活跃**（适合长耗时请求）、**一致性哈希**（同一 key 落同一实例，利于缓存命中）、**随机**（简单，大样本下接近均匀）。
- 健康实例才参与分配：注册中心标记下线的实例要立刻从本地列表中摘除，否则会持续打到挂掉的节点。
- 重试要区分错误类型：**连接失败**可以重试另一台实例；**业务异常（4xx）**不该重试；**超时**要看接口是否幂等。
- 重试策略：固定间隔、指数退避、带抖动的退避（避免所有客户端同时重试造成"重试风暴"）。
- 熔断与重试配合：重试次数用尽后触发熔断，直接把后续请求快速失败，给下游恢复时间。
- 易错：重试仍打同一台实例（没有换节点）；重试次数配 5 次且每层都重试，实际放大 5^3 倍。

**示例代码**
```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;
import java.util.Random;

public class LoadBalanceRetry {
    static final List<String> HEALTHY = new ArrayList<>(List.of("10.0.0.11", "10.0.0.12", "10.0.0.13"));
    static final List<String> ALL = new ArrayList<>(List.of("10.0.0.11", "10.0.0.12", "10.0.0.13", "10.0.0.14"));

    static String roundRobin(int[] cursor) {
        String pick = HEALTHY.get(cursor[0] % HEALTHY.size());
        cursor[0]++;
        return pick;
    }

    static String leastActive(int[] active) {
        int best = 0;
        for (int i = 1; i < active.length; i++) {
            if (active[i] < active[best]) {
                best = i;
            }
        }
        return HEALTHY.get(best);
    }

    static String consistentHash(String key) {
        int idx = Math.floorMod(key.hashCode(), HEALTHY.size());
        return HEALTHY.get(idx);
    }

    public static void main(String[] args) {
        System.out.println("=== 轮询 ===");
        int[] cursor = {0};
        Map<String, Integer> stat = new LinkedHashMap<>();
        for (int i = 0; i < 9; i++) {
            String pick = roundRobin(cursor);
            stat.merge(pick, 1, Integer::sum);
        }
        System.out.println("  9 次分配：" + stat);

        System.out.println();
        System.out.println("=== 最少活跃连接 ===");
        int[] active = {7, 2, 5};
        for (int i = 0; i < 3; i++) {
            String pick = leastActive(active);
            int idx = HEALTHY.indexOf(pick);
            active[idx]++;
            System.out.println("  选 " + pick + "（当前活跃 " + (active[idx] - 1) + " -> " + active[idx] + "）");
        }

        System.out.println();
        System.out.println("=== 一致性哈希：同一用户固定落同一实例（利于本地缓存）===");
        for (String user : List.of("u1001", "u1002", "u1001", "u1003", "u1002")) {
            System.out.println("  " + user + " -> " + consistentHash(user));
        }

        System.out.println();
        System.out.println("=== 摘除不健康实例 ===");
        System.out.println("  注册中心标记 10.0.0.13 下线后，本地列表变为 " + HEALTHY);
        System.out.println("  仍在 ALL 里的 10.0.0.14 未注册，不参与分配：" + ALL);

        System.out.println();
        System.out.println("=== 重试：换节点 + 退避 + 抖动 ===");
        Random random = new Random(42);
        String[] nodes = {"10.0.0.11", "10.0.0.12", "10.0.0.13"};
        for (int attempt = 1; attempt <= 3; attempt++) {
            String node = nodes[attempt - 1];
            boolean ok = attempt == 3;
            long backoff = (long) (100 * Math.pow(2, attempt - 1) * (0.5 + random.nextDouble()));
            System.out.println("  第 " + attempt + " 次 -> " + node + "，结果=" + (ok ? "成功" : "超时")
                    + (ok ? "" : "，退避 " + backoff + "ms（含抖动）"));
            if (ok) {
                break;
            }
        }

        System.out.println();
        System.out.println("=== 重试放大计算 ===");
        int layers = 3;
        int retries = 3;
        long amplified = (long) Math.pow(retries + 1, layers);
        System.out.println("  " + layers + " 层调用每层重试 " + retries + " 次 => 最坏放大 " + amplified + " 倍");
        System.out.println("  对策：只在最外层重试，内层超时后快速失败");
    }
}
```

### 29-06 网关：路由、鉴权、限流

**知识点**
- 网关是所有外部流量的**唯一入口**，承担：路由转发、统一鉴权、限流熔断、协议转换、日志埋点、跨域处理。它的存在让内部服务不必各自实现这些横切能力。
- 路由规则：按路径前缀（`/api/order/**` → order-service）、按域名、按 Header。路由要支持**灰度**（按用户 ID 或 Header 分流到新版本）。
- 鉴权放在网关：统一校验 token，把解析出的用户 ID 放进请求头传给下游（下游信任内网头，不再重复解析）。注意内部头必须由网关**覆盖**而非透传，否则外部可以伪造。
- 限流三个维度：**QPS/并发数**（令牌桶、漏桶、滑动窗口）、**用户级**（防单用户刷接口）、**接口级**（保护慢接口）。限流算法选令牌桶（允许突发）或漏桶（严格匀速）。
- 网关自身要高可用：多实例 + 前面挂 SLB，网关不能成为单点。
- 易错：网关做了鉴权但下游还信任外部传入的 `X-User-Id`（越权）；限流只做全局限流，一个用户刷满把所有人挡住；网关里写业务逻辑，越写越厚变成"网关巨石"。

**示例代码**
```java
import java.util.ArrayList;
import java.util.HashMap;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class ApiGateway {
    /** 路由规则 */
    record Route(String prefix, String target, boolean needAuth) { }

    static final List<Route> ROUTES = new ArrayList<>(List.of(
            new Route("/api/users", "user-service", false),
            new Route("/api/items", "item-service", false),
            new Route("/api/orders", "order-service", true),
            new Route("/api/points", "points-service", true)
    ));

    /** 令牌桶：容量 capacity，每秒补充 rate 个 */
    static class TokenBucket {
        final int capacity;
        final int rate;
        double tokens;
        long lastRefillMs;

        TokenBucket(int capacity, int rate, long now) {
            this.capacity = capacity;
            this.rate = rate;
            this.tokens = capacity;
            this.lastRefillMs = now;
        }

        boolean tryAcquire(long now) {
            double add = (now - lastRefillMs) / 1000.0 * rate;
            tokens = Math.min(capacity, tokens + add);
            lastRefillMs = now;
            if (tokens >= 1) {
                tokens -= 1;
                return true;
            }
            return false;
        }
    }

    static String route(String path) {
        for (Route r : ROUTES) {
            if (path.startsWith(r.prefix())) {
                return r.target();
            }
        }
        return null;
    }

    static boolean needAuth(String path) {
        for (Route r : ROUTES) {
            if (path.startsWith(r.prefix())) {
                return r.needAuth();
            }
        }
        return true;
    }

    public static void main(String[] args) {
        System.out.println("=== 路由转发 ===");
        for (String p : List.of("/api/items/1", "/api/orders/9", "/api/points/1001", "/api/unknown")) {
            String target = route(p);
            System.out.println("  " + p + " -> " + (target == null ? "404 无匹配路由" : target));
        }

        System.out.println();
        System.out.println("=== 统一鉴权 + 覆盖内部头（防伪造）===");
        Map<String, String> headers = new HashMap<>();
        headers.put("X-User-Id", "9999");
        System.out.println("  外部请求自带 X-User-Id=" + headers.get("X-User-Id") + "（伪造）");
        String token = "Bearer valid-token-for-u1001";
        if (needAuth("/api/orders") && token.startsWith("Bearer ")) {
            headers.put("X-User-Id", "u1001");
            System.out.println("  网关校验 token 通过，强制覆盖 X-User-Id=" + headers.get("X-User-Id"));
        }
        System.out.println("  下游只信任网关写入的头，绝不透传外部同名头");

        System.out.println();
        System.out.println("=== 接口级限流：令牌桶 容量5 / 每秒2 ===");
        TokenBucket bucket = new TokenBucket(5, 2, 0);
        long now = 0;
        int allowed = 0;
        int rejected = 0;
        for (int i = 1; i <= 12; i++) {
            boolean ok = bucket.tryAcquire(now);
            System.out.println("  t=" + now + "ms 第 " + i + " 个请求 -> " + (ok ? "放行" : "429 限流"));
            if (ok) {
                allowed++;
            } else {
                rejected++;
            }
            now += 300;
        }
        System.out.println("  放行 " + allowed + "，拒绝 " + rejected);
        System.out.println("  令牌桶允许突发（初始 5 个），漏桶则严格匀速");

        System.out.println();
        System.out.println("=== 限流维度 ===");
        Map<String, String> dims = new LinkedHashMap<>();
        dims.put("全局 QPS", "保护整个集群，防止被打穿");
        dims.put("单用户 QPS", "防刷接口，避免一个用户挤占所有人");
        dims.put("单接口 QPS", "保护慢接口（如导出报表）不拖垮线程池");
        dims.put("单 IP 连接数", "防爬虫和异常客户端");
        for (Map.Entry<String, String> e : dims.entrySet()) {
            System.out.println("  " + e.getKey() + "：" + e.getValue());
        }
    }
}
```

### 29-07 配置中心与动态刷新

**知识点**
- 配置散落在每个服务的 `application.yml` 里，改一个开关要重新打包发布 10 个服务——配置中心解决"集中管理 + 动态生效"。
- 配置分层：**公共配置**（注册中心地址、日志格式）→ **应用级配置**（数据库、线程池）→ **环境级配置**（dev/test/prod 不同值）→ **实例级配置**（灰度开关）。优先级从低到高，后者覆盖前者。
- 动态刷新：配置中心推送变更 → 客户端收到通知 → 更新本地缓存 → 触发 `@RefreshScope` 类重建或监听器回调。注意：**不是所有配置都能热更新**（数据库连接池大小、JVM 参数、线程池核心数通常需要重启）。
- 灰度与回滚：配置变更要能按实例/按比例生效，并且能一键回滚到上一版本。配置错误导致的故障比代码 bug 更常见。
- 安全：数据库密码等敏感配置要加密存储，客户端本地不能明文落盘；配置中心的访问要鉴权。
- 易错：把配置中心当"实时数据库"频繁读写（配置是低频变更，不是状态存储）；改了配置但客户端没有监听，以为生效了；配置中心挂了服务无法启动（应支持本地快照兜底）。

**示例代码**
```java
import java.util.ArrayList;
import java.util.HashMap;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class ConfigCenter {
    /** 配置项：key -> (value, 版本号) */
    static class ConfigItem {
        String value;
        int version;

        ConfigItem(String value, int version) {
            this.value = value;
            this.version = version;
        }
    }

    /** 极简配置中心 */
    static class Center {
        final Map<String, ConfigItem> store = new LinkedHashMap<>();
        final List<String> listeners = new ArrayList<>();

        void put(String key, String value) {
            ConfigItem old = store.get(key);
            int v = old == null ? 1 : old.version + 1;
            store.put(key, new ConfigItem(value, v));
            System.out.println("  [中心] 更新 " + key + " = " + value + "（v" + v + "），推送变更");
            for (String l : listeners) {
                System.out.println("    -> 通知 " + l);
            }
        }
    }

    /** 客户端：本地快照 + 监听 */
    static class Client {
        final String name;
        final Map<String, String> snapshot = new HashMap<>();
        boolean hotReloadable = true;

        Client(String name, Center center) {
            this.name = name;
            center.listeners.add(name);
        }

        void load(Center center, String key) {
            ConfigItem item = center.store.get(key);
            if (item != null) {
                snapshot.put(key, item.value);
                System.out.println("  [" + name + "] 加载 " + key + " = " + item.value);
            }
        }

        void onChange(String key, String value) {
            if (!hotReloadable) {
                System.out.println("  [" + name + "] 收到 " + key + " 变更，但该项需要重启生效，暂存待下次启动");
                return;
            }
            snapshot.put(key, value);
            System.out.println("  [" + name + "] 热更新 " + key + " -> " + value);
        }
    }

    public static void main(String[] args) {
        Center center = new Center();
        center.store.put("app.timeout.ms", new ConfigItem("3000", 1));
        center.store.put("app.retry.max", new ConfigItem("3", 1));
        center.store.put("db.pool.size", new ConfigItem("20", 1));

        Client order = new Client("order-service", center);
        Client item = new Client("item-service", center);
        for (String k : List.of("app.timeout.ms", "app.retry.max", "db.pool.size")) {
            order.load(center, k);
            item.load(center, k);
        }

        System.out.println();
        System.out.println("=== 改超时：可热更新 ===");
        center.put("app.timeout.ms", "1500");
        order.onChange("app.timeout.ms", "1500");
        item.onChange("app.timeout.ms", "1500");

        System.out.println();
        System.out.println("=== 改连接池大小：需要重启 ===");
        order.hotReloadable = false;
        center.put("db.pool.size", "50");
        order.onChange("db.pool.size", "50");

        System.out.println();
        System.out.println("=== 配置优先级（后者覆盖前者）===");
        Map<String, String> merged = new LinkedHashMap<>();
        merged.put("公共配置 timeout=3000", "注册中心、日志格式");
        merged.put("应用配置 timeout=2000", "数据库、线程池");
        merged.put("环境配置 timeout=1000", "prod 覆盖 test");
        merged.put("实例配置 timeout=800", "灰度实例单独调小");
        for (Map.Entry<String, String> e : merged.entrySet()) {
            System.out.println("  " + e.getKey() + "  ← " + e.getValue());
        }
        System.out.println("  最终生效 timeout=800ms");

        System.out.println();
        System.out.println("=== 配置中心不可用：本地快照兜底 ===");
        System.out.println("  客户端启动时先从本地 snapshot 文件加载，再尝试连中心刷新");
        System.out.println("  -> 中心宕机不影响已有实例启动，只是拿不到最新配置");
        System.out.println("  版本回滚：中心保留最近 N 个版本，出问题一键回退 v" + (center.store.get("app.timeout.ms").version - 1));
    }
}
```

### 29-08 熔断、降级与服务隔离

**知识点**
- **雪崩**：下游 B 变慢 → 调用 B 的线程全部阻塞 → A 的线程池耗尽 → A 也不可用 → 上游 C 跟着挂。一个慢接口能拖垮整条链路。
- **熔断器三态**：`CLOSED`（正常放行，统计失败率）→ 失败率超阈值 → `OPEN`（直接快速失败，不发起调用）→ 等待窗口后 → `HALF_OPEN`（放少量试探请求）→ 成功则回 `CLOSED`，失败则回 `OPEN`。
- **降级**：熔断或异常时返回兜底结果——缓存旧值、默认值、空列表、友好提示。降级要**有损但可用**，不能降级成报错。
- **隔离**：线程池隔离（每个下游独立线程池，慢的不拖累快的）、信号量隔离（轻量，限制并发数）、集群隔离（不同业务用不同实例）。
- 熔断参数：失败率阈值（如 50%）、最小请求数（样本太少不熔断）、熔断时长（给下游恢复时间）、半开试探数量。
- 易错：熔断后没有兜底，直接把异常抛给用户；熔断时长设太短（下游还没恢复就放流量）；所有下游共用一个线程池，等于没隔离。

**示例代码**
```java
public class CircuitBreaker {
    enum State { CLOSED, OPEN, HALF_OPEN }

    static class Breaker {
        State state = State.CLOSED;
        int total;
        int failed;
        long openUntilMs;
        int halfOpenPermits;

        final int minRequests = 10;
        final double failRateThreshold = 0.5;
        final long openDurationMs = 5000;
        final int halfOpenMax = 3;

        /** 返回 true 表示放行调用 */
        boolean allow(long now) {
            if (state == State.OPEN) {
                if (now >= openUntilMs) {
                    state = State.HALF_OPEN;
                    halfOpenPermits = halfOpenMax;
                    System.out.println("    [熔断器] 冷却结束 -> HALF_OPEN，允许 " + halfOpenMax + " 个试探");
                } else {
                    return false;
                }
            }
            if (state == State.HALF_OPEN) {
                if (halfOpenPermits <= 0) {
                    return false;
                }
                halfOpenPermits--;
            }
            return true;
        }

        void record(boolean ok, long now) {
            total++;
            if (!ok) {
                failed++;
            }
            if (state == State.HALF_OPEN) {
                if (ok) {
                    System.out.println("    [熔断器] 试探成功 -> CLOSED，恢复正常");
                    reset();
                } else {
                    System.out.println("    [熔断器] 试探失败 -> 重新 OPEN");
                    trip(now);
                }
                return;
            }
            if (total >= minRequests) {
                double rate = (double) failed / total;
                if (rate >= failRateThreshold) {
                    System.out.println("    [熔断器] 失败率 " + Math.round(rate * 100) + "% 超阈值 -> OPEN");
                    trip(now);
                }
            }
        }

        void trip(long now) {
            state = State.OPEN;
            openUntilMs = now + openDurationMs;
            reset();
            state = State.OPEN;
            openUntilMs = now + openDurationMs;
        }

        void reset() {
            total = 0;
            failed = 0;
        }
    }

    /** 下游服务：前若干次失败，之后恢复 */
    static boolean callDownstream(int seq) {
        return seq > 12;
    }

    /** 降级兜底 */
    static String fallback() {
        return "降级：返回缓存中的旧商品列表（可能不是最新）";
    }

    public static void main(String[] args) {
        Breaker breaker = new Breaker();
        long now = 0;
        int seq = 0;

        System.out.println("=== 下游持续失败：熔断器打开 ===");
        for (int i = 1; i <= 20; i++) {
            seq++;
            now += 100;
            if (!breaker.allow(now)) {
                System.out.println("  第 " + i + " 次请求：熔断 OPEN，直接走降级 -> " + fallback());
                continue;
            }
            boolean ok = callDownstream(seq);
            System.out.println("  第 " + i + " 次请求：调用下游 -> " + (ok ? "成功" : "超时"));
            breaker.record(ok, now);
            if (!ok) {
                System.out.println("    -> " + fallback());
            }
        }

        System.out.println();
        System.out.println("=== 冷却 5s 后进入半开，试探恢复 ===");
        now += 5000;
        for (int i = 21; i <= 26; i++) {
            seq++;
            now += 100;
            if (!breaker.allow(now)) {
                System.out.println("  第 " + i + " 次请求：仍不放行 -> 降级");
                continue;
            }
            boolean ok = callDownstream(seq);
            System.out.println("  第 " + i + " 次请求：试探调用 -> " + (ok ? "成功" : "失败"));
            breaker.record(ok, now);
        }

        System.out.println();
        System.out.println("=== 隔离方式对比 ===");
        System.out.println("  线程池隔离：每个下游独立池（如 20 线程），慢的下游只耗尽自己的池");
        System.out.println("  信号量隔离：只限并发数，不换线程，开销小但无法超时中断");
        System.out.println("  集群隔离：核心业务和非核心业务部署在不同实例组，互不影响");
        System.out.println("  反例：所有下游共用一个 200 线程池，一个慢接口就能拖垮全部");
    }
}
```

### 29-09 分布式事务：从 2PC 到最终一致

**知识点**
- 本地事务靠数据库 ACID，跨服务后没有统一的锁和日志，只能用**补偿**或**协调者**来近似。
- **2PC/XA**：协调者先 `prepare` 所有参与者，全部就绪再 `commit`。强一致，但同步阻塞、协调者单点、性能差，不适合高并发互联网场景。
- **TCC**（Try-Confirm-Cancel）：业务层实现预留/确认/取消三个接口。性能好、可控性强，但侵入大，要处理空回滚、悬挂、幂等三个经典问题。
- **Saga**：把长事务拆成一串本地事务，失败时按反序执行补偿。适合长流程（旅游预订：机票 + 酒店 + 租车），但**没有隔离性**，中间状态对外可见。
- **本地消息表 / 事务消息**：只保证"本地操作 + 消息发送"原子，下游异步消费，是互联网最常用的**最终一致**方案（详见第 28-09 课）。
- **最大努力通知**：不断重试通知对方，直到成功或达到上限，适合对账、支付回调这类"必须通知到但可以晚"的场景。
- 选型口诀：强一致且低频 → 2PC；高并发且能补偿 → TCC/Saga；只要最终一致 → 本地消息表；对外通知 → 最大努力通知。
- 易错：以为加了 `@Transactional` 就能跨服务；TCC 的 Cancel 没有做幂等，重试时把已确认的又取消了；Saga 补偿顺序搞反。

**示例代码**
```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class DistributedTx {
    /** 参与者：账户，余额 + 冻结 */
    static class Account {
        final String name;
        int balance;
        int frozen;

        Account(String name, int balance) {
            this.name = name;
            this.balance = balance;
        }

        boolean tryFreeze(int amount) {
            if (balance < amount) {
                return false;
            }
            balance -= amount;
            frozen += amount;
            System.out.println("    [" + name + "] Try：冻结 " + amount + "，余额 " + balance + "，冻结中 " + frozen);
            return true;
        }

        void confirm(int amount) {
            frozen -= amount;
            System.out.println("    [" + name + "] Confirm：扣减冻结 " + amount + "，余额 " + balance + "，冻结中 " + frozen);
        }

        void cancel(int amount) {
            frozen -= amount;
            balance += amount;
            System.out.println("    [" + name + "] Cancel：解冻 " + amount + "，余额 " + balance + "，冻结中 " + frozen);
        }
    }

    public static void main(String[] args) {
        System.out.println("=== TCC：转账 100（A -> B）===");
        Account a = new Account("A", 500);
        Account b = new Account("B", 100);
        int amount = 100;

        List<Runnable> confirms = new ArrayList<>();
        List<Runnable> cancels = new ArrayList<>();

        boolean okA = a.tryFreeze(amount);
        if (okA) {
            confirms.add(() -> a.confirm(amount));
            cancels.add(() -> a.cancel(amount));
        }
        boolean okB = b.tryFreeze(amount);
        if (okB) {
            confirms.add(() -> b.confirm(amount));
            cancels.add(() -> b.cancel(amount));
        }

        System.out.println("  Try 阶段结果：A=" + okA + "，B=" + okB);
        if (okA && okB) {
            System.out.println("  全部 Try 成功 -> 执行 Confirm");
            confirms.forEach(Runnable::run);
        } else {
            System.out.println("  有 Try 失败 -> 反序执行 Cancel");
            for (int i = cancels.size() - 1; i >= 0; i--) {
                cancels.get(i).run();
            }
        }
        System.out.println("  最终：A 余额 " + a.balance + "，B 余额 " + b.balance);

        System.out.println();
        System.out.println("=== Saga：机票 -> 酒店 -> 租车，酒店失败 ===");
        List<String> done = new ArrayList<>();
        boolean hotelOk = false;
        if (true) {
            done.add("机票已订");
            System.out.println("  步骤1 订机票 成功");
        }
        if (hotelOk) {
            done.add("酒店已订");
            System.out.println("  步骤2 订酒店 成功");
        } else {
            System.out.println("  步骤2 订酒店 失败 -> 反序补偿");
            for (int i = done.size() - 1; i >= 0; i--) {
                System.out.println("    补偿：" + done.get(i).replace("已订", "已取消"));
            }
            System.out.println("  步骤3 租车 未执行");
        }

        System.out.println();
        System.out.println("=== 方案对比 ===");
        Map<String, String> table = new LinkedHashMap<>();
        table.put("2PC/XA", "强一致，同步阻塞，协调者单点，适合低频强一致");
        table.put("TCC", "高性能可控，侵入大，要处理空回滚/悬挂/幂等");
        table.put("Saga", "适合长流程，无隔离性，中间状态可见");
        table.put("本地消息表", "最终一致，最常用，需下游幂等");
        table.put("最大努力通知", "反复重试直到成功，适合对账与支付回调");
        for (Map.Entry<String, String> e : table.entrySet()) {
            System.out.println("  " + e.getKey() + "：" + e.getValue());
        }

        System.out.println();
        System.out.println("=== TCC 三个坑 ===");
        System.out.println("  空回滚：Try 没执行就收到 Cancel -> Cancel 要能识别并直接返回成功");
        System.out.println("  悬挂：Cancel 先到，Try 后到 -> Try 要检查是否已 Cancel，拒绝执行");
        System.out.println("  幂等：Confirm/Cancel 重试多次 -> 结果必须一致");
    }
}
```

### 29-10 链路追踪与日志聚合

**知识点**
- 微服务下一个请求跨多个服务，传统单机日志无法串起来。**链路追踪**用 `traceId`（整条链路）+ `spanId`（单个调用）把调用树还原出来。
- 传递方式：HTTP 头（`traceparent`/`X-B3-TraceId`）、MQ 消息属性、线程上下文（`ThreadLocal` + 线程池透传）。**异步和线程池是 traceId 最容易丢的地方**。
- 采样：全量采集成本太高，通常按 1%~10% 采样，但**出错的请求必须 100% 采集**（尾部采样）。
- 日志聚合：ELK/Loki 集中存储，按 `traceId` 一次查出整条链路的所有日志。日志格式必须结构化（JSON），字段固定：时间、级别、traceId、服务名、方法、耗时、业务键。
- 关键指标：每个 span 的耗时、下游错误率、慢调用 Top N。用这些定位"到底慢在哪一跳"。
- 易错：只在入口生成 traceId，下游重新生成导致链路断裂；日志里打业务对象 `toString()` 带出敏感信息；日志级别全开导致磁盘打满。

**示例代码**
```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class TraceLogging {
    /** 一个 span：一次方法/一次远程调用 */
    record Span(String traceId, String spanId, String parentId, String service,
                String method, long startMs, long costMs, boolean error) { }

    static final List<Span> SPANS = new ArrayList<>();
    static long clock = 0;

    static String newId(String prefix, int seq) {
        return prefix + "-" + Integer.toHexString(seq);
    }

    static Span record(String traceId, String spanId, String parentId, String service,
                       String method, long costMs, boolean error) {
        Span s = new Span(traceId, spanId, parentId, service, method, clock, costMs, error);
        SPANS.add(s);
        clock += costMs;
        return s;
    }

    public static void main(String[] args) {
        String traceId = "trace-4a1f";
        System.out.println("=== 一次下单请求的调用树（traceId=" + traceId + "）===");

        Span gateway = record(traceId, newId("s", 1), null, "gateway", "POST /api/orders", 0, false);
        Span order = record(traceId, newId("s", 2), gateway.spanId(), "order-service", "createOrder", 0, false);
        Span item = record(traceId, newId("s", 3), order.spanId(), "item-service", "deductStock", 120, false);
        Span user = record(traceId, newId("s", 4), order.spanId(), "user-service", "getAddress", 35, false);
        Span points = record(traceId, newId("s", 5), order.spanId(), "points-service", "addPoints", 480, true);
        Span db = record(traceId, newId("s", 6), order.spanId(), "order-service", "insertOrder", 60, false);

        long total = 0;
        for (Span s : SPANS) {
            total += s.costMs();
        }
        SPANS.set(0, new Span(gateway.traceId(), gateway.spanId(), null, gateway.service(),
                gateway.method(), 0, total, false));

        for (Span s : SPANS) {
            String indent = s.parentId() == null ? "" : "  ";
            System.out.printf("%s[%s] %-14s %-18s %5dms %s  spanId=%s parent=%s%n",
                    indent, s.traceId(), s.service(), s.method(), s.costMs(),
                    s.error() ? "ERROR" : "OK", s.spanId(), s.parentId());
        }

        System.out.println();
        System.out.println("=== 定位慢在哪一跳 ===");
        Span slowest = SPANS.get(0);
        for (Span s : SPANS) {
            if (s.costMs() > slowest.costMs()) {
                slowest = s;
            }
        }
        System.out.println("  最慢：" + slowest.service() + "." + slowest.method() + " " + slowest.costMs() + "ms");
        System.out.println("  总耗时 " + total + "ms，慢调用占 " + (slowest.costMs() * 100 / total) + "%");

        System.out.println();
        System.out.println("=== 结构化日志（按 traceId 聚合）===");
        Map<String, String> logLine = new LinkedHashMap<>();
        logLine.put("ts", "2026-11-17T10:00:01.234");
        logLine.put("level", "ERROR");
        logLine.put("traceId", traceId);
        logLine.put("service", "points-service");
        logLine.put("method", "addPoints");
        logLine.put("costMs", "480");
        logLine.put("bizKey", "ORD-20261117-001");
        logLine.put("msg", "下游超时，已进重试队列");
        System.out.println("  " + logLine);
        System.out.println("  一条命令捞出整条链路：grep '" + traceId + "' app-*.log");

        System.out.println();
        System.out.println("=== traceId 最容易丢的三个地方 ===");
        System.out.println("  1. 线程池：提交任务时没把 MDC 上下文带过去 -> 用包装 Runnable 透传");
        System.out.println("  2. MQ：发送时没放进消息头 -> 消费端从 header 恢复 traceId");
        System.out.println("  3. 异步回调：CompletableFuture 默认用公共线程池，上下文丢失");
        System.out.println("  采样：正常请求 1%~10%，错误请求 100%（尾部采样）");
    }
}
```

### 29-11 综合案例：微服务化的下单链路

**知识点**
- 把前面所有能力拼起来：网关统一鉴权限流 → 订单服务编排 → 调用商品服务扣库存（超时 + 重试 + 熔断）→ 调用用户服务取地址 → 本地事务写订单 → 发消息异步加积分 → 全链路 traceId。
- 每一步都要有明确的**失败策略**：库存不足 → 直接失败；用户服务超时 → 用默认地址或让用户重填（可降级）；积分失败 → 不影响下单（异步 + 重试）。
- 关键设计：**核心链路只包含必须同步的步骤**，任何"可以晚点做"的都移到异步。
- 熔断与降级在案例中的位置：商品服务熔断时快速失败（不能超卖），积分服务熔断时静默降级（不影响下单）。
- 配置中心提供超时/重试/开关参数，出问题可以动态调小超时或关闭某条旁路。
- 易错：把积分调用放在订单事务里（事务被远程调用拉长，锁持有时间暴增）；库存扣减失败后没有回滚已扣的优惠券。

**示例代码**
```java
import java.util.ArrayList;
import java.util.HashMap;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class MicroserviceOrderCase {
    static final Map<String, Integer> STOCK = new HashMap<>(Map.of("ITEM-1", 10));
    static final Map<String, String> ORDERS = new LinkedHashMap<>();
    static final Map<String, Integer> POINTS = new HashMap<>();
    static final List<String> MQ = new ArrayList<>();
    static final List<String> TRACE = new ArrayList<>();

    /** 简单熔断器：连续失败 3 次打开 5s */
    static class Breaker {
        int fails;
        long openUntil;
        boolean allow(long now) {
            return now >= openUntil;
        }
        void record(boolean ok, long now) {
            if (ok) {
                fails = 0;
            } else if (++fails >= 3) {
                openUntil = now + 5000;
                log("WARN", "积分服务熔断打开 5s");
            }
        }
    }

    static void log(String level, String msg) {
        String line = "[trace-" + Integer.toHexString(TRACE.size() + 1) + "] " + level + " " + msg;
        TRACE.add(line);
        System.out.println("  " + line);
    }

    /** 商品服务：扣库存（核心链路，失败即整单失败） */
    static boolean deductStock(String itemId, int qty) {
        Integer cur = STOCK.get(itemId);
        if (cur == null || cur < qty) {
            log("ERROR", "item-service 扣库存失败：库存不足 " + cur);
            return false;
        }
        STOCK.put(itemId, cur - qty);
        log("INFO", "item-service 扣库存成功，剩余 " + (cur - qty));
        return true;
    }

    /** 用户服务：取地址（可降级） */
    static String getAddress(String userId, boolean timeout) {
        if (timeout) {
            log("WARN", "user-service 超时 300ms -> 降级：使用用户上次地址");
            return "默认地址（降级）";
        }
        log("INFO", "user-service 返回地址");
        return "北京市海淀区";
    }

    /** 积分服务：异步 + 熔断 + 幂等 */
    static void addPointsAsync(Breaker breaker, String orderNo, String userId, long now) {
        if (!breaker.allow(now)) {
            log("WARN", "points-service 熔断中，消息留在队列稍后重试");
            return;
        }
        try {
            if (orderNo.endsWith("BAD")) {
                throw new IllegalStateException("积分服务 500");
            }
            POINTS.merge(userId, 100, Integer::sum);
            breaker.record(true, now);
            log("INFO", "points-service 加积分成功，累计 " + POINTS.get(userId));
        } catch (RuntimeException e) {
            breaker.record(false, now);
            log("ERROR", "points-service 失败：" + e.getMessage() + " -> 进重试队列");
        }
    }

    public static void main(String[] args) {
        long now = 0;
        Breaker pointsBreaker = new Breaker();

        System.out.println("=== 场景一：正常下单 ===");
        createOrder(pointsBreaker, "ORD-001", "u1001", "ITEM-1", 2, false, now);

        System.out.println();
        System.out.println("=== 场景二：用户服务超时，降级继续 ===");
        createOrder(pointsBreaker, "ORD-002", "u1001", "ITEM-1", 1, true, now);

        System.out.println();
        System.out.println("=== 场景三：库存不足，核心链路失败 ===");
        createOrder(pointsBreaker, "ORD-003", "u1002", "ITEM-1", 999, false, now);

        System.out.println();
        System.out.println("=== 场景四：积分服务连续失败 -> 熔断 ===");
        for (int i = 0; i < 3; i++) {
            addPointsAsync(pointsBreaker, "ORD-BAD-" + i, "u1003", now);
        }
        addPointsAsync(pointsBreaker, "ORD-004", "u1003", now);
        System.out.println("  等待 5s 冷却后恢复：");
        now += 5000;
        addPointsAsync(pointsBreaker, "ORD-005", "u1003", now);

        System.out.println();
        System.out.println("=== 最终状态 ===");
        System.out.println("  库存=" + STOCK);
        System.out.println("  订单=" + ORDERS);
        System.out.println("  积分=" + POINTS);
        System.out.println("  待投递消息=" + MQ);
        System.out.println("  链路日志条数=" + TRACE.size());
    }

    static void createOrder(Breaker breaker, String orderNo, String userId, String itemId,
                            int qty, boolean userTimeout, long now) {
        log("INFO", "gateway 鉴权通过，限流放行，userId=" + userId);
        if (!deductStock(itemId, qty)) {
            log("ERROR", "order-service 下单失败，返回 409");
            return;
        }
        String address = getAddress(userId, userTimeout);
        ORDERS.put(orderNo, "CREATED:" + address);
        log("INFO", "order-service 写订单 " + orderNo + " 成功（本地事务）");
        MQ.add("order.created:" + orderNo);
        log("INFO", "投递 order.created -> MQ");
        addPointsAsync(breaker, orderNo, userId, now);
    }
}
```
