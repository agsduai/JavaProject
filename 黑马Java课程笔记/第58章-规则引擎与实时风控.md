# 第58章 规则引擎与实时风控

第51章讲了支付链路，本章把其中"该不该放行"的判断抽出来做成可配置、可热更、可评估的规则体系。风控规则的本质矛盾是：业务规则一天改三次，而代码一周发一次——规则引擎把规则从代码变成数据，代价是类型安全与调试能力下降，因此必须配套测试集、影响面预览、灰度与效果评估。本章按「规则引擎全景 → 规则模型 → 表达式求值器 → 决策表 → 规则链与冲突消解 → 实时特征 → 名单管理 → 热更新与灰度 → 效果评估与误杀治理 → 风控决策全链路 → 支付风控案例」的顺序讲。所有示例仍是纯 JDK：词法分析与递归下降求值器真跑（含短路与括号）、决策表覆盖检查、规则链冲突消解、特征缺失策略、名单布隆预筛、影响面回放全部真实执行。

### 58-01 规则引擎全景：从 if-else 到规则平台

**知识点**
- **业务规则的痛点是"变化频率远高于代码发布频率"**：风控阈值、营销门槛、费率档位——业务方一天改三次，代码一周发一次。**规则引擎的核心价值是把"规则"从"代码"里抽出来，变成可配置、可热更、可审计的数据**（41-08 特性开关的进阶形态）。
- **规则引擎的三个层次**：**硬编码 if-else**（最快但不可配）、**配置化规则**（条件-动作表 + 解释器，绝大多数业务够用）、**专业引擎**（Drools 类 RETE 算法，适合复杂规则网）——**不要默认上专业引擎**（学习与运维成本高，52-03 的技术选型纪律）。
- **规则的四个组成**：**条件**（什么情况下触发：金额 > 5000 且 设备异常）、**动作**（做什么：拦截/二次验证/放行）、**优先级**（多条命中时谁说了算）、**元数据**（谁建/何时生效/适用场景/版本）。
- **规则引擎的必要组成**：表达式求值（58-03）、决策表（58-04）、冲突消解（58-05）、热更新（58-08）、效果评估（58-09）——**"能配"只是起点，"敢用"要靠评估与灰度**。
- **与 49 章 DDD 的关系**：规则引擎是"策略模式（31 章）的数据化"——策略从编译期多态变为运行期解析；**代价是类型安全与调试能力下降**，因此要配套：规则测试集、模拟执行（dry-run）、版本回滚。
- **何时不该用规则引擎**：规则极其稳定（一年改一次）、规则需要复杂计算与外部调用（写代码更清晰）、团队没有规则治理能力（配错比改代码更危险）。
- 易错点：把所有逻辑都搬进规则（规则爆炸、不可读）；规则无版本（改坏无法回滚）；规则无测试集（上线即事故）；规则引擎当脚本引擎用（安全风险 36-10）。

**示例代码**

```java
public class RuleEngineOverview {

    }

        System.out.println("【规则表达的三代形态】");
        String[][] rows = {
                {"硬编码 if-else", "改规则 = 改代码 + 发布", "稳定规则"},
                {"配置化规则表", "改规则 = 改配置 + 热更", "高频变化的业务规则"},
                {"专业规则引擎", "RETE/规则网 + 事实推理", "数百条互相关联的规则"},
        };
        for (String[] r : rows) {
            System.out.printf("  %-16s %-26s %s%n", r[0], r[1], r[2]);
        }
        System.out.println();
    }

    static void anatomy() {
        System.out.println("【一条风控规则的完整定义】");
        List<Rule> rules = List.of(
                new Rule("R-001", "amount > 500000 && deviceAge < 1", "BLOCK", 100),
                new Rule("R-002", "amount > 100000 && hour >= 0 && hour < 6", "CHALLENGE", 80),
                new Rule("R-003", "userLevel == NEW && amount > 50000", "CHALLENGE", 60),
                new Rule("R-004", "always", "ALLOW", 0));
        for (Rule r : rules) {
            System.out.printf("  %-6s 优先级%-4d 条件=[%s] -> %s%n",
                    r.id(), r.priority(), r.condition(), r.action());
        }
        System.out.println("  要素齐全：条件/动作/优先级/元数据（id 即审计锚点）");
    }

    public static void main(String[] args) {
```

### 58-02 规则模型：条件、动作与优先级

**知识点**
- **条件的三种表达形式**：**表达式字符串**（`amount > 5000 && hour < 6`，灵活但要解析）、**结构化条件树**（AND/OR/比较节点，可视化编辑友好）、**决策表行**（条件组合 -> 动作，业务方最易读 58-04）。**生产常用"结构化树 + 表达式"混合**：UI 编辑树，存储为表达式。
- **动作的语义分级**：**放行**（ALLOW）、**观察**（LOG，不拦只记）、**挑战**（CHALLENGE，二次验证/短信）、**拦截**（BLOCK）——**与 51-07 风控决策分级一致**，规则输出的是"决策建议"，最终裁决在决策层（可能有多规则投票）。
- **优先级的意义**：多条规则同时命中时**按优先级取最高危动作**（BLOCK 优先于 CHALLENGE）或**取第一条命中**（first-match）——**语义必须显式定义**，否则规则打架时行为不可预测。
- **规则的生命周期字段**：生效时间窗（活动期规则）、适用渠道（App/Web）、灰度比例（58-08）、版本号（回滚锚点）、创建人与审批人（51-10 审计）。
- **规则与特征解耦**：规则里引用的是**特征名**（`deviceAge`/`hour`/`userLevel`），不是直接查库——**特征由特征层统一计算**（58-06），规则引擎只管"用特征做判断"，这让规则可单测（喂特征快照即可）。
- 易错点：优先级无定义（同命中时结果随机）；规则无时间窗（活动结束规则还在生效）；规则直接查库（性能与可测性双崩）；动作只有"拦截"（缺少观察档，无法灰度验证）。

**示例代码**
```java
import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;
import java.util.Map;

public class RuleModel {
    record Rule(String id, String expr, Decision action, int priority,
                long effectiveFrom, long effectiveTo, boolean enabled) {

        boolean active(long now) {
            return enabled && now >= effectiveFrom && now <= effectiveTo;
        }
    }

    enum Decision {
        ALLOW(0), LOG(1), CHALLENGE(2), BLOCK(3);

        final int severity;

        Decision(int severity) {
            this.severity = severity;
        }
    }

    record Fact(String eventId, Map<String, Object> features) {
        boolean bool(String k) {
            return Boolean.TRUE.equals(features.get(k));
        }

        long num(String k) {
            Object v = features.get(k);
            return v instanceof Number n ? n.longValue() : 0L;
        }
    }

    /** 极简求值：支持 amount 比较与布尔特征（真实实现见 58-03） */
    static boolean eval(String expr, Fact fact) {
        String e = expr.strip();
        if (e.equals("always")) {
            return true;
        }
        if (e.contains(">")) {
            String[] p = e.split(">");
            return fact.num(p[0].strip()) > Long.parseLong(p[1].strip());
        }
        return fact.bool(e);
    }

    /** 取最高危动作（优先级相同时按 severity 兜底） */
    static Decision decide(List<Rule> rules, Fact fact, long now) {
        List<Rule> hits = new ArrayList<>();
        for (Rule r : rules) {
            if (r.active(now) && eval(r.expr(), fact)) {
                hits.add(r);
            }
        }
        return hits.stream()
                .max(Comparator.comparingInt(Rule::priority)
                        .thenComparingInt(r -> r.action().severity))
                .map(Rule::action)
                .orElse(Decision.ALLOW);
    }

    public static void main(String[] args) {
        long now = 1000;
        List<Rule> rules = List.of(
                new Rule("R-1", "amount > 500", Decision.BLOCK, 100, 0, 9999, true),
                new Rule("R-2", "night", Decision.CHALLENGE, 50, 0, 9999, true),
                new Rule("R-3", "amount > 9000", Decision.BLOCK, 100, 0, 500, true));
        System.out.println("  大额+夜间：" + decide(rules, new Fact("e1",
                Map.<String, Object>of("amount", 800L, "night", true)), now) + "（BLOCK 优先级最高）");
        System.out.println("  小额+夜间：" + decide(rules, new Fact("e2",
                Map.<String, Object>of("amount", 100L, "night", true)), now) + "（CHALLENGE）");
        System.out.println("  过期规则不生效：" + decide(rules, new Fact("e3",
                Map.<String, Object>of("amount", 20000L, "night", false)), 600) + "（R-3 已过期）");
    }
}
```

### 58-03 规则表达式与求值器

**知识点**
- **手写表达式求值器是理解规则引擎的最佳路径**：词法分析（数字/标识符/运算符）-> 递归下降解析（或调度场算法）-> 语法树 -> 求值（携带特征上下文）。**掌握后 Drools/QLExpress 只是"加强版"**。
- **运算符优先级与结合性**：`!` > 比较（`> >= < <= == !=`）> `&&` > `||`——**优先级错了规则行为就错了**，必须与文档一致（表达式语言要写语法手册）。
- **短路求值是语义而非优化**：`a != null && a.x > 0` 依赖短路避免 NPE——**求值器必须实现短路**（`&&` 左边 false 时不求右边），否则规则里无法写空值保护。
- **类型处理**：数值比较（整数/小数）、字符串比较、布尔值；**类型不匹配要报明确错误**（而不是静默 false）——规则写错的成本远高于代码写错（业务方直接改）。
- **安全边界**：**绝不用脚本引擎执行用户输入**（36-10 注入的规则版）——自研求值器只支持白名单语法（无方法调用/无反射/无 IO），这是规则引擎与脚本引擎的根本区别。
- 易错点：不支持短路的求值器（空值保护写不了）；运算符优先级错（`a || b && c` 结果不符直觉）；数字用 double 比较（精度问题，金额要整数分）；支持任意方法调用（注入风险）。

**示例代码**
```java
import java.util.ArrayList;
import java.util.List;
import java.util.Map;

public class ExpressionEvaluator {
    /** 词法单元 */
    enum Kind { NUM, IDENT, OP, LPAREN, RPAREN }

    record Token(Kind kind, String text) {
    }

    /** 词法分析：支持数字、标识符、比较与逻辑运算符、括号 */
    static List<Token> lex(String src) {
        List<Token> out = new ArrayList<>();
        int i = 0;
        while (i < src.length()) {
            char c = src.charAt(i);
            if (Character.isWhitespace(c)) {
                i++;
            } else if (Character.isDigit(c)) {
                int j = i;
                while (j < src.length() && Character.isDigit(src.charAt(j))) {
                    j++;
                }
                out.add(new Token(Kind.NUM, src.substring(i, j)));
                i = j;
            } else if (Character.isLetter(c) || c == '_') {
                int j = i;
                while (j < src.length()
                        && (Character.isLetterOrDigit(src.charAt(j)) || src.charAt(j) == '_')) {
                    j++;
                }
                out.add(new Token(Kind.IDENT, src.substring(i, j)));
                i = j;
            } else if (c == '(') {
                out.add(new Token(Kind.LPAREN, "("));
                i++;
            } else if (c == ')') {
                out.add(new Token(Kind.RPAREN, ")"));
                i++;
            } else {
                String two = i + 1 < src.length() ? src.substring(i, i + 2) : "";
                if (two.equals(">=") || two.equals("<=") || two.equals("==") || two.equals("!=")
                        || two.equals("&&") || two.equals("||")) {
                    out.add(new Token(Kind.OP, two));
                    i += 2;
                } else {
                    out.add(new Token(Kind.OP, String.valueOf(c)));
                    i++;
                }
            }
        }
        return out;
    }

    /** 求值（递归下降 + 短路）：ctx 提供特征值 */
    static class Parser {
        final List<Token> tokens;
        int pos = 0;
        final Map<String, Object> ctx;

        Parser(List<Token> tokens, Map<String, Object> ctx) {
            this.tokens = tokens;
            this.ctx = ctx;
        }

        boolean parse() {
            boolean v = or();
            if (pos != tokens.size()) {
                throw new IllegalArgumentException("表达式未消费完：" + tokens.get(pos).text());
            }
            return v;
        }

        boolean or() {
            boolean left = and();
            while (peekOp("||")) {
                pos++;
                boolean right = and();       // 注意：此处已求值右侧，真实短路见下
                left = left || right;
            }
            return left;
        }

        boolean and() {
            boolean left = cmp();
            while (peekOp("&&")) {
                pos++;
                if (!left) {
                    skipExpr();              // 短路：跳过右侧求值
                    return false;
                }
                left = cmp();
            }
            return left;
        }

        /** 跳过表达式直到同层的 || 或结尾（简化实现） */
        void skipExpr() {
            int depth = 0;
            while (pos < tokens.size()) {
                Token t = tokens.get(pos);
                if (t.kind() == Kind.LPAREN) {
                    depth++;
                } else if (t.kind() == Kind.RPAREN) {
                    depth--;
                } else if (depth == 0 && t.kind() == Kind.OP && t.text().equals("||")) {
                    return;
                }
                pos++;
            }
        }

        boolean cmp() {
            if (pos < tokens.size() && tokens.get(pos).kind() == Kind.LPAREN) {
                pos++;                            // 进入括号
                boolean inner = or();
                if (pos >= tokens.size() || tokens.get(pos).kind() != Kind.RPAREN) {
                    throw new IllegalArgumentException("缺少右括号");
                }
                pos++;
                return inner;
            }
            long a = num();
            if (pos < tokens.size() && tokens.get(pos).kind() == Kind.OP) {
                String op = tokens.get(pos).text();
                if (List.of(">", ">=", "<", "<=", "==", "!=").contains(op)) {
                    pos++;
                    long b = num();
                    return switch (op) {
                        case ">" -> a > b;
                        case ">=" -> a >= b;
                        case "<" -> a < b;
                        case "<=" -> a <= b;
                        case "==" -> a == b;
                        default -> a != b;
                    };
                }
            }
            return a != 0;
        }

        long num() {
            Token t = tokens.get(pos++);
            if (t.kind() == Kind.NUM) {
                return Long.parseLong(t.text());
            }
            if (t.kind() == Kind.IDENT) {
                Object v = ctx.get(t.text());
                if (v instanceof Number n) {
                    return n.longValue();
                }
                if (v instanceof Boolean b) {
                    return b ? 1 : 0;
                }
                return 0;
            }
            throw new IllegalArgumentException("意外符号：" + t.text());
        }

        boolean peekOp(String op) {
            return pos < tokens.size() && tokens.get(pos).kind() == Kind.OP
                    && tokens.get(pos).text().equals(op);
        }
    }

    static boolean evaluate(String expr, Map<String, Object> ctx) {
        return new Parser(lex(expr), ctx).parse();
    }

    public static void main(String[] args) {
        var ctx = Map.<String, Object>of("amount", 8000L, "hour", 3L, "newDevice", true);
        System.out.println("  amount > 5000 && hour < 6          -> "
                + evaluate("amount > 5000 && hour < 6", ctx));
        System.out.println("  amount >= 10000 || newDevice != 0  -> "
                + evaluate("amount >= 10000 || newDevice != 0", ctx));
        System.out.println("  (amount < 100) && hour > 10        -> "
                + evaluate("(amount < 100) && hour > 10", ctx));
        System.out.println();
        System.out.println("  安全边界：只支持白名单语法（无方法调用/无反射/无 IO）");
    }
}
```

### 58-04 决策表与规则矩阵

**知识点**
- **决策表（Decision Table）是"业务方最易读"的规则形式**：行=规则，列=条件与动作（Excel 风格）——**业务方能在表格里直接看到"什么情况下做什么"**，评审效率远高于表达式。
- **条件列的写法**：精确值（`=100`）、范围（`100-500`）、通配（`*` 任意/`-` 不关心）、枚举集合（`wechat|alipay`）——**通配符语义要严格定义**（"不关心"与"必须为空"是两回事）。
- **决策表的完整性检查**：**规则覆盖是否完整**（所有条件组合都有命中）、**是否有矛盾行**（同一组合多个动作）、**是否有不可达行**（被前序行遮蔽）——**这三项检查是决策表上线的门禁**（可自动化）。
- **行序即优先级**（first-match）：决策表从上到下匹配，第一个命中生效——**行序是业务语义的一部分**，调整行序 = 改变规则（需要版本与评审）。
- **决策表到执行引擎的编译**：表格解析 -> 规则对象列表 -> 求值（58-03）；**双向**：人工维护表格，系统渲染成可视化编辑器（业务方在 UI 上改，存储仍是结构化数据）。
- 易错点：通配符语义不清（`*` 被理解成"必须为空"）；行序调整无版本记录（隐性变更）；不检查覆盖完整（漏配组合静默放行）；决策表无责任人（改了不知道找谁）。

**示例代码**
```java
import java.util.ArrayList;
import java.util.List;

public class DecisionTable {
    /** 一行决策表：条件用 "范围|通配*|集合a,b"，动作为决策 */
    record Row(String ruleId, String amountRange, String channel, String decision) {
    }

    record Fact(long amountCents, String channel) {
    }

    static boolean condMatch(String cond, String value) {
        String c = cond.strip();
        if (c.equals("*")) {
            return true;                              // 不关心
        }
        if (c.contains("-")) {
            String[] p = c.split("-");
            long v = Long.parseLong(value);
            return v >= Long.parseLong(p[0]) && v <= Long.parseLong(p[1]);
        }
        if (c.contains(",")) {
            return List.of(c.split(",")).contains(value);
        }
        return c.equals(value);
    }

    static boolean condMatchNum(String cond, long value) {
        String c = cond.strip();
        if (c.equals("*")) {
            return true;
        }
        if (c.contains("-")) {
            String[] p = c.split("-");
            return value >= Long.parseLong(p[0]) && value <= Long.parseLong(p[1]);
        }
        return Long.parseLong(c) == value;
    }

    /** first-match：自上而下，第一个命中生效 */
    static String decide(List<Row> table, Fact fact) {
        for (Row r : table) {
            if (condMatchNum(r.amountRange(), fact.amountCents())
                    && condMatch(r.channel(), fact.channel())) {
                return r.ruleId() + " -> " + r.decision();
            }
        }
        return "NO_MATCH（默认放行）";
    }

    /** 覆盖性检查：抽样枚举条件组合，找出无命中的组合 */
    static List<String> coverageGaps(List<Row> table) {
        List<String> gaps = new ArrayList<>();
        long[] amounts = {0, 5000, 50000, 500000};
        String[] channels = {"wechat", "alipay", "bank"};
        for (long a : amounts) {
            for (String ch : channels) {
                boolean hit = table.stream().anyMatch(r -> condMatchNum(r.amountRange(), a)
                        && condMatch(r.channel(), ch));
                if (!hit) {
                    gaps.add("amount=" + a + ",channel=" + ch);
                }
            }
        }
        return gaps;
    }

    public static void main(String[] args) {
        List<Row> table = List.of(
                new Row("T-01", "100000-999999", "*", "CHALLENGE"),
                new Row("T-02", "0-99999", "wechat,alipay", "ALLOW"),
                new Row("T-03", "0-99999", "bank", "LOG"),
                new Row("T-04", "*", "*", "BLOCK"));
        System.out.println("【决策表执行（first-match）】");
        System.out.println("  20 万 wechat -> " + decide(table, new Fact(200_000, "wechat")));
        System.out.println("  5 万 bank    -> " + decide(table, new Fact(50_000, "bank")));
        System.out.println("  巨大金额     -> " + decide(table, new Fact(9_000_000, "alipay")));
        System.out.println();
        System.out.println("【覆盖性检查】缺口=" + coverageGaps(table)
                + "（T-04 兜底后应无缺口）");
    }
}
```

### 58-05 规则链与冲突消解

**知识点**
- **规则不是孤立的，而是"链"**：一笔交易依次经过反欺诈 -> 限额 -> 黑白名单 -> 营销适用性，**前一个规则的输出可以成为后一个的输入**（如"风险分"）。规则链（Rule Chain）是比单条规则更贴近业务的抽象。
- **冲突消解（Conflict Resolution）四种策略**：**最高优先级优先**（priority max）、**最高危动作为准**（most-severe wins）、**全部执行取并集**（叠加动作：拦截 + 打标 + 告警）、**first-match**（58-04）——**业务语义决定策略，且要写进文档**。
- **RETE 算法的直觉**（专业引擎）：把规则条件拆成"模式网络"，**新事实到达时只沿匹配路径传播**，避免全量重算——适合"数百条规则 × 高频事实"的场景；**简单规则集（<50 条）用线性扫描完全够**。
- **规则链的短路语义**：BLOCK 之后是否还执行后续规则？——**"命中拦截即终止"（省算力）vs "继续收集证据"（便于复盘）** 是产品决策；常见折衷：BLOCK 终止，但记录"本可命中"的后续规则（dry-run 痕迹）。
- **规则链的可观测**：每条规则的命中次数、命中率、耗时——**不命中的规则要能解释**（是条件太严还是特征缺失），这是规则治理的日常（58-09）。
- 易错点：链上规则互相矛盾无裁决（重复告警/漏拦）；短路策略未定义（同笔交易结果不稳定）；规则数上百仍线性扫描不优化（性能可接受但要注意特征计算成本）；无命中日志（规则形同黑盒）。

**示例代码**
```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class RuleChain {
    record Rule(String id, String stage, String expr, String action, int priority) {
    }

    record Fact(String eventId, Map<String, Object> features) {
    }

    /** 极简求值：支持 "k>n" 与布尔特征 */
    static boolean eval(String expr, Fact f) {
        if (expr.equals("always")) {
            return true;
        }
        if (expr.contains(">")) {
            String[] p = expr.split(">");
            Object v = f.features().get(p[0].strip());
            return v instanceof Number n && n.longValue() > Long.parseLong(p[1].strip());
        }
        return Boolean.TRUE.equals(f.features().get(expr));
    }

    /** 分阶段执行 + 最高危裁决 + 命中终止（记录后续可命中项） */
    static void run(List<Rule> chain, Fact fact) {
        Map<String, List<String>> hitsByStage = new LinkedHashMap<>();
        String finalAction = "ALLOW";
        List<String> canaryHits = new ArrayList<>();
        boolean blocked = false;

        for (Rule r : chain) {
            if (blocked) {
                if (eval(r.expr(), fact)) {
                    canaryHits.add(r.id());          // 未执行但记录"本可命中"
                }
                continue;
            }
            boolean hit = eval(r.expr(), fact);
            System.out.printf("  [%s] %-6s 条件=[%-18s] %s%n",
                    r.stage(), r.id(), r.expr(), hit ? "命中 -> " + r.action() : "未命中");
            if (hit) {
                hitsByStage.computeIfAbsent(r.stage(), k -> new ArrayList<>()).add(r.id());
                if (severity(r.action()) >= severity(finalAction)) {
                    finalAction = r.action();
                }
                if (r.action().equals("BLOCK")) {
                    blocked = true;
                }
            }
        }
        System.out.println("  最终裁决：" + finalAction);
        System.out.println("  命中分布：" + hitsByStage);
        if (!canaryHits.isEmpty()) {
            System.out.println("  短路后本可命中：" + canaryHits + "（保留复盘证据）");
        }
    }

    static int severity(String action) {
        return switch (action) {
            case "BLOCK" -> 3;
            case "CHALLENGE" -> 2;
            case "LOG" -> 1;
            default -> 0;
        };
    }

    public static void main(String[] args) {
        List<Rule> chain = List.of(
                new Rule("F-1", "反欺诈", "deviceNew", "CHALLENGE", 80),
                new Rule("F-2", "反欺诈", "riskScore>80", "BLOCK", 100),
                new Rule("L-1", "限额", "amount>500000", "BLOCK", 90),
                new Rule("M-1", "名单", "inBlacklist", "BLOCK", 100),
                new Rule("P-1", "营销", "always", "LOG", 10));
        Map<String, Object> features = new LinkedHashMap<>();
        features.put("deviceNew", true);
        features.put("riskScore", 90L);
        features.put("amount", 800_000L);
        features.put("inBlacklist", false);
        run(chain, new Fact("e-1", features));
    }
}
```

### 58-06 实时特征与规则计算

**知识点**
- **规则的效果取决于特征的质量**：`riskScore`/`deviceAge`/`hourHeat` 这些特征由**特征层**计算（43 章流处理 + 46-10 特征平台），**规则引擎只消费特征快照**——两者解耦后规则可单测、特征可独立演进。
- **特征的三类时效**：**实时**（本次会话点击/近 1 分钟失败次数，Flink 窗口 43-03）、**近线**（近 1 小时/1 天统计）、**离线**（用户画像 T+1）——**风控决策通常"实时 + 近线"组合**，离线特征只做辅助。
- **特征缺失的处理**：规则里引用了没算出来的特征——**必须显式降级**（默认值/跳过该规则/拒绝），**静默当 false 是最危险的**（本该拦的放过了）。规则引擎要暴露"特征缺失清单"（46-10 新鲜度监控）。
- **特征计算的一致性**：规则测试用的特征快照必须与线上同源同口径（54-04 训练-推理一致性在风控的对应）——**规则回归测试 = 喂历史特征快照重放**。
- **特征与规则的成本账**：一次决策要算 30 个特征（含 3 次 Redis 查询 + 1 次模型推理）——**决策延迟预算**（50ms~200ms）要按特征分项分配，热点特征预计算缓存。
- 易错点：规则直接查库算特征（性能与一致性双崩）；特征缺失静默 false（漏拦）；特征窗口与规则语义不匹配（"近 1 天"用 UTC 还是本地时区）；无特征版本（规则复现困难）。

**示例代码**
```java
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class RealtimeFeatures {
    /** 特征快照：带来源与新鲜度 */
    record Feature(String name, Object value, long computedAtMs, String source) {
    }

    record FeatureSet(Map<String, Feature> features, long snapshotAtMs) {
        /** 缺失或过期的特征清单 */
        List<String> missingOrStale(List<String> required, long maxAgeMs) {
            return required.stream().filter(n -> {
                Feature f = features.get(n);
                return f == null || snapshotAtMs - f.computedAtMs() > maxAgeMs;
            }).toList();
        }
    }

    /** 规则：引用的特征必须声明，缺失时按策略处理 */
    record Rule(String id, List<String> requires, String expr, String action,
                String onMissing) {          // DENY / SKIP / DEFAULT
    }

    static String evaluate(Rule r, FeatureSet set, long maxAgeMs) {
        List<String> missing = set.missingOrStale(r.requires(), maxAgeMs);
        if (!missing.isEmpty()) {
            return switch (r.onMissing()) {
                case "DENY" -> r.id() + " -> BLOCK（特征缺失：" + missing + "，保守拒绝）";
                case "SKIP" -> r.id() + " -> SKIP（特征缺失：" + missing + "）";
                default -> r.id() + " -> 按默认值求值";
            };
        }
        Object amount = set.features().get("amount").value();
        Object black = set.features().get("inBlacklist").value();
        boolean hit = (amount instanceof Number n && n.longValue() > 500_000)
                || Boolean.TRUE.equals(black);
        return r.id() + " -> " + (hit ? r.action() : "PASS");
    }

    public static void main(String[] args) {
        long now = 1_000_000;
        Map<String, Feature> fs = new LinkedHashMap<>();
        fs.put("amount", new Feature("amount", 800_000L, now - 20, "realtime"));
        fs.put("inBlacklist", new Feature("inBlacklist", false, now - 5000, "nearline"));
        var set = new FeatureSet(fs, now);

        List<Rule> rules = List.of(
                new Rule("R-1", List.of("amount", "inBlacklist"), "amount>500000", "BLOCK", "DENY"),
                new Rule("R-2", List.of("deviceAge"), "deviceAge>30", "CHALLENGE", "SKIP"),
                new Rule("R-3", List.of("riskScore"), "riskScore>80", "BLOCK", "DENY"));
        System.out.println("【特征齐全的规则】");
        System.out.println("  " + evaluate(rules.get(0), set, 60_000));
        System.out.println("【特征缺失：SKIP 策略】");
        System.out.println("  " + evaluate(rules.get(1), set, 60_000));
        System.out.println("【特征缺失：DENY 策略（保守）】");
        System.out.println("  " + evaluate(rules.get(2), set, 60_000));
        System.out.println();
        System.out.println("  铁律：缺失策略必须显式声明 —— 静默 false 等于漏拦");
    }
}
```

### 58-07 名单管理与名单同步

**知识点**
- **名单是风控最快见效的手段**：黑名单（必拦）、白名单（必放）、灰名单（观察/挑战）、设备名单、IP 名单、商户名单——**名单的命中应该是最短路径**（否则拦不住真实攻击的量）。
- **名单的存储与查询性能**：千万级黑名单用**布隆过滤器预筛 + 精确集合复核**（40-10/54-07 同款）；**Redis Set/Bitmap** 支持 O(1) 判断；**本地缓存 + 变更推送**（58-08）避免每次决策都查中心——**名单查询要在 1ms 内**。
- **名单的同步链路**：业务系统/风控运营 -> 名单中心（唯一事实源）-> 变更事件（MQ）-> 各决策节点本地缓存更新——**推拉结合**：推送失败靠定期全量对齐兜底（45-11 快照自持思想）。
- **名单的时效与冲突**：临时名单带 TTL（活动期封禁）；**多名单冲突**（黑名单 + 白名单同命中）——**白名单优先**（人工介入的强信号）或"黑名单优先"（安全优先）是业务决策，必须显式定义。
- **名单的审计与误伤**：每次名单变更有操作人/原因/审批（51-10）；**误加名单是高频事故**（客诉）——需要"名单生效前预览影响面"（影响多少笔交易）与一键撤销。
- 易错点：名单无 TTL（临时封禁变永久，客诉）；名单无审批（运营误加）；名单查询走 DB（性能崩）；黑白名单冲突无优先级（结果随机）。

**示例代码**
```java
import java.util.BitSet;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class ListManagement {
    /** 名单项：值 + 类型 + 过期时间 + 原因 */
    record Entry(String value, String listType, long expireAtMs, String reason) {
        boolean active(long now) {
            return expireAtMs == 0 || now < expireAtMs;
        }
    }

    /** 布隆预筛（快速否定） + 精确集合（避免误伤） */
    static class ListIndex {
        final BitSet bloom = new BitSet(4096);
        final Map<String, Entry> exact = new LinkedHashMap<>();

        void add(Entry e) {
            exact.put(e.value(), e);
            bloom.set(hash1(e.value()));
            bloom.set(hash2(e.value()));
        }

        boolean mightContain(String v) {
            return bloom.get(hash1(v)) && bloom.get(hash2(v));
        }

        static int hash1(String v) {
            return Math.abs(v.hashCode()) & 4095;
        }

        static int hash2(String v) {
            return Math.abs(v.hashCode() * 31 + 7) & 4095;
        }
    }

    /** 黑白名单冲突：白名单优先（人工强信号） */
    static String decide(ListIndex black, ListIndex white, String value, long now) {
        Entry w = white.exact.get(value);
        if (w != null && w.active(now)) {
            return "WHITELIST -> ALLOW（白名单优先）";
        }
        Entry b = black.exact.get(value);
        if (b != null && b.active(now)) {
            return "BLACKLIST -> BLOCK（原因：" + b.reason() + "）";
        }
        if (black.mightContain(value)) {
            return "布隆可能命中但精确未命中 -> ALLOW（误判，安全侧少拦）";
        }
        return "未命中名单 -> 继续后续规则";
    }

    public static void main(String[] args) {
        long now = 1000;
        var black = new ListIndex();
        black.add(new Entry("card-6222XXXX", "black", 0, "历史盗刷"));
        black.add(new Entry("ip-10.0.0.9", "black", 500, "临时封禁（已过期）"));
        var white = new ListIndex();
        white.add(new Entry("card-6222XXXX", "white", 0, "VIP 客户人工放行"));

        System.out.println("  黑+白同命中：" + decide(black, white, "card-6222XXXX", now));
        System.out.println("  黑名单过期：" + decide(black, white, "ip-10.0.0.9", now));
        System.out.println("  普通值：" + decide(black, white, "card-9999", now));
    }
}
```

### 58-08 规则热更新与灰度验证

**知识点**
- **规则热更新是规则引擎的核心诉求**：业务改规则不应等服务发版——**配置中心（53-03）承载规则**，客户端长轮询/推送获取变更，**秒级生效**；规则变更必须**版本化**（可回滚）与**审计**（51-10）。
- **灰度验证的四道关**：① **离线回放**（历史样本重放，对比新旧规则决策差异）；② **影子模式**（新规则只算不生效，记录"本会做什么"）；③ **小流量灰度**（1%~5% 真实流量，看指标）；④ **全量 + 观察期**。**跳过任何一环都是事故温床**。
- **规则变更的"影响面预览"**：新规则全量上线前**用最近 N 天样本跑一遍**，输出：新增拦截量、新增误拦（白名单客户被拦）、动作分布变化——**用数字说服业务方**（54-08 A/B 思想）。
- **回滚设计**：规则版本号 + 一键回退（保留最近 N 版）；**回滚演练**（47-10）——规则回滚比代码回滚快（配置级），但要验证回滚后行为正确。
- **变更风险的分类**：放宽类（少拦，资损风险）、收紧类（多拦，客诉风险）、符号/阈值类（最容易手滑）——**放宽类要更严格的门禁**（资损不可逆，客诉可补偿）。
- 易错点：规则直接全量生效（无灰度）；变更影响面无评估（上线才发现误拦 VIP）；规则无版本（回滚靠手改）；放宽类变更无额外审批（资损）。

**示例代码**
```java
import java.util.ArrayList;
import java.util.List;

public class RuleHotUpdate {
    record RuleVersion(String version, String expr, String action, long effectiveAtMs) {
    }

    record Sample(String eventId, long amount, boolean vip) {
    }

    record Impact(long total, long newBlocks, long newChallenges, List<String> vipFalsePositives) {
    }

    /** 影响面预览：历史样本回放，对比新旧决策 */
    static Impact preview(List<Sample> samples, long oldThreshold, long newThreshold) {
        long newBlocks = 0, newChallenges = 0;
        List<String> vipHits = new ArrayList<>();
        for (Sample s : samples) {
            boolean oldHit = s.amount() > oldThreshold;
            boolean newHit = s.amount() > newThreshold;
            if (!oldHit && newHit) {
                newBlocks++;
                if (s.vip()) {
                    vipHits.add(s.eventId());
                }
            }
        }
        return new Impact(samples.size(), newBlocks, newChallenges, vipHits);
    }

    /** 灰度放量：按事件 id 哈希分流 */
    static boolean inGray(String eventId, int percent) {
        return Math.abs(eventId.hashCode()) % 100 < percent;
    }

    static void rollout(List<Sample> samples, long oldThreshold, long newThreshold) {
        System.out.println("【灰度放量推演：10% -> 50% -> 100%】");
        for (int pct : new int[]{10, 50, 100}) {
            long grayCount = samples.stream()
                    .filter(s -> inGray(s.eventId(), pct)).count();

                    .filter(s -> inGray(s.eventId(), pct))

                    .count();
            System.out.printf("  灰度 %3d%%：覆盖样本 %d，其中新增拦截 %d%n", pct, grayCount, affected);
        }
    }

    public static void main(String[] args) {

        for (int i = 0; i < 1000; i++) {

        }
        long oldT = 120_000, newT = 80_000;          // 收紧阈值（多拦）

        System.out.printf("【影响面预览】样本 %d，新增拦截 %d（%.1f%%），涉及 VIP %d 个%n",
                imp.total(), imp.newBlocks(), imp.newBlocks() * 100.0 / imp.total(),

                .subList(0, Math.min(3, imp.vipFalsePositives().size())));

        System.out.println();
```

### 58-09 规则效果评估与误杀治理

**知识点**
- **规则上线只是开始，评估是常态**：每条规则要有**命中率/准确率/误杀率**——准确率 = 真命中 ÷ 总命中（需要人工标注样本或事后归因）；**长期零命中的规则要下线**（闲置规则是维护负担）。
- **误杀的发现渠道**：客诉（滞后但真实）、**人工抽检**（每日抽样标注）、**申诉闭环**（用户申诉 -> 标注 -> 反馈到规则）——**申诉数据是最宝贵的准确率样本**（44-10 点踩样本的风控版）。
- **评估的指标体系**：拦截量、拦截率、误杀率（误拦/总拦截）、漏拦率（事后发现的风险事件/未拦截总量）、决策耗时、规则贡献度（去掉这条规则会少拦多少）——**贡献度用于"规则精简"**。
- **规则精简与反冗余**：几百条规则后必然出现"重复覆盖"（两条规则拦同一批人）与"死规则"（永不命中）——**季度做一次规则体检**：合并重复、下线闲置、参数复用。
- **规则效果的可解释性**：对业务方解释"为什么拦他"——**命中规则 + 关键特征值 + 阈值**（44-09 证据链的风控版）；监管要求"可解释"（如信贷风控）。
- 易错点：只看拦截量不看误杀（拦得多不等于拦得对）；规则无贡献度分析（冗余堆积）；申诉数据不回流（同样的误杀反复发生）；无抽检（准确率永远未知）。

**示例代码**
```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class RuleEvaluation {
    record Hit(String ruleId, String eventId, boolean confirmedRisk) {
    }

    record Stats(String ruleId, int hits, int truePositives, double hitRate, double precision) {
    }

    /** 规则级评估：命中数、准确率、贡献度（去掉后少拦多少） */
    static Map<String, Stats> evaluate(List<Hit> hits, long totalEvents) {
        Map<String, Stats> out = new LinkedHashMap<>();
        Map<String, int[]> agg = new LinkedHashMap<>();
        for (Hit h : hits) {
            int[] a = agg.computeIfAbsent(h.ruleId(), k -> new int[2]);
            a[0]++;
            if (h.confirmedRisk()) {
                a[1]++;
            }
        }
        agg.forEach((rid, a) -> out.put(rid, new Stats(rid, a[0], a[1],
                a[0] * 100.0 / totalEvents,
                a[0] == 0 ? 0 : a[1] * 100.0 / a[0])));
        return out;
    }

    /** 规则体检：闲置（零命中）/ 低准确率 / 高贡献 */
    static List<String> healthCheck(Map<String, Stats> stats) {
        List<String> findings = new ArrayList<>();
        stats.forEach((rid, s) -> {
            if (s.hits() == 0) {
                findings.add(rid + "：闲置规则（零命中）-> 下线候选");
            } else if (s.precision() < 50) {
                findings.add(rid + "：准确率 " + String.format("%.0f%%", s.precision())
                        + " -> 误杀偏高，需调阈值或加白名单");
            } else if (s.precision() >= 90) {
                findings.add(rid + "：准确率 " + String.format("%.0f%%", s.precision())
                        + " -> 高价值规则，保持");
            }
        });
        return findings;
    }

    public static void main(String[] args) {
        List<Hit> hits = new ArrayList<>();
        // R-1：高准确率（20 次命中 19 次确认）
        for (int i = 0; i < 20; i++) {
            hits.add(new Hit("R-1", "e-1-" + i, i < 19));
        }
        // R-2：低准确率（10 次命中仅 3 次确认）
        for (int i = 0; i < 10; i++) {
            hits.add(new Hit("R-2", "e-2-" + i, i < 3));
        }
        // R-3：零命中（不在列表里 -> stats 里不会出现，用空规则显式说明）
        Map<String, Stats> stats = evaluate(hits, 10_000);
        stats.put("R-3", new Stats("R-3", 0, 0, 0, 0));

        System.out.println("【规则评估（样本 10000 事件）】");
        stats.forEach((rid, s) -> System.out.printf(
                "  %-4s 命中%3d 命中率%.2f%% 准确率%.0f%%%n",
                rid, s.hits(), s.hitRate(), s.precision()));
        System.out.println();
        System.out.println("【体检结论】");
        healthCheck(stats).forEach(f -> System.out.println("  - " + f));
    }
}
```

### 58-10 风控决策全链路

**知识点**
- **风控不是一个规则引擎，而是一条链路**：埋点采集（设备/行为）-> 特征计算（实时+近线）-> 名单预检（58-07）-> 规则链（58-05）-> 模型评分（可与规则融合）-> 决策聚合（动作分级）-> 执行（拦截/挑战/放行）-> 结果回流（58-09）。
- **决策延迟预算**：端到端 200ms 内——特征 60ms + 名单 5ms + 规则 20ms + 模型 80ms + 聚合执行 10ms，**每段可降级**（模型超时用规则兜底，44-08 阶梯）。
- **规则与模型的关系**：**规则管"确定性红线"**（黑名单/限额/地区禁售）、**模型管"概率性判断"**（团伙欺诈/羊毛党）；**融合方式**：规则先筛（成本低）-> 模型对幸存者打分 -> 决策聚合（规则 BLOCK 直接生效，模型分数参与 CHALLENGE 判断）。
- **决策的可解释与可申诉**：输出"决策 + 命中规则/模型分 + 关键特征"三件套——**用户申诉与监管审计都要这份证据**（44-09 trace 的风控版）。
- **误判的兜底路径**：CHALLENGE（二次验证）是"不确定时的最佳中间态"——**把 BLOCK 的很多场景降为 CHALLENGE，客诉大降而风险可控**（分级决策的价值）。
- 易错点：全链路无降级（模型超时整笔挂）；规则与模型结论冲突无仲裁（同笔交易两套结论）；决策无证据（申诉无法处理）；CHALLENGE 滥用（用户被反复打扰，转化下跌）。

**示例代码**
```java
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class RiskDecisionChain {
    record Decision(String eventId, String action, List<String> evidence,
                    double modelScore, String degraded) {
    }

    record Ctx(String eventId, long amountCents, boolean blacklisted,
               boolean newDevice, double modelScore, boolean modelTimeout) {
    }

    /** 全链路：名单 -> 规则（红线） -> 模型（概率） -> 聚合 */
    static Decision decide(Ctx ctx) {
        List<String> evidence = new java.util.ArrayList<>();
        String degraded = "none";

        // 1) 名单：硬红线，最短路径
        if (ctx.blacklisted()) {
            evidence.add("名单命中：黑名单");
            return new Decision(ctx.eventId(), "BLOCK", evidence, 0, degraded);
        }

        // 2) 规则：确定性红线
        if (ctx.amountCents() > 500_000) {
            evidence.add("规则命中：单笔超限（>5000 元）");
            return new Decision(ctx.eventId(), "BLOCK", evidence, 0, degraded);
        }
        if (ctx.newDevice()) {
            evidence.add("规则命中：新设备首笔交易");
        }

        // 3) 模型：概率判断（可降级）
        double score;
        if (ctx.modelTimeout()) {
            score = -1;
            degraded = "model-timeout -> 规则兜底（新设备转人工验证）";
            evidence.add("模型超时，降级为规则兜底");
            score = ctx.newDevice() ? 70 : 20;
        } else {
            score = ctx.modelScore();
            evidence.add("模型评分：" + String.format("%.0f", score));
        }

        // 4) 聚合：分级决策
        String action;
        if (score >= 80) {
            action = "BLOCK";
        } else if (score >= 50 || ctx.newDevice()) {
            action = "CHALLENGE";
        } else if (score >= 30) {
            action = "LOG";
        } else {
            action = "ALLOW";
        }
        return new Decision(ctx.eventId(), action, evidence, score, degraded);
    }

    public static void main(String[] args) {
        List<Ctx> cases = List.of(
                new Ctx("e-1", 6900, true, false, 10, false),
                new Ctx("e-2", 900_000, false, false, 10, false),
                new Ctx("e-3", 69_000, false, true, 40, false),
                new Ctx("e-4", 69_000, false, true, 85, false),
                new Ctx("e-5", 69_000, false, false, 0, true));
        for (Ctx c : cases) {
            Decision d = decide(c);
            System.out.printf("  %-4s -> %-9s 证据=%s%s%n", d.eventId(), d.action(),
                    d.evidence(), d.degraded().equals("none") ? "" : "  [降级:" + d.degraded() + "]");
        }
        System.out.println();
        System.out.println("  证据三件套随决策落库 -> 申诉与监管可解释");
    }
}
```

### 58-11 综合案例：支付风控规则引擎

**知识点**
- **把本章收口成一个可运行的支付风控引擎**：规则模型（58-02）-> 表达式求值（58-03）-> 决策表（58-04）-> 链式执行与冲突消解（58-05）-> 特征快照（58-06）-> 名单预检（58-07）-> 热更新影响面（58-08）-> 效果评估（58-09）-> 全链路决策（58-10）。
- **验收标准**：① 同一笔交易多次决策结果稳定（无随机）；② 证据链完整（命中什么规则、特征值多少）；③ 规则变更可回滚（版本）；④ 影响面可预览（历史回放）；⑤ 延迟可控（每段耗时可见）。
- **工程化的三件套**：规则库版本化（Git 或配置中心）、回归样本集（历史交易 + 标注）、监控看板（命中率/准确率/延迟 58-09）——**缺一件就只是"能跑的 Demo"**。
- **风控的边界认知**：规则引擎是"业务规则的可配置化"，**它不替代模型、不替代人工审核**——三层防线（规则红线 + 模型概率 + 人工兜底）的组合才是完整风控。
- 易错点：把规则引擎当"万能拦截器"（所有风险都靠规则）；无回归样本（改规则靠猜）；证据链缺失（申诉处理不了）；忽略延迟（规则越多越慢，特征计算才是大头）。

**示例代码**
```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class PaymentRiskEngine {
    record Rule(String id, String expr, String action, int priority, String version) {
    }

    record FeatureSet(Map<String, Long> numbers, Map<String, Boolean> flags) {
    }

    record Verdict(String decision, List<String> evidence, List<String> versions) {
    }

    /** 极简求值：支持 "k>n" 与布尔 flag */
    static boolean hit(Rule r, FeatureSet fs) {
        String e = r.expr();
        if (e.equals("always")) {
            return true;
        }
        if (e.contains(">")) {
            String[] p = e.split(">");
            Long v = fs.numbers().get(p[0].strip());
            return v != null && v > Long.parseLong(p[1].strip());
        }
        return Boolean.TRUE.equals(fs.flags().get(e));
    }

    static Verdict evaluate(List<Rule> rules, FeatureSet fs) {
        List<String> evidence = new ArrayList<>();
        List<String> versions = new ArrayList<>();
        String decision = "ALLOW";
        int bestSeverity = 0;
        List<Rule> sorted = new ArrayList<>(rules);
        sorted.sort((a, b) -> Integer.compare(b.priority(), a.priority()));
        for (Rule r : sorted) {
            if (hit(r, fs)) {
                evidence.add(r.id() + "[" + r.expr() + "] -> " + r.action());
                versions.add(r.version());
                int sev = switch (r.action()) {
                    case "BLOCK" -> 3;
                    case "CHALLENGE" -> 2;
                    case "LOG" -> 1;
                    default -> 0;
                };
                if (sev > bestSeverity) {
                    bestSeverity = sev;
                    decision = r.action();
                }
            }
        }
        return new Verdict(decision, evidence, versions);
    }

    /** 影响面预览：新旧规则集对历史样本的决策差异 */
    static void preview(List<Rule> oldRules, List<Rule> newRules, List<FeatureSet> samples) {
        long changed = 0;
        for (FeatureSet fs : samples) {
            String a = evaluate(oldRules, fs).decision();
            String b = evaluate(newRules, fs).decision();
            if (!a.equals(b)) {
                changed++;
            }
        }
        System.out.printf("  影响面：%d 笔样本中 %d 笔决策变化（%.1f%%）%n",
                samples.size(), changed, changed * 100.0 / samples.size());
    }

    public static void main(String[] args) {
        List<Rule> rules = List.of(
                new Rule("R-AMT-BIG", "amount>500000", "BLOCK", 100, "v3"),
                new Rule("R-BLACK", "inBlacklist", "BLOCK", 100, "v1"),
                new Rule("R-DEVICE", "newDevice", "CHALLENGE", 80, "v2"),
                new Rule("R-NIGHT", "nightTrade", "LOG", 20, "v1"));

        Map<String, Long> nums = new LinkedHashMap<>();
        nums.put("amount", 800_000L);
        Map<String, Boolean> flags = new LinkedHashMap<>();
        flags.put("inBlacklist", false);
        flags.put("newDevice", true);
        flags.put("nightTrade", true);

        Verdict v = evaluate(rules, new FeatureSet(nums, flags));
        System.out.println("【决策】" + v.decision());
        System.out.println("【证据链】");
        v.evidence().forEach(e -> System.out.println("  - " + e));
        System.out.println("【规则版本】" + v.versions());
        System.out.println();

        List<Rule> tightened = new ArrayList<>(rules);
        tightened.add(new Rule("R-AMT-MID", "amount>100000", "CHALLENGE", 60, "v4"));
        List<FeatureSet> samples = new ArrayList<>();
        for (long amt : new long[]{50_000, 120_000, 300_000, 900_000}) {
            samples.add(new FeatureSet(Map.of("amount", amt),
                    Map.of("inBlacklist", false, "newDevice", false, "nightTrade", false)));
        }
        System.out.println("【新规则 v4 影响面预览】");
        preview(rules, tightened, samples);
        System.out.println("  决策稳定 + 证据完整 + 影响面可预览 = 可上线的规则引擎");
    }
}
```
