## 卷一 平台与数据（容器化 + 搜索 + 分库分表）

**知识点注释**
- 【题目要求】设计并实现「商品中台迷你系统」的三个模块：① 容器化模块——构建缓存评估器（37-01 升级版：支持 Dockerfile 解析与变更清单）；② 搜索模块——倒排索引 + BM25 排序（38 章合并升级：索引构建、布尔查询、评分排序、explain 输出）；③ 分库分表模块——基因法路由 + 均匀度报告（39 章合并升级）。三模块用统一命令行入口驱动，演示“一个商品从建索引到分库”的完整数据流。
- 【考核点】跨模块数据流编排、构建缓存判定、倒排与评分、基因路由与均匀度、模块边界（每模块独立类）。
- 【易错点】模块间直接互拷字段（无边界）；索引与分库的数据口径不一致；演示脚本缺主流程叙事。
- 【提示】先用 52-01 估算确定规模假设（商品 10 万、QPS 500），再实现——数字贯穿三模块。

**示例代码**（技术示范：命令行驱动编排，非本题答案）
```java
import java.util.LinkedHashMap;
import java.util.Map;

public class MiniPlatformDemo {
    public static void main(String[] args) {
        Map<String, Runnable> modules = new LinkedHashMap<>();
        modules.put("build-cache", () -> System.out.println("  [构建缓存] 评估演示：3 层命中 1 层重算"));
        modules.put("search", () -> System.out.println("  [搜索] 演示：倒排命中 2 篇，BM25 排序输出"));
        modules.put("sharding", () -> System.out.println("  [分库] 演示：基因路由命中 shard-3"));
        String command = args.length > 0 ? args[0] : "help";
        Runnable runnable = modules.get(command);
        if (runnable == null) {
            System.out.println("  可用模块：" + modules.keySet());
        } else {
            runnable.run();
        }
    }
}
```

**课后练习题**
1. 完整实现三模块并串联：建商品 -> 写索引 -> 落分库，演示一条商品的完整数据流。
2. 为三模块分别写“规模 ×10 会怎样”的演进段落（每段 ≥150 字）。
3. 用 52-02 模板为“存储选型（MySQL+ES+分库）”写一份 ADR。

## 卷二 观测与共识（可观测 + 流处理 + 配置中心）

**知识点注释**
- 【题目要求】实现「服务健康迷你平台」：① 指标层——Histogram 分位数（42-01 升级：多实例聚合）；② 告警层——聚合抑制器（42-02 升级：依赖方向表 + 窗口）；③ 流层——水位线窗口聚合（43 章合并：事件时间、容忍度、旁路）；④ 共识层——配置中心客户端（45-11 升级：本地快照 + 版本单调 + 拉齐兜底）。演示一条完整线：指标异常 -> 告警事件 -> 配置变更（阈值调整）-> 客户端热更新。
- 【考核点】四层协同、trace 思想贯穿（42 章）、水位线与容忍度、配置版本 fencing、演示叙事完整。
- 【易错点】四层各自为政无连接（演示不成一条线）；告警与指标口径不一致；配置更新无版本校验。
- 【提示】用同一个“故障脚本”驱动：注入 DB 慢查询 -> 指标劣化 -> 告警聚合 -> 调整熔断阈值（配置热更）。

**示例代码**（技术示范：脚本驱动编排，非本题答案）
```java
import java.util.ArrayList;
import java.util.List;

public class HealthPlatformDemo {
    public static void main(String[] args) {
        List<String> timeline = new ArrayList<>(List.of(
                "T+0    注入：DB 慢查询",
                "T+2min 指标：order P99 470ms（超阈值）",
                "T+3min 告警聚合：根因 db，抑制下游 3 条",
                "T+4min 决策：调熔断阈值（配置 v42 -> v43）",
                "T+4min 客户端热更新：本地快照 v43"));
        for (String s : timeline) {
            System.out.println("  " + s);
        }
    }
}
```

**课后练习题**
1. 完整实现四层并跑通故障脚本，输出每层的内部状态变化（指标/事件/水位/版本）。
2. 演练“配置中心全挂”：验证客户端自持快照存活与恢复后对齐（45-11）。
3. 用 52-04 四步法把本卷写成一篇系统设计短文（800 字以内）。

## 卷三 架构与资金（DDD + 虚拟线程 + 支付）

**知识点注释**
- 【题目要求】实现「订单-支付迷你域」：① 建模层——订单聚合（不变量四条 49 章）+ 支付单状态机（51 章三层幂等）；② 并发层——虚拟线程扇出（调用库存/券两个域，Semaphore 限流，50 章）；③ 资金层——复式记账分录（支付成功事件 -> 借贷平衡分录，51-08）；④ 验收——并发 200 请求压测：无超卖、无重复记账、分录试算平衡、幂等零重复。输出压测报告与不变量守护证据。
- 【考核点】聚合不变量并发守护、状态机与三层幂等、虚拟线程编排、复式记账平衡、跨层验收叙事。
- 【易错点】域间直接同步调用（应事件驱动 49-03）；幂等键缺失一层；压测无不变量断言（只有“没报错”）。
- 【提示】压测报告的关键数字：成功订单数 = 记账分录数 = 事件数（三方恒等）。

**示例代码**（技术示范：三方恒等断言，非本题答案）
```java
public class IdentityCheckDemo {
    public static void main(String[] args) {
        long orders = 186, ledgerEntries = 186, events = 186;
        boolean identity = orders == ledgerEntries && ledgerEntries == events;
        System.out.printf("  订单 %d = 分录 %d = 事件 %d -> 三方恒等：%b%n",
                orders, ledgerEntries, events, identity);
        System.out.println("  恒等式破坏 = 资金/数据事故的信号（42 章对账思想）");
    }
}
```

**课后练习题**
1. 完整实现四层并跑 200 并发压测，输出三方恒等报告与全部被拒请求的分类清单。
2. 注入三个故障（券域宕机/渠道回调丢失/重复回调），验证降级、幂等与恒等式恢复。
3. 按四维评分表（52-10：定位路径/恢复速度/权衡表达/知识连接）自评本卷，写 500 字答辩稿。
