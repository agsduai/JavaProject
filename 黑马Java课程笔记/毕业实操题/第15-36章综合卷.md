## 卷一 业务核心综合（集合 + IO + 多线程 + 网络）

**知识点注释**
- 【题目要求】实现「订单批处理管道」：① 读取订单 CSV 文件（含脏数据行）；② 多线程分片解析与校验（脏数据收集进错误清单，不中断）；③ Stream 聚合统计（按城市/状态）；④ 结果写回结果文件；⑤ 通过 TCP 上报处理进度（本地 HttpServer 或 Socket 接收端模拟）。验收：脏行不丢单不阻塞、并发校验正确（与串行一致）、进度可观测。
- 【考核点】IO 读与解析容错、多线程分片与聚合正确性、Stream 统计、网络上报、管道编排。
- 【易错点】解析异常中断全批（应收集错误继续）；并发聚合结果与串行不一致（无同步聚合）；进度上报阻塞主流程（应异步）。
- 【提示】分片策略：按行号取模分给 N 个线程，各线程独立校验后合并——正确性用"并行结果 == 串行结果"验证。

**示例代码**（技术示范：脏行容错，非本题答案）
```java
import java.util.ArrayList;
import java.util.List;

public class TolerantParseDemo {
    record Order(String id, long amountCents) {
    }

    static List<Order> parse(List<String> lines, List<String> errors) {
        List<Order> ok = new ArrayList<>();
        for (int i = 0; i < lines.size(); i++) {
            String[] p = lines.get(i).split(",");
            try {
                ok.add(new Order(p[0], Long.parseLong(p[1])));
            } catch (Exception e) {
                errors.add("第" + (i + 1) + "行脏数据：" + lines.get(i));
            }
        }
        return ok;
    }

    public static void main(String[] args) {
        List<String> errors = new ArrayList<>();
        List<Order> orders = parse(List.of("9001,6900", "bad,line", "9002,3900"), errors);
        System.out.println("  有效订单：" + orders.size() + "  脏行：" + errors);
    }
}
```

**课后练习题**
1. 完整实现五段管道（IO->并发解析->统计->写回->进度上报），10 万行模拟数据跑通全链。
2. 实现"并行结果 == 串行结果"的等价性验证（统计快照比对），并故意制造一次不等价定位原因。
3. 输出设计说明：分片策略、容错策略、上报频率三项的决策理由（52-04 取舍模板）。

## 卷二 数据与框架综合（MySQL + JDBC + MyBatis + Spring Boot）

**知识点注释**
- 【题目要求】实现「用户中心迷你栈」：① SQL 层——建表（用户/地址两表）与三条典型 SQL（join/分页/聚合），附 EXPLAIN 说明；② DAO 层——JdbcTemplate + RowMapper + 参数绑定审计（21 章模板）；③ Mapper 层——动态代理 Mapper（23 章）配动态 SQL（条件查询）；④ 应用层——校验注解 + 统一异常 + 自动配置模拟（24 章）。验收：SQL 全参数化、三层边界清晰、异常与校验响应规范。
- 【考核点】SQL 语义与执行计划、模板与映射分层、动态 SQL、校验与统一异常、层间依赖方向。
- 【易错点】层间穿透（Controller 直调 JDBC）；动态 SQL 首条件 AND；校验错误逐个返回（应聚合）。
- 【提示】用内存表模拟数据源（46-08 同款），把四层真实串起来——重点考核分层纪律而非真实 DB 连接。

**示例代码**（技术示范：分层边界，非本题答案）
```java
import java.util.ArrayList;
import java.util.List;

public class LayeredDemo {
    /** 数据层：只管存取 */
    static class UserDao {
        List<String> table = new ArrayList<>();

        void insert(String name) {
            table.add(name);
        }

        List<String> findByName(String name) {
            return table.stream().filter(n -> n.equals(name)).toList();
        }
    }

    /** 应用层：编排 + 校验，不写 SQL */
    static class UserService {
        final UserDao dao;

        UserService(UserDao dao) {
            this.dao = dao;
        }

        List<String> register(String name) {
            if (name == null || name.isBlank()) {
                throw new IllegalArgumentException("name 不能为空");
            }
            dao.insert(name);
            return dao.findByName(name);
        }
    }

    public static void main(String[] args) {
        UserService svc = new UserService(new UserDao());
        System.out.println("  注册结果：" + svc.register("alice"));
    }
}
```

**课后练习题**
1. 完整实现四层迷你栈（含两条表的 SQL 设计与 EXPLAIN 说明），演示用户注册→查询→聚合全流程。
2. 故意"层间穿透"一次（Controller 拼 SQL），对照评审清单（49-11 六问）说明违反了哪条边界。
3. 为本卷全部决策写 ADR（52-02）：存储、DAO 模板、校验策略、异常规范。

## 卷三 深度与质量综合（JVM + 并发 + 测试 + 安全）

**知识点注释**
- 【题目要求】实现「安全压测套件」：① 被测目标——带 synchronized 热点的计数服务（50-06 pinning 素材）+ 弱口令注册接口（36-02）；② 压测工具——虚拟线程压测器（并发可配、耗时统计 P50/P99）；③ 检测工具——ThreadMXBean 死锁检测 + JFR pinning 提示 + 弱口令拦截率统计；④ 报告——压测数字、缺陷清单（pinning/弱口令）、修复建议。验收：报告三件套齐全（数字/缺陷/建议）。
- 【考核点】压测方法（50-09）、并发缺陷检测（32 章）、安全测试（36 章）、报告工程（42-11 复盘形态）。
- 【易错点】压测无分位数（只有平均值）；缺陷无证据（只说"可能有问题"）；修复建议不可执行（"注意性能"式空话）。
- 【提示】报告模板：现象（数字）-> 证据（工具输出）-> 根因 -> 建议动作（可执行）。

**示例代码**（技术示范：P 统计，非本题答案）
```java
import java.util.ArrayList;
import java.util.List;

public class PercentileReportDemo {
    public static void main(String[] args) {
        List<Long> costs = new ArrayList<>(List.of(20L, 25L, 30L, 28L, 22L, 90L));
        costs.sort(Long::compare);
        int n = costs.size();
        System.out.printf("  P50=%dms P90=%dms Max=%dms（样本 %d）%n",
                costs.get((int) (0.5 * n)), costs.get((int) (0.9 * n)), costs.get(n - 1), n);
    }
}
```

**课后练习题**
1. 完整实现四件套（目标/压测/检测/报告），对两个缺陷各输出证据与可执行的修复建议。
2. 修复 pinning 与弱口令后复测，输出修复前后对比报告（数字说话）。
3. 按 52-10 四维评分自评本卷，并模拟一次答辩追问（规模 ×10 会怎样）。
