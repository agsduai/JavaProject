### 实操 20-01 SQL 语义模拟器

**知识点注释**
- 【题目要求】用内存表（List<Map<String,Object>>）实现迷你 SQL 引擎：支持 SELECT 列/带 WHERE（=、>、LIKE 前缀）/ORDER BY/LIMIT 的执行器；实现一个 JOIN（订单表 join 用户表取用户名）；输出每条 SQL 的"执行计划"（扫描行数 -> 过滤后行数）。
- 【考核点】SELECT/WHERE/ORDER/LIMIT 语义、内连接语义、执行计划概念（扫描 vs 过滤）。
- 【易错点】LIKE 把前缀匹配实现成 contains（应 startsWith，38 章索引原理呼应）；JOIN 产生笛卡尔积未按键过滤；ORDER 对 null 值的排序位置未定义。
- 【提示】先实现"全表扫描版本"，再实现"有索引版本"（Map<key, rows>），对比扫描行数——索引价值的代码级呈现。

**示例代码**（技术示范：过滤语义，另一套场景）
```java
import java.util.List;
import java.util.stream.Collectors;

public class MiniSqlDemo {
    record User(long id, String name, int age) {
    }

    public static void main(String[] args) {
        List<User> users = List.of(new User(1, "a", 20), new User(2, "b", 30),
                new User(3, "c", 25));
        List<User> hit = users.stream()
                .filter(u -> u.age() > 22)
                .sorted((a, b) -> Integer.compare(b.age(), a.age()))
                .limit(2)
                .collect(Collectors.toList());
        System.out.println("  WHERE age>22 ORDER BY age DESC LIMIT 2 -> " + hit);
    }
}
```

**课后练习题**
1. 实现完整迷你 SQL 引擎（SELECT/WHERE/ORDER/LIMIT/JOIN），跑 5 条 SQL 并输出执行计划。
2. 实现"索引加速"：给 user.id 建哈希索引，对比点查的扫描行数（10 vs 1）。
3. 思考题：为什么 LIKE 前缀匹配能走索引而后缀不行？从 B+ 树有序性推导（39-02）。

### 实操 20-02 事务与隔离级别模拟

**知识点注释**
- 【题目要求】用两线程 + 共享账户表模拟隔离级别问题：读未提交（读到对方未 commit 的扣款）、读已提交（版本快照）、可重复读（首次读建快照）、串行化（全局锁）；每个级别跑同一场"转账对账"脚本，输出各级别的现象与适用建议。
- 【考核点】脏读/不可重复读/幻读的定义与演示、隔离级别递进、快照读概念（MVCC 雏形）。
- 【易错点】把"读到旧值"误判为脏读（脏读专指未提交数据）；串行化与"加锁"混淆；幻读与不可重复读不分。
- 【提示】数据带版本链（value + committed 标志），读侧按级别决定"取最新还是取快照"。

**示例代码**（技术示范：脏读判定，另一套场景）
```java
public class DirtyReadDemo {
    static volatile int value = 100;
    static volatile boolean committed = false;

    public static void main(String[] args) throws Exception {
        Thread writer = new Thread(() -> {
            value = 50;                       // 未提交
            try {
                Thread.sleep(100);
            } catch (InterruptedException e) {
            }
            committed = true;                 // 提交
        });
        writer.start();
        Thread.sleep(50);                     // 读侧在提交前读
        System.out.printf("  读未提交视角读到 %d（committed=%b）-> %s%n",
                value, committed, committed ? "正常读" : "脏读！");
        writer.join();
        System.out.printf("  提交后读到 %d%n", value);
    }
}
```

**课后练习题**
1. 实现四级隔离完整模拟（版本链 + 快照），四种现象各造一个用例并标注级别。
2. 实现"幻读"用例：可重复读级别下两次范围查询，第二次多出一行（MVCC 快照应避免——先复现再修）。
3. 思考题：为什么 MySQL 默认选可重复读而不是读已提交？从业务对账与锁开销两个角度分析。

### 实操 21-02 批量写入与事务

**知识点注释**
- 【题目要求】实现批量插入对比：逐条插入 1000 行 vs addBatch+executeBatch（分批 500），统计耗时；任一批失败则整体回滚（事务边界），输出"部分插入被回滚"的证据；实现 savepoint（保留前 500 行，只回滚后 500）。
- 【考核点】批处理 API、事务边界与回滚、Savepoint 局部回滚、批量与事务的组合。
- 【易错点】逐条 executeUpdate（性能差一个数量级）；回滚未关自动提交；Savepoint 释放顺序混乱。
- 【提示】模拟层用"插入计数器 + 故障注入点"演示回滚——计数器回滚即证据。

**示例代码**（技术示范：回滚证据，另一套场景）
```java
import java.util.ArrayList;
import java.util.List;

public class TxRollbackDemo {
    static List<String> committed = new ArrayList<>();

    static void tx(List<String> writes, String failAt) {
        List<String> pending = new ArrayList<>();
        for (String w : writes) {
            if (w.equals(failAt)) {
                System.out.printf("  写 %s 失败 -> 回滚 %d 条（已提交不受影响：%s）%n",
                        w, pending.size(), committed);
                return;
            }
            pending.add(w);
        }
        committed.addAll(pending);
    }

    public static void main(String[] args) {
        tx(List.of("w1", "w2", "w3"), null);
        tx(List.of("w4", "BOOM", "w5"), "BOOM");
        System.out.println("  最终已提交：" + committed);
    }
}
```

**课后练习题**
1. 实现批量 vs 逐条的性能对比（1000 行，输出耗时），并实现事务回滚与 Savepoint 局部回滚。
2. 注入"第 600 行失败"，验证前 500 行已批提交（分批边界）与后 500 行回滚的账目清晰。
3. 思考题：为什么批量插入快一个数量级？从网络往返与语句解析复用两个成本项分析。

### 实操 22-01 依赖冲突调解器

**知识点注释**
- 【题目要求】实现依赖树与冲突调解：依赖节点（groupId/artifactId/version/依赖列表）；实现最近优先（路径短的胜出）与最先声明优先（同深度按声明顺序）；输出解析后的有效版本树与"被忽略的依赖"清单；模拟 fastjson 2.4 与 2.9 经由不同路径汇聚的冲突场景。
- 【考核点】依赖树解析、Maven 调解规则（最近优先/最先声明）、依赖排除（exclusion）、冲突的发现方法。
- 【易错点】以为声明的版本一定生效（被更短路径覆盖）；不知道版本冲突的存在（无 dependency:tree 习惯）；升级依赖不查传递依赖。
- 【提示】递归解析时记录路径深度，冲突时按"深度小者胜，同深度先声明胜"裁决并记录被淘汰者。

**示例代码**（技术示范：最近优先，另一套场景）
```java
import java.util.LinkedHashMap;
import java.util.Map;

public class NearestDemo {
    static Map<String, String> resolved = new LinkedHashMap<>();

    static void declare(String artifact, String version, int depth) {
        String cur = resolved.get(artifact);
        if (cur == null) {
            resolved.put(artifact, version);
        } else {
            System.out.printf("  冲突：%s 已解析为 %s（更近路径），忽略 %s%n", artifact, cur, version);
        }
    }

    public static void main(String[] args) {
        declare("lib-a", "1.0", 1);
        declare("lib-a", "2.0", 3);
        System.out.println("  解析结果：" + resolved);
    }
}
```

**课后练习题**
1. 实现完整调解器（递归树 + 两条规则 + 排除清单），构造三路冲突场景验证裁决顺序。

### 实操 22-02 生命周期与插件钩子

**知识点注释**
- 【题目要求】实现迷你生命周期：validate -> compile -> test -> package 四个阶段（有序执行，前序失败即停）；插件绑定到阶段（compile 阶段挂 compiler 插件、test 段挂 surefire）；实现 `mvn package` 语义（执行到 package 含之前全部阶段）；跳过测试的 -DskipTests 语义实现。
- 【考核点】生命周期相位有序性、插件目标绑定、命令映射到相位区间、skip 参数语义。
- 【易错点】以为 `mvn package` 只跑 package（实际包含前置相位）；插件绑定错相位（测试插件挂到 compile）；跳过测试后 package 仍依赖 test 产物。
- 【提示】相位用有序列表，执行区间 = 从头到目标相位；skipTests 只影响 test 相位的插件目标。

**示例代码**（技术示范：相位区间，另一套场景）
```java
import java.util.List;

public class LifecycleDemo {
    static final List<String> PHASES = List.of("validate", "compile", "test", "package");

    static void run(String target, boolean skipTests) {
        int end = PHASES.indexOf(target);
        for (int i = 0; i <= end; i++) {
            String phase = PHASES.get(i);
            if (skipTests && phase.equals("test")) {
                System.out.println("  " + phase + " -> SKIPPED");
                continue;
            }
            System.out.println("  " + phase + " -> 执行绑定插件");
        }
    }

    public static void main(String[] args) {
        run("package", true);
    }
}
```

**课后练习题**
1. 实现完整生命周期模拟（相位 + 插件绑定 + skip + 失败即停），用"test 失败"验证 package 不执行。
2. 实现自定义插件绑定（clean 相位挂删除临时文件目标），演示绑定配置。
3. 思考题：为什么 `mvn test` 会先执行 validate/compile？从生命周期的设计目的（保证前置状态）分析。

### 实操 23-01 Mapper 动态代理模拟

**知识点注释**
- 【题目要求】用 JDK 动态代理模拟 MyBatis Mapper：定义 UserMapper 接口（findById/update/insert）；代理 InvocationHandler 解析方法名与参数 -> 映射到"SQL 模板注册表" -> 执行模拟查询 -> 结果经 RowMapper 转对象返回；接口无需实现类（MyBatis 的核心魔法拆解）；演示未注册 SQL 时的报错。
- 【考核点】动态代理（31 章）、接口到 SQL 的映射机制、参数绑定、代理层的职责（MyBatis 只做映射，执行交 JDBC）。
- 【易错点】以为 Mapper 有实现类（运行时代理生成）；方法名拼写错在编译期不报（运行期才报 SQL 未注册）；把业务逻辑写进 Mapper（应只有数据访问）。
- 【提示】SQL 注册表 key = 接口全名.方法名；invoke 里按 key 取模板执行。

**示例代码**（技术示范：接口代理，另一套场景）
```java
import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Method;
import java.lang.reflect.Proxy;

public class MapperProxyDemo {
    interface UserDao {
        String findById(long id);
    }

    public static void main(String[] args) {
        UserDao dao = (UserDao) Proxy.newProxyInstance(
                UserDao.class.getClassLoader(), new Class<?>[]{UserDao.class},
                (InvocationHandler) (proxy, method, args1) -> {
                    System.out.println("  代理拦截：" + method.getName() + " 参数=" + args1[0]);
                    return "user-" + args1[0];
                });
        System.out.println("  调用结果：" + dao.findById(1001));
        System.out.println("  接口没有实现类 —— 代理在运行时生成行为");
    }
}
```

**课后练习题**
1. 实现完整 Mapper 代理（SQL 注册表 + 参数绑定 + 结果映射 + 未注册报错），跑三个接口方法。
2. 支持注解 SQL（@Select("...")），代理读取方法注解而不是注册表。
3. 思考题：为什么 MyBatis 选择"接口 + 动态代理"而不是"XML 生成实现类"？从开发体验与运行时灵活性对比。

### 实操 23-02 动态 SQL 拼接器

**知识点注释**
- 【题目要求】实现动态 SQL 拼接（模拟 <if>/<where>/<foreach>）：查询条件对象（可选 name/status/idList）-> 按 null 判断拼 WHERE 片段（首条件无 AND）-> foreach 生成 IN 占位符列表 -> 输出最终 SQL 与参数顺序；注入恶意输入验证参数化下"值永不进结构"。
- 【考核点】动态 SQL 条件拼接、WHERE 首条件与 AND 处理、foreach 占位符生成、参数化防注入。
- 【易错点】首条件多余 AND（where 标签语义）；foreach 占位符数量与参数数量不匹配；拼接用户输入进 SQL（注入）。
- 【提示】实现"片段列表 + 连接器"：条件非空才加入片段，连接器负责首片段无 AND。

**示例代码**（技术示范：条件拼接，另一套场景）
```java
import java.util.ArrayList;
import java.util.List;

public class DynamicSqlDemo {
    public static void main(String[] args) {
        List<String> fragments = new ArrayList<>();
        String name = "abc";           // 非 null -> 参与
        Integer minAge = null;         // null -> 跳过
        if (name != null) {
            fragments.add("name LIKE ?");
        }
        if (minAge != null) {
            fragments.add("age >= ?");
        }
        StringBuilder where = new StringBuilder();
        for (int i = 0; i < fragments.size(); i++) {
            if (i > 0) {
                where.append(" AND ");
            }
            where.append(fragments.get(i));
        }
        System.out.println("  动态 SQL：SELECT * FROM t WHERE " + where);
    }
}
```

**课后练习题**
1. 实现完整动态 SQL 拼接器（if/where/foreach），四种参数组合输出四种 SQL 与参数序。
2. 对比"字符串拼接用户输入"与"参数绑定"在同恶意输入下的 SQL 形态（36-02 复习）。
3. 思考题：为什么动态 SQL 的每个片段都用占位符而非拼值？从注入与缓存（预编译复用）两个角度分析。

### 实操 24-01 自动配置模拟

**知识点注释**
- 【题目要求】模拟 Spring Boot 自动配置：条件注解 `@ConditionalOnClass("redis")` 与 `@ConditionalOnMissingBean`；类路径探测（模拟 Map 存在性）-> 满足条件注册默认 Bean -> 用户显式定义的 Bean 优先（MissingBean 检查）；输出容器装配过程（哪些自动配置生效、哪些被用户覆盖）。
- 【考核点】自动配置原理（条件装配）、约定优于配置、用户覆盖优先级、装配日志可观测。
- 【易错点】以为自动配置是"魔法"（本质是条件化注册）；用户 Bean 与自动 Bean 冲突时报错而非覆盖；条件探测顺序未定义。
- 【提示】按"用户 Bean 先注册 -> 自动配置只补缺失"的顺序实现，即 MissingBean 语义。

**示例代码**（技术示范：条件装配，另一套场景）
```java
import java.util.HashMap;
import java.util.Map;

public class ConditionalDemo {
    record BeanDef(String name, String source) {
    }

    static Map<String, BeanDef> container = new HashMap<>();

    static void register(String name, String source, boolean condition, boolean missing) {
        if (condition && missing) {
            container.put(name, new BeanDef(name, source));
            System.out.printf("  注册 %s（来源：%s）%n", name, source);
        } else if (condition && !missing) {
            System.out.printf("  跳过 %s：用户已定义%n", name);
        } else {
            System.out.printf("  跳过 %s：条件不满足%n", name);
        }
    }

    public static void main(String[] args) {
        container.put("myCache", new BeanDef("myCache", "user"));      // 用户已定义
        register("cache", "auto-config", true, !container.containsKey("myCache"));
        register("queue", "auto-config", false, true);                 // classpath 无 MQ -> 不装配
    }
}
```

**课后练习题**
1. 实现完整自动配置模拟（classpath 探测 + MissingBean + 装配日志），演示"引入依赖即生效"与"用户覆盖"。
2. 实现 `@ConditionalOnProperty`（配置开关控制装配），演示开关切换两种实现。

### 实操 24-02 参数校验与统一异常

**知识点注释**
- 【题目要求】实现迷你校验框架：注解 @NotBlank/@Min/@Max（字段级）-> 校验器反射扫描 -> 错误收集（字段:消息列表）-> 全部通过才执行业务；实现统一异常处理：业务异常（含错误码）与校验异常分别转不同响应结构（模拟 ControllerAdvice 语义）；用 3 个对象（全对/缺字段/超限）验证。
- 【考核点】校验注解与反射扫描、错误收集与聚合返回、异常分层（业务/校验/系统）、统一响应结构。
- 【易错点】校验失败抛异常中断（应聚合所有错误一次返回）；业务异常与系统异常混用同一响应；错误码无规范（调用方无法程序化处理）。
- 【提示】校验器返回"错误清单"而不是首个错误——聚合返回是用户体验与调试效率的关键。

**示例代码**（技术示范：聚合校验，另一套场景）
```java
import java.util.ArrayList;
import java.util.List;

public class ValidationDemo {
    record User(String name, int age) {
    }

    static List<String> validate(User u) {
        List<String> errors = new ArrayList<>();
        if (u.name() == null || u.name().isBlank()) {
            errors.add("name: 不能为空");
        }
        if (u.age() < 0 || u.age() > 150) {
            errors.add("age: 超出合理范围");
        }
        return errors;
    }

    public static void main(String[] args) {
        List<String> errs = validate(new User("", -1));
        System.out.println("  聚合错误：" + errs + "（一次性返回全部，而不是逐个试错）");
    }
}
```

**课后练习题**
1. 实现完整校验框架（三注解 + 反射扫描 + 聚合返回）+ 统一异常处理（两类异常两种响应）。
2. 实现"分组校验"（创建时校验全部字段，更新时只校验非空字段），演示分组语义。
3. 思考题：为什么校验异常与业务异常要分两种响应结构？从前端处理逻辑与错误码规范化分析。
