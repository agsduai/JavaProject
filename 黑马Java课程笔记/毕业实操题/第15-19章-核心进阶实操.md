### 实操 15-01 Stream 流水线统计报表

**知识点注释**
- 【题目要求】给定订单列表（订单号/金额/状态/城市），用 Stream 完成四项统计：各状态订单数、各城市 GMV（降序 Top3）、金额高于平均值的所有订单号、用 groupingBy + counting 统计状态分布；输出格式化报表。
- 【考核点】Stream 中间/终端操作、collect 与 Collectors（groupingBy/summingLong/counting）、Comparator 排序、Optional 处理。
- 【易错点】多次遍历同一流（流只能消费一次）；groupingBy 后误用 sum 而非 summingLong；排序比较器方向颠倒。
- 【提示】报表风格输出：先算平均值（terminal），再过滤高于平均——注意平均值要用集合先落袋。

**示例代码**（技术示范：groupingBy 聚合，另一套场景）
```java
import java.util.List;
import java.util.Map;
import java.util.stream.Collectors;

public class StreamStatDemo {
    record Sale(String city, long amount) {
    }

    public static void main(String[] args) {
        List<Sale> sales = List.of(new Sale("杭州", 100), new Sale("杭州", 200),
                new Sale("上海", 300), new Sale("上海", 50), new Sale("北京", 80));
        Map<String, Long> byCity = sales.stream().collect(
                Collectors.groupingBy(Sale::city, Collectors.summingLong(Sale::amount)));
        byCity.entrySet().stream()
                .sorted((a, b) -> Long.compare(b.getValue(), a.getValue()))
                .limit(2)
                .forEach(e -> System.out.printf("  %s GMV=%d%n", e.getKey(), e.getValue()));
    }
}
```

**课后练习题**
1. 完整实现四项统计报表，并用 20 条订单验证各统计口径（含边界：空列表、全相同金额）。
2. 用 parallelStream 重跑统计，验证结果一致并测量加速比（记录线程开销的观察）。
3. 思考题：为什么 Stream 只能消费一次？从"管道与终端操作"的语义分析并给出复用数据的正确姿势。

### 实操 15-02 Map 去重与分组倒排

**知识点注释**
- 【题目要求】实现商品标签倒排：给定商品列表（id + 标签数组），构建 Map<标签, List<商品id>>（computeIfAbsent）；实现按标签集合的"与查询"（取交集）；实现去重（同 id 合并标签取并集）输出合并后清单；三个功能各一个方法。
- 【考核点】HashMap/computeIfAbsent、ArrayList 值列表维护、集合交集、LinkedHashMap 保序。
- 【易错点】get 后手动判空再 add（应使用 computeIfAbsent）；交集直接 removeAll 修改原集合；去重用双重循环 O(n²)。
- 【提示】交集用"最小集合驱动 + contains"或转 Set 复用 retainAll 的副本。

**示例代码**（技术示范：computeIfAbsent，另一套场景）
```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class InvertMapDemo {
    public static void main(String[] args) {
        Map<String, List<String>> index = new LinkedHashMap<>();
        addTo(index, "科幻", "书A");
        addTo(index, "科幻", "书B");
        addTo(index, "历史", "书C");
        System.out.println("  倒排：" + index);
    }

    static void addTo(Map<String, List<String>> index, String tag, String item) {
        index.computeIfAbsent(tag, k -> new ArrayList<>()).add(item);
    }
}
```

### 实操 16-01 文件遍历统计器

**知识点注释**
- 【题目要求】对指定目录递归遍历：统计文件数/目录数/总字节数，找最大文件；按扩展名分组统计（.java/.md/...）；跳过隐藏目录；输出树形概览（缩进两级即可）。
- 【考核点】Files.walk/DirectoryStream、File 属性读取、分组统计、递归与异常处理（权限拒绝）。
- 【易错点】walk 不关流（try-with-resources）；符号链接导致死循环；IOException 在 lambda 里无法抛出需包装。
- 【提示】Files.walkFileTree 或 Files.walk（Stream）二选一，统一在 catch 里记录跳过原因。

**示例代码**（技术示范：walkFileTree，另一套场景）
```java
import java.io.IOException;
import java.nio.file.*;
import java.nio.file.attribute.BasicFileAttributes;
import java.util.concurrent.atomic.AtomicLong;

public class WalkDemo {
    public static void main(String[] args) throws IOException {
        AtomicLong bytes = new AtomicLong();
        Files.walkFileTree(Paths.get("."), new SimpleFileVisitor<>() {
            @Override
            public FileVisitResult visitFile(Path file, BasicFileAttributes attrs) {
                bytes.addAndGet(attrs.size());
                return FileVisitResult.CONTINUE;
            }

            @Override
            public FileVisitResult visitFileFailed(Path file, IOException e) {
                System.out.println("  跳过：" + file + "（" + e.getClass().getSimpleName() + "）");
                return FileVisitResult.CONTINUE;
            }
        });
        System.out.println("  当前目录总字节：" + bytes.get());
    }
}
```

**课后练习题**
1. 完整实现遍历统计器（含扩展名分组与最大文件），对项目某真实目录运行并输出报告。

### 实操 16-02 对象序列化存取

**知识点注释**
- 【题目要求】实现对象存取：可序列化类（员工：姓名/工号/入职日期）-> ObjectOutputStream 写文件 -> ObjectInputStream 读回并校验一致；演示 serialVersionUID 不匹配的 InvalidClassException（改类结构后用旧文件读）；演示 transient 字段（密码）不序列化。
- 【考核点】Serializable 接口、serialVersionUID 作用、transient、对象流关闭顺序、版本兼容。
- 【易错点】忘记 serialVersionUID（编译器自动生成，类一改就失效）；transient 后反序列化为默认值未处理；静态字段不会被序列化的误解。
- 【提示】写两个版本类（V1/V2 不同 UID）演示异常比讲十遍都清楚。

**示例代码**（技术示范：transient，另一套场景）
```java
import java.io.*;

public class TransientDemo {
    static class Token implements Serializable {
        private static final long serialVersionUID = 1L;
        String user;
        transient String secret;       // 不序列化

        Token(String user, String secret) {
            this.user = user;
            this.secret = secret;
        }
    }

    public static void main(String[] args) throws Exception {
        File f = File.createTempFile("tok", ".bin");
        try (ObjectOutputStream out = new ObjectOutputStream(new FileOutputStream(f))) {
            out.writeObject(new Token("u1", "s3cret"));
        }
        try (ObjectInputStream in = new ObjectInputStream(new FileInputStream(f))) {
            Token t = (Token) in.readObject();
            System.out.printf("  user=%s secret=%s（transient 读回为 %s）%n",
                    t.user, t.secret, t.secret);
        }
        f.deleteOnExit();
    }
}
```

**课后练习题**
1. 实现员工存取完整版（含日期字段与一致性校验），并演示 UID 不匹配异常。
2. 实现"transient 字段的反序列化恢复"（readObject 定制），让 secret 从安全源重建。
3. 思考题：为什么生产环境更推荐 JSON/Protobuf 而不是 Java 原生序列化？从安全（36 章）与跨语言两个角度分析。

### 实操 17-01 线程安全转账

**知识点注释**
- 【题目要求】实现账户类（余额）与转账方法：先写"无同步"版本，10 线程各转账 100 次 × 100 分，验证总账不平（丢失更新）；再用 synchronized（或 ReentrantLock）修复，验证总账恒等；对比两版吞吐。
- 【考核点】竞态条件与丢失更新、临界区设计（锁粒度：锁单账户 vs 锁两个账户的顺序）、死锁预防（按固定顺序加锁）、synchronized vs Lock。
- 【易错点】只锁"扣款方"不锁"入账方"；两账户转账用嵌套锁无序（死锁）；把 check-then-act（余额判断）留在锁外。
- 【提示】修复版用"账户对按 id 排序后加锁"或单锁全局账户表——两种都实现并对比锁粒度。

**示例代码**（技术示范：丢失更新，另一套场景）
```java
public class LostUpdateDemo {
    static int counter = 0;

    static void unsafe() throws Exception {
        counter = 0;
        Thread[] ts = new Thread[10];
        for (int i = 0; i < ts.length; i++) {
            ts[i] = new Thread(() -> {
                for (int j = 0; j < 1000; j++) {
                    counter++;          // 读-改-写 非原子
                }
            });
            ts[i].start();
        }
        for (Thread t : ts) {
            t.join();
        }
        System.out.printf("  期望 10000，实际 %d（丢失更新）%n", counter);
    }

    public static void main(String[] args) throws Exception {
        unsafe();
    }
}
```

**课后练习题**
1. 完整实现转账两版：无同步（复现总账不平）与修复版（总账恒等），各输出证据。
2. 实现"按 id 排序加锁"防死锁，构造两线程交叉转账的死锁场景并对比修复前后。

### 实操 17-02 线程池参数调优

**知识点注释**
- 【题目要求】实现线程池对比实验：IO 型任务（sleep 100ms）分别用核心数池、核数×2 池、虚拟线程跑 200 任务，记录吞吐与队列峰值；再演示拒绝策略差异（Abort/CallerRuns/Discard）在队列满时的行为；输出调优建议表。
- 【考核点】线程池七参数、IO/CPU 任务的池大小公式、拒绝策略行为差异、压测方法。
- 【易错点】IO 任务用核数池（严重欠并发）；无界队列掩盖背压（内存风险）；拒绝策略选 Discard 无日志（静默丢任务）。
- 【提示】队列峰值用自定义 LinkedBlockingQueue 记录 size 峰值；三种拒绝策略各跑一次对比。

**示例代码**（技术示范：拒绝策略，另一套场景）
```java
import java.util.concurrent.*;

public class RejectDemo {
    public static void main(String[] args) throws Exception {
        try (ExecutorService pool = new ThreadPoolExecutor(1, 1, 0, TimeUnit.SECONDS,
                new SynchronousQueue<>(), new ThreadPoolExecutor.CallerRunsPolicy())) {
            for (int i = 0; i < 4; i++) {
                final int id = i;
                pool.submit(() -> {
                    System.out.println("  执行 " + id + "（线程 " + Thread.currentThread().getName() + "）");
                    return null;
                });
            }
        }
        System.out.println("  CallerRuns：提交者线程亲自执行 -> 天然背压，任务不丢");
    }
}
```

**课后练习题**
1. 完整实现三池对比实验（含队列峰值统计），输出调优建议表并标注每种池的适用负载。
2. 对比三种拒绝策略在同一过载场景下的任务丢失率与提交线程阻塞时间。

### 实操 18-01 TCP Echo 与连接管理

**知识点注释**

- 【考核点】ServerSocket/Socket API、TCP 无消息边界（粘包半包）、按分隔符/长度头拆包、连接生命周期。
- 【易错点】假设一次 read 收到完整消息；服务端单线程处理（阻塞其他客户端）；忘记 flush（数据滞留缓冲）。
- 【提示】协议设计两种方案：分隔符（\n）与长度头（4 字节 int）——实现分隔符版，长度头版留练习。

**示例代码**（技术示范：Socket 读写，另一套场景）
```java
import java.io.*;
import java.net.ServerSocket;
import java.net.Socket;

public class EchoDemo {
    public static void main(String[] args) throws Exception {
        try (ServerSocket server = new ServerSocket(0)) {
            int port = server.getLocalPort();
            Thread serverThread = new Thread(() -> {
                try (Socket conn = server.accept();
                     BufferedReader in = new BufferedReader(
                             new InputStreamReader(conn.getInputStream()));
                     PrintWriter out = new PrintWriter(conn.getOutputStream(), true)) {
                    String line;
                    while ((line = in.readLine()) != null) {
                        out.println("echo:" + line);
                    }
                } catch (IOException ignored) {
                }
            });
            serverThread.start();
            try (Socket client = new Socket("127.0.0.1", port);
                 PrintWriter out = new PrintWriter(client.getOutputStream(), true);
                 BufferedReader in = new BufferedReader(
                         new InputStreamReader(client.getInputStream()))) {
                for (int i = 0; i < 3; i++) {
                    out.println("msg-" + i);
                    System.out.println("  收到：" + in.readLine());
                }
            }
            serverThread.join();
        }
    }
}
```

### 实操 19-01 注解扫描与迷你路由

**知识点注释**
- 【题目要求】定义注解 `@Route(path)` 与 `@Method(GET/POST)`；写三个带注解的处理类方法；实现"扫描器"：遍历类的方法（getDeclaredMethods），读取注解构建路由表（path -> Method 实例）；实现"分发器"：按 path+method 反射调用（invoke）并返回结果；模拟 404 与 405 两种未命中。
- 【考核点】自定义注解（@Retention RUNTIME/@Target）、反射读取注解、Method.invoke、路由表设计、404/405 语义。
- 【易错点】Retention 写成 SOURCE（运行时拿不到）；invoke 忘记 setAccessible（私有方法）；路由匹配用前缀 contains（应精确或分段匹配）。
- 【提示】路由表 key 用 "GET /users" 组合键；分发器演示参数注入（简单类型从模拟请求取值）。

**示例代码**（技术示范：注解读取，另一套场景）
```java
import java.lang.annotation.*;
import java.lang.reflect.Method;

public class AnnoScanDemo {
    @Retention(RetentionPolicy.RUNTIME)
    @Target(ElementType.METHOD)
    @interface Job {
        String value();
    }

    static class Tasks {
        @Job("backup")
        void doBackup() {
            System.out.println("  执行备份");
        }

        @Job("cleanup")
        void doCleanup() {
            System.out.println("  执行清理");
        }
    }

    public static void main(String[] args) throws Exception {
        Tasks tasks = new Tasks();
        for (Method m : Tasks.class.getDeclaredMethods()) {
            Job job = m.getAnnotation(Job.class);
            if (job != null && job.value().equals("cleanup")) {
                m.invoke(tasks);
            }
        }
    }
}
```

**课后练习题**
1. 实现完整迷你路由（扫描表 + 分发器 + 404/405），用三个路由演示命中与未命中。
2. 支持路径参数（/users/{id}），实现参数注入 invoke（简单类型转换）。
3. 思考题：为什么 Spring MVC 的 @RequestMapping 本质上就是本课的放大版？从"注解即元数据、框架即扫描器+分发器"的结构分析。

### 实操 19-02 依赖注入容器

**知识点注释**

import java.util.HashMap;
import java.util.Map;

public class SingletonDemo {
    static final Map<Class<?>, Object> cache = new HashMap<>();

    static <T> T get(Class<T> cls) throws Exception {
        Object o = cache.get(cls);
        if (o == null) {
            o = cls.getDeclaredConstructor().newInstance();
            cache.put(cls, o);
        }
        return cls.cast(o);
    }

    static class Config {
    }

    public static void main(String[] args) throws Exception {
        Config a = get(Config.class);
        Config b = get(Config.class);
        System.out.println("  单例验证（同一实例）：" + (a == b));
    }
}
