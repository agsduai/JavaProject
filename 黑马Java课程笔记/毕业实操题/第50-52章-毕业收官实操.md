## 第50章 响应式编程与虚拟线程

### 实操 50-01 虚拟线程扇出聚合

**知识点注释**
- 【题目要求】实现聚合网关虚拟线程版：4 个下游（不同耗时与可失败标记）并行调用，每下游独立 Semaphore 限流，总超时预算分级（关键 400ms/非关键 200ms），非关键超时返回占位数据（整体不失败），输出合并结果、降级清单与总耗时；与串行实现对比耗时。
- 【考核点】虚拟线程扇出、每下游限流、分级超时预算、降级合并语义（44-08/48-07 思想落地）。
- 【易错点】Future.get 无超时（慢下游拖死整批）；取消不传播（幽灵任务）；关键与非关键混用同一预算。
- 【提示】先并行提交全部任务，再按各自预算 get；超时的非关键任务 cancel(true) 后合并占位。

**示例代码**（技术示范：分级 get，另一套场景）
```java
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.Future;
import java.util.concurrent.TimeUnit;

public class BudgetGetDemo {
    public static void main(String[] args) throws Exception {
        try (ExecutorService pool = Executors.newVirtualThreadPerTaskExecutor()) {
            Future<String> fast = pool.submit(() -> "fast-ok");
            Future<String> slow = pool.submit(() -> {
                Thread.sleep(800);
                return "slow-ok";
            });
            String a = fast.get(100, TimeUnit.MILLISECONDS);
            String b;
            try {
                b = slow.get(100, TimeUnit.MILLISECONDS);
            } catch (Exception e) {
                b = "placeholder";
                slow.cancel(true);
            }
            System.out.printf("  合并：%s / %s%n", a, b);
        }
    }
}
```

**课后练习题**
1. 实现完整聚合网关（4 下游 + 限流 + 分级预算 + 降级合并），压测对比串行/虚拟线程两版的耗时与成功率。
2. 加入“取消传播”：模拟用户断开（取消总任务），验证全部下游任务被取消且无幽灵计算。
3. 思考题：为什么聚合网关是并发模型试金石？从扇出数、延迟方差、失败语义三个维度对比虚拟线程与响应式。

### 实操 50-02 Pinning 排查与修复

**知识点注释**
- 【题目要求】构造 pinning 现场：10 个虚拟线程在 synchronized 方法内 sleep（模拟持锁做 IO），观察吞吐坍塌（实际并发退化为 1）；改用 ReentrantLock 修复后对比；输出“修复前/修复后”的完成耗时与结论（对应 JFR jdk.VirtualThreadPinned 事件的代码层复现）。
- 【考核点】pinning 成因（synchronized 内阻塞不卸载）、载体耗尽的表现（吞吐退化为串行）、修复姿势（ReentrantLock）与验证方法。
- 【易错点】只改锁不验证（修没修好要压测）；短临界区也全局替换（改动面失控）；误判（把下游慢当 pinning）。
- 【提示】对照组实验设计：同任务量，仅锁实现不同——控制变量归因。

**示例代码**（技术示范：对照组，另一套场景）
```java
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

public class AbTestDemo {
    static long shared = 0;
    static final Object monitor = new Object();

    static void workSync() {
        synchronized (monitor) {
            shared++;                  // 短临界区：此形态安全
        }
    }

    public static void main(String[] args) throws Exception {
        try (ExecutorService pool = Executors.newVirtualThreadPerTaskExecutor()) {
            for (int i = 0; i < 8; i++) {
                pool.submit(() -> {
                    for (int j = 0; j < 1000; j++) {
                        workSync();
                    }
                    return null;
                });
            }
        }
        System.out.println("  短临界区 synchronized 在虚拟线程下可接受；长阻塞才必须换 ReentrantLock");
        System.out.println("  计数结果：" + shared);
    }
}
```

**课后练习题**
1. 完整复现 pinning：synchronized 内 sleep 200ms × 10 任务，记录耗时；换 ReentrantLock 对比并写结论。
2. 用 JFR（jdk.VirtualThreadPinned）采集你的复现程序，验证事件栈与代码位置对应。
3. 思考题：为什么“短临界区 synchronized 可以保留”？从临界区时长与载体占用概率的关系量化判断标准。

### 实操 51-01 三层幂等支付链路

**知识点注释**
- 【题目要求】实现迷你支付链路：创建支付单（orderId 幂等，重复请求返回同一单）-> 渠道回调处理（notifyId 去重 + channelTxId 唯一约束 + 状态机只进不退）-> 记账事件（outbox 模拟）；并发测试：50 线程重复回调同一通知，验证“状态只转移一次、记账只有一条、全部应答 success”。
- 【考核点】三层幂等键、状态机 CAS、并发去重（putIfAbsent/唯一约束）、回调应答语义。
- 【易错点】回调处理在幂等检查前（验签与去重顺序）；状态更新无乐观锁（双成功）；记账与状态不同事务（不一致）。
- 【提示】幂等去重表用 putIfAbsent 语义；状态机转移与记账放进同一个 synchronized/事务边界。

**示例代码**（技术示范：putIfAbsent 去重，另一套场景）
```java
import java.util.concurrent.ConcurrentHashMap;

public class DedupeDemo {
    static final ConcurrentHashMap<String, String> seen = new ConcurrentHashMap<>();

    static String first(String key, String value) {
        return seen.putIfAbsent(key, value);   // 首次返回 null，重复返回旧值
    }

    public static void main(String[] args) {
        System.out.println("  首次：" + first("n-1", "processed"));
        System.out.println("  重复：" + first("n-1", "processed-again") + "（拿到首次结果，忽略新值）");
    }
}
```

**课后练习题**
1. 实现完整支付链路（三层幂等 + 状态机 + outbox），50 线程并发回调测试输出“记账条数=1”的证据。
2. 构造“回调与关单竞态”（51-03），验证状态机裁决与差异单（已关单但有款 -> 自动退款）路径。
3. 思考题：为什么三层幂等键缺一不可？分别构造“缺业务键/缺渠道号/缺通知 ID”时的重复事故场景。

### 实操 51-02 复式记账分录器

**知识点注释**
- 【题目要求】实现账务分录器：账户表（渠道清算户/商户应付户/平台收入户）+ 分录生成（支付/退款/手续费三类业务的借贷分录）+ 试算平衡校验（任一时刻借方合计 = 贷方合计）+ 余额视图（每账户余额 = 分录合计）；注入“方向搞反”的分录验证试算失衡检测。
- 【考核点】复式记账（有借必有贷）、账户余额推导、试算平衡作为硬校验、退款反向冲正。
- 【易错点】单式记账（无法平衡校验）；分录与业务事件不同事务；退款方向搞反（试算失衡是唯一能当场发现的手段）。
- 【提示】分录生成器按业务类型模板化（支付：借渠道清算/贷商户+收入；退款：反向）；平衡校验放在每次分录落库后。

**示例代码**（技术示范：平衡校验，另一套场景）
```java
import java.util.List;

public class BalanceDemo {
    record Entry(String account, boolean debit, long cents) {
    }

    static boolean balanced(List<Entry> entries) {
        long d = entries.stream().filter(e -> e.debit()).mapToLong(e -> e.cents()).sum();
        long c = entries.stream().filter(e -> !e.debit()).mapToLong(e -> e.cents()).sum();
        return d == c;
    }

    public static void main(String[] args) {
        var ok = List.of(new Entry("A", true, 100), new Entry("B", false, 100));
        var bad = List.of(new Entry("A", true, 100), new Entry("B", false, 90));
        System.out.printf("  正常分录平衡：%b%n", balanced(ok));
        System.out.printf("  方向搞反/金额错 平衡：%b（当场发现）%n", balanced(bad));
    }
}
```

**课后练习题**
1. 实现分录器完整版（三类业务模板 + 平衡校验 + 账户余额视图），注入反向分录验证失衡检测。
2. 实现“业务流水 vs 账务分录”的第二层对账：故意丢一条分录，定位缺失凭证号。
3. 思考题：为什么复式记账“自带纠错检测”？从借贷平衡的数学约束推导它能当场发现哪几类错误、发现不了哪几类。

### 实操 52-01 容量估算器

**知识点注释**
- 【题目要求】实现容量估算器：输入（日活、人均请求数、集中时段占比、峰值因子、读写比、平均输出 token、单卡吞吐、目标利用率、冗余系数），输出峰值 QPS、读写拆分、token 需求、所需卡数与目标利用率（52-01 公式链的可执行版）；支持“场景预设”（日常/大促）对比。
- 【考核点】估算公式链（52-06/48-06）、非功能需求量化、利用率悬崖意识（60~70% 目标）、冗余依据。
- 【易错点】QPS 与 token 混算；峰值因子拍脑袋无依据；利用率按 90% 规划（排队悬崖）。
- 【提示】输出表每行带“推导说明”字段——估算器是 ADR 的数字来源（52-02）。

**示例代码**（技术示范：公式链，另一套场景）
```java
public class FormulaDemo {
    public static void main(String[] args) {
        long dau = 1_000_000;
        double reqPerUser = 10;
        double slot = 0.2;
        double peak = 3.0;
        long avgQps = Math.round(dau * reqPerUser / (86400 * slot));
        long peakQps = Math.round(avgQps * peak);
        System.out.printf("  平均 QPS=%d  峰值=%d（推导：日活×人均÷时段×因子）%n", avgQps, peakQps);
    }
}
```

**课后练习题**
1. 实现完整估算器：双场景对比输出（日常/大促），并生成可直接贴进 ADR 的表格文本。
2. 加入“反向校验”：由成本上限反推可支撑的峰值 QPS，验证商业模式与架构的匹配。
3. 思考题：为什么利用率目标定 60~70% 而不是 90%？用排队延迟的非线性推导目标值的选择。

### 实操 52-02 ADR 生成器

**知识点注释**
- 【题目要求】实现 ADR 生成器：决策输入（标题/背景/选项列表/选中项/负面后果/回顾条件）-> 校验（选项 ≥2、负面后果非空、回顾条件存在）-> 输出格式化 ADR 文档（Markdown）+ 决策索引（追加到 ADR 索引表）；输入不合规时输出整改提示（52-02 纪律的自动化）。
- 【考核点】ADR 结构（背景/选项/决策/后果）、纪律校验（选项数/负面后果）、决策索引与历史保留。
- 【易错点】只有结论没有选项；负面后果空泛（“可能有风险”）；索引不更新（文档孤岛）。
- 【提示】生成器输出后自动追加索引行（编号/标题/状态/日期）——决策资产化管理。

**示例代码**（技术示范：文档校验，另一套场景）
```java
import java.util.ArrayList;
import java.util.List;

public class DocGateDemo {
    static List<String> validate(String title, List<String> options, String negative) {
        List<String> errors = new ArrayList<>();
        if (title == null || title.isBlank()) {
            errors.add("缺少标题");
        }
        if (options.size() < 2) {
            errors.add("选项少于 2 个：单一选项不需要 ADR");
        }
        if (negative == null || negative.length() < 20) {
            errors.add("负面后果过于空泛，请写具体风险");
        }
        return errors;
    }

    public static void main(String[] args) {
        System.out.println(validate("并发模型选型",
                List.of("虚拟线程", "WebFlux"), "需排查 pinning，连接池将成为新瓶颈"));
        System.out.println(validate("并发模型选型", List.of("虚拟线程"), "有风险"));
    }
}
```

**课后练习题**
1. 实现 ADR 生成器完整版：含校验、Markdown 渲染、索引追加，生成你系统的三个真实决策文档。
2. 实现“决策取代”：新 ADR 生成时自动把被取代的旧 ADR 状态改为 superseded（历史不删）。
3. 思考题：为什么 ADR 校验器能长期保住决策质量？从“纪律自动化”与人工评审的互补关系分析。
