# 第82章 灰度发布与实验平台设计

代码写完、测试通过，并不等于可以一次推给全部用户：新版本可能只在某个机型上崩、只对某个地域慢、只让某类用户的转化率掉。灰度发布解决「怎么安全地放量」，AB 实验解决「改了到底有没有用」，两者共用同一套底座：染色、分流、指标、判定。本章按「发布形态选型 → 流量染色透传 → 分流规则引擎 → 稳定分流 → 放量阶梯与门禁 → 数据兼容 → 指标对比与自动回滚 → 实验分层正交 → 样本量与显著性 → 实验陷阱 → 大促灰度案例」的顺序讲。所有示例仍是纯 JDK：四种发布形态的成本与回滚耗时对比、染色丢失的链路复现、规则引擎求值、hash 稳定分流与嵌套性验证、阶梯放量门禁、expand-contract 三阶段读写矩阵、绝对/相对双阈值回滚判定、分层正交的交叉表校验、最小样本量与两比例 z 检验、SRM 卡方检验、多重比较与新奇效应全部真实运行。

### 82-01 四种发布形态：蓝绿、金丝雀、滚动、功能开关

**知识点**
- **蓝绿部署**：**两套完整环境，切流量在网关做**——**回滚就是切回来（秒级）**，但**资源翻倍**，且**数据库是共享的，回滚救不了脏数据**。
- **金丝雀（灰度）**：**新版本只接一小部分流量（1%~10%），观察后再扩**——**爆炸半径可控**，是**互联网公司的主流选择**，代价是**要能按用户/请求分流**。
- **滚动发布**：**逐台替换实例**——**不额外占资源**，但**新旧版本会同时在线一段时间**，**回滚要把整个滚动过程倒着走一遍（分钟级）**，且**期间接口必须双向兼容**。
- **功能开关（Feature Flag）**：**代码先全量上线，行为由开关控制**——**回滚是改一个配置（亚秒级）**，但**开关会烂在代码里**，必须有**开关生命周期管理与清理机制**。
- **回滚耗时不是一个数，是四段之和**：**发现时间 + 决策时间 + 生效时间 + 数据修复时间**——**前两段是人的问题，后两段才是技术问题**，很多团队只优化了「生效时间」。
- 易错点：把「能回滚代码」当成「能回滚」；蓝绿共享库却以为切回去就干净了；滚动发布期间改了接口字段（旧实例解析不了）；开关加了不删（一年后没人敢动）。

**示例代码**
```java
import java.util.ArrayList;
import java.util.List;

public class ReleaseStrategies {
    // 一次发布要付出的代价，全部量化成数字
    record Strategy(String name, int extraInstancePct, int rollbackEffectSec,
                    int blastRadiusPct, boolean needsRouting) {
    }

    // 回滚总耗时 = 发现 + 决策 + 生效 + 数据修复
    record Timeline(int detectSec, int decideSec, int effectSec, int repairSec) {
        int total() {
            return detectSec + decideSec + effectSec + repairSec;
        }
    }

    static void table(List<Strategy> list) {
        System.out.printf("%-12s %-10s %-10s %-10s %s%n",
                "形态", "额外资源", "生效耗时", "爆炸半径", "需要分流能力");
        for (Strategy s : list) {
            System.out.printf("%-12s %-10s %-10s %-10s %s%n",
                    s.name(), s.extraInstancePct() + "%",
                    s.rollbackEffectSec() + "s",
                    s.blastRadiusPct() + "%",
                    s.needsRouting() ? "是" : "否");
        }
    }

    static void timeline(String name, Timeline t) {
        System.out.printf("  %-10s 发现 %3ds + 决策 %3ds + 生效 %3ds + 数据修复 %3ds = %4ds（%.1f 分钟）%n",
                name, t.detectSec(), t.decideSec(), t.effectSec(), t.repairSec(),
                t.total(), t.total() / 60.0);
    }

    public static void main(String[] args) {
        List<Strategy> list = new ArrayList<>();
        list.add(new Strategy("蓝绿", 100, 5, 100, true));
        list.add(new Strategy("金丝雀", 10, 5, 10, true));
        list.add(new Strategy("滚动", 0, 300, 60, false));
        list.add(new Strategy("功能开关", 0, 1, 100, true));
        table(list);

        System.out.println();
        System.out.println("【回滚耗时拆解】同一个「价格算错了」的事故，四种形态各自多久恢复");
        timeline("蓝绿", new Timeline(120, 60, 5, 600));
        timeline("金丝雀", new Timeline(120, 60, 5, 0));
        timeline("滚动", new Timeline(120, 60, 300, 600));
        timeline("功能开关", new Timeline(120, 60, 1, 0));

        System.out.println();
        System.out.println("【读结论】");
        System.out.println("  1. 金丝雀的爆炸半径只有 10%，所以「数据修复」可以是 0——脏数据只影响了 10% 用户");
        System.out.println("  2. 蓝绿和功能开关都是 100% 爆炸半径，代码切回去了，已经写错的订单还得人工修");
        System.out.println("  3. 滚动发布的 300s 生效耗时最容易被忽略：它要倒着滚一遍");
        System.out.println("  4. 四种形态的「发现 120s + 决策 60s」完全一样——这段是人的流程，不换架构就优化不掉");

        System.out.println();
        System.out.println("【选型】");
        System.out.println("  改动影响资金/库存  -> 金丝雀 + 功能开关（双重保险）");
        System.out.println("  纯前端/展示层改版  -> 功能开关（最快回滚）");
        System.out.println("  无状态服务扩容     -> 滚动（最省资源）");
        System.out.println("  数据库大版本升级   -> 蓝绿 + 双写（唯一能整体切换的方案）");
    }
}
```

### 82-02 流量染色与全链路透传

**知识点**
- **染色的本质**：**给一次请求打上「它属于哪个版本/哪个实验组」的标记**，**后续每一跳都要带着它**，否则**下游不知道自己该走哪条路**。
- **染色必须全链路透传**：**网关打标 → RPC 透传 → 线程池透传 → 消息队列透传 → 数据库/缓存 key 隔离**——**任何一跳丢失，下游就退化成基线**。
- **ThreadLocal 是默认做法，也是最容易丢的地方**：**异步任务、线程池复用、`CompletableFuture`、定时任务**都会丢——**必须显式装饰（wrap Runnable/Callable）或用支持透传的实现**。
- **染色的三种载体**：**HTTP Header（跨进程）**、**RPC attachment（跨服务）**、**ThreadLocal（进程内）**——**跨进程靠协议，进程内靠上下文**。
- **灰度数据也要隔离**：**缓存 key 加版本前缀、消息队列加 tag、数据库双写**——**否则灰度写的数据会被基线读到**，**这是比代码 bug 更难查的事故**。
- 易错点：只在入口打标不做透传；用 `@Async` 就丢了上下文；线程池里复用旧标记；缓存不隔离导致灰度数据污染基线。

**示例代码**
```java
import java.util.HashMap;
import java.util.Map;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.TimeUnit;

public class TrafficTagging {
    // ---------- 进程内上下文 ----------
    static final ThreadLocal<String> TAG = new ThreadLocal<>();

    static void setTag(String t) {
        TAG.set(t);
    }

    static String tag() {
        return TAG.get();
    }

    static void clear() {
        TAG.remove();
    }

    // 下游服务：有 tag 走灰度，没 tag 走基线
    static String callDownstream(String where) {
        String t = tag();
        String route = (t == null) ? "基线" : ("灰度-" + t);
        System.out.printf("    %-22s 收到 tag=%-6s -> 走 %s%n", where, String.valueOf(t), route);
        return route;
    }

    // 手动装饰：把当前线程的 tag 捕获下来，交给线程池执行
    static Runnable wrap(Runnable task) {
        String captured = tag();
        return () -> {
            String old = tag();
            setTag(captured);
            try {
                task.run();
            } finally {
                if (old == null) {
                    clear();
                } else {
                    setTag(old);
                }
            }
        };
    }

    public static void main(String[] args) throws Exception {
        ExecutorService pool = Executors.newFixedThreadPool(2);

        System.out.println("【场景1】同步调用链：网关打标，服务A、服务B 依次调用");
        setTag("gray-v2");
        callDownstream("服务A(同步)");
        callDownstream("服务B(同步)");
        clear();

        System.out.println();
        System.out.println("【场景2】服务A 把活丢给线程池（未装饰）：ThreadLocal 丢失");
        setTag("gray-v2");
        pool.submit(() -> callDownstream("服务B(线程池-裸提交)")).get();
        clear();

        System.out.println();
        System.out.println("【场景3】服务A 用 wrap 装饰后再提交：tag 被捕获并还原");
        setTag("gray-v2");
        pool.submit(wrap(() -> callDownstream("服务B(线程池-wrap)"))).get();
        clear();

        System.out.println();
        System.out.println("【场景4】线程池复用：上一个任务留下的脏标记污染了下一个基线任务");
        // 必须固定同一个线程才能复现「线程复用」，多线程池可能把两个任务分到不同线程
        ExecutorService single = Executors.newSingleThreadExecutor();
        single.submit(() -> {
            setTag("gray-v2");                     // 故意不清理
            callDownstream("服务B(不清理)");
        }).get();
        single.submit(() -> callDownstream("服务C(本该走基线)")).get();
        single.shutdown();
        single.awaitTermination(2, TimeUnit.SECONDS);

        System.out.println();
        System.out.println("【场景5】跨进程：tag 靠 Header 传递，每跳都要显式带上");
        Map<String, String> headers = new HashMap<>();
        headers.put("x-gray-tag", "gray-v2");
        System.out.println("    网关写入 Header: " + headers);
        System.out.println("    服务A 透传 Header: " + headers.get("x-gray-tag"));
        System.out.println("    服务B 忘了透传      : null -> 走基线（染色断在这里）");

        pool.shutdown();
        pool.awaitTermination(2, TimeUnit.SECONDS);

        System.out.println();
        System.out.println("【结论】染色不是「打一个标」就完了，是「每一跳都不能丢」：");
        System.out.println("  同步调用靠 ThreadLocal，异步必须 wrap，跨进程靠 Header/attachment，");
        System.out.println("  线程池用完必须 clear——否则脏标记会让基线用户走进灰度。");
    }
}
```

**课后练习**

2. 用 `CompletableFuture.supplyAsync` 替代 `pool.submit` 复现场景2，再加一层自定义 Executor 修好它。

### 82-03 分流规则引擎与稳定分桶

**知识点**
- **分流规则要可配置、可组合**：**白名单（指定用户）→ 地域/机型（定向放量）→ 比例（随机放量）**——**按优先级短路求值，命中即返回**。
- **比例分流必须稳定**：**同一个用户在 5% 阶段进了灰度，扩到 10% 时必须还在灰度**——**靠「分桶值固定 + 阈值单调递增」实现**，**不能每次请求重新随机**。
- **稳定分桶的做法**：**`bucket = hash(userId) % 10000`**，**5% 就是 `bucket < 500`，10% 就是 `bucket < 1000`**——**阈值变大只增不减，天然嵌套**。
- **hash 必须用稳定算法**：**不能用 `String.hashCode()` 之外的随机源，也不能加时间戳/随机数**——**同一用户在任何机器、任何时间算出来必须是同一个值**。
- **嵌套性要能验证**：**`5% 的用户集合 ⊆ 10% 的用户集合 ⊆ 25% 的用户集合`**——**这条不成立，实验数据就废了（同一用户在不同阶段换了组）**。
- 易错点：每次请求 `Math.random() < 0.05`（用户反复横跳）；扩容后取模的模数变了（`% 100` 改 `% 1000`，老用户全被打散）；白名单用户被比例规则覆盖。

**示例代码**
```java
import java.util.ArrayList;
import java.util.HashSet;
import java.util.List;
import java.util.Random;
import java.util.Set;

public class RoutingRuleEngine {
    // ---------- 请求上下文 ----------
    record Ctx(String userId, String region) {
    }

    // ---------- 规则：命中就短路 ----------
    interface Rule {
        String name();

        boolean match(Ctx c);
    }

    record WhitelistRule(Set<String> users) implements Rule {
        public String name() {
            return "白名单";
        }

        public boolean match(Ctx c) {
            return users.contains(c.userId());
        }
    }

    record RegionRule(Set<String> regions) implements Rule {
        public String name() {
            return "地域";
        }

        public boolean match(Ctx c) {
            return regions.contains(c.region());
        }
    }

    // 比例规则：bucket 固定，阈值可变 -> 天然嵌套
    record PercentRule(int permille) implements Rule {
        public String name() {
            return "比例" + permille / 10.0 + "%";
        }

        public boolean match(Ctx c) {
            return bucket(c.userId()) < permille * 10;
        }
    }

    // 稳定分桶：同一 userId 永远落在同一个桶
    static int bucket(String userId) {
        int h = 0x811C9DC5;                        // FNV-1a 32 位
        for (int i = 0; i < userId.length(); i++) {
            h ^= userId.charAt(i);
            h *= 0x01000193;
        }
        return Math.floorMod(h, 10000);
    }

    static class Engine {
        final List<Rule> rules = new ArrayList<>();

        Engine add(Rule r) {
            rules.add(r);
            return this;
        }

        String route(Ctx c) {
            for (Rule r : rules) {
                if (r.match(c)) {
                    return "灰度(" + r.name() + ")";
                }
            }
            return "基线";
        }
    }

    // 不稳定的对照实现：每次请求重新随机（固定种子，保证每次运行数字一致）
    static final Random RND = new Random(20261120L);

    static String unstableRoute(Ctx c, double pct) {
        return RND.nextDouble() < pct ? "灰度" : "基线";
    }

    public static void main(String[] args) {
        Set<String> white = Set.of("u1001", "u1002");
        Set<String> regions = Set.of("杭州", "深圳");
        Engine e5 = new Engine().add(new WhitelistRule(white)).add(new RegionRule(regions))
                .add(new PercentRule(50));
        Engine e10 = new Engine().add(new WhitelistRule(white)).add(new RegionRule(regions))
                .add(new PercentRule(100));

        System.out.println("【规则优先级】命中白名单就直接进灰度，不再看地域和比例");
        System.out.println("  u1001(上海) -> " + e5.route(new Ctx("u1001", "上海")));
        System.out.println("  u2001(杭州) -> " + e5.route(new Ctx("u2001", "杭州")));
        System.out.println("  u3001(北京) -> " + e5.route(new Ctx("u3001", "北京")));

        System.out.println();
        System.out.println("【嵌套性】5% 的用户集合必须被 10% 完整包含");
        Set<String> g5 = new HashSet<>();
        Set<String> g10 = new HashSet<>();
        for (int i = 0; i < 100_000; i++) {
            Ctx c = new Ctx("u" + i, "北京");
            if (e5.route(c).startsWith("灰度")) {
                g5.add(c.userId());
            }
            if (e10.route(c).startsWith("灰度")) {
                g10.add(c.userId());
            }
        }
        Set<String> leak = new HashSet<>(g5);
        leak.removeAll(g10);
        System.out.printf("  5%% 组 %d 人，10%% 组 %d 人，5%% 里不在 10%% 的：%d 人%n",
                g5.size(), g10.size(), leak.size());
        System.out.printf("  实际比例：5%% 档 %.2f%%，10%% 档 %.2f%%（各 10 万人抽样）%n",
                g5.size() / 1000.0, g10.size() / 1000.0);

        System.out.println();
        System.out.println("【对照】每次请求重新随机的「不稳定分流」：同一用户 20 次请求里换了几次组");
        Ctx fixed = new Ctx("u777", "北京");
        int flips = 0;
        String last = unstableRoute(fixed, 0.10);
        for (int i = 1; i < 20; i++) {
            String now = unstableRoute(fixed, 0.10);
            if (!now.equals(last)) {
                flips++;
                last = now;
            }
        }
        System.out.printf("  不稳定分流：20 次请求换组 %d 次%n", flips);
        int stableFlips = 0;
        last = e10.route(fixed);
        for (int i = 1; i < 20; i++) {
            String now = e10.route(fixed);
            if (!now.equals(last)) {
                stableFlips++;
                last = now;
            }
        }
        System.out.printf("  稳定分桶  ：20 次请求换组 %d 次（bucket=%d）%n", stableFlips, bucket("u777"));

        System.out.println();
        System.out.println("【结论】比例分流的正确姿势：bucket 固定不变，只让阈值单调变大；");
        System.out.println("  这样 5% -> 10% 只是「再多放 5% 进来」，原来那 5% 一个都不会被踢出去。");
    }
}
```

### 82-04 放量阶梯与自动化门禁

**知识点**
- **放量不是「1% 没问题就上 100%」**：**1% → 5% → 25% → 50% → 100% 每一档都要停下来看**——**观察窗口内样本量不够，等于没看**。
- **门禁要三类指标同时看**：**技术指标（错误率、P99、超时率）**、**业务指标（转化率、下单量）**、**资源指标（CPU、内存、连接池）**——**只看技术指标会放过「能跑但没人买」的版本**。
- **观察窗口要够长**：**样本量 n 与「要发现的最小差异」成反比**——**想发现 0.5% 的转化率差异，1% 流量下可能要等几小时**，**所以小流量档只卡技术指标，业务指标留到大流量档再判**。
- **门禁失败要能自动停**：**不是「报警然后等人」，是「自动把流量切回上一档」**——**人从看到告警到动手平均 5~10 分钟，这段损失比自动停大得多**。
- **放量节奏要和业务节律对齐**：**别在流量高峰前 10 分钟放量**，**别在没人的凌晨放到 100% 然后早上出事**——**放量窗口本身就是个决策**。
- 易错点：1% 跑 5 分钟就上 100%；门禁阈值写死不看基线（大促期间错误率天然更高）；只卡错误率不卡延迟；失败只告警不自动回退。

**示例代码**
```java
import java.util.LinkedHashMap;
import java.util.Map;

public class RampupGate {
    // 每一档的配置：流量比例、观察窗口、最小样本量、门禁阈值
    record Stage(int pct, int windowSec, long minSamples,
                 double maxErrRate, double maxP99Ms, double minCvr) {
    }

    // 实测数据
    record Observed(long samples, double errRate, double p99Ms, double cvr) {
    }

    static final Map<Integer, Stage> STAGES = new LinkedHashMap<>();

    static {
        STAGES.put(1, new Stage(1, 600, 20_000, 0.005, 300, 0.030));
        STAGES.put(5, new Stage(5, 900, 60_000, 0.005, 300, 0.030));
        STAGES.put(25, new Stage(25, 1800, 200_000, 0.008, 350, 0.029));
        STAGES.put(50, new Stage(50, 1800, 400_000, 0.008, 350, 0.029));
        STAGES.put(100, new Stage(100, 0, 0, 0.010, 400, 0.028));
    }

    // 返回 null 表示通过，否则返回失败原因
    static String gate(Stage s, Observed o) {
        if (o.samples() < s.minSamples()) {
            return String.format("样本不足：%d < %d，观察窗口没跑满，不能判",
                    o.samples(), s.minSamples());
        }
        if (o.errRate() > s.maxErrRate()) {
            return String.format("错误率 %.3f%% > %.3f%%", o.errRate() * 100, s.maxErrRate() * 100);
        }
        if (o.p99Ms() > s.maxP99Ms()) {
            return String.format("P99 %.0fms > %.0fms", o.p99Ms(), s.maxP99Ms());
        }
        if (o.cvr() < s.minCvr()) {
            return String.format("转化率 %.2f%% < %.2f%%", o.cvr() * 100, s.minCvr() * 100);
        }
        return null;
    }

    public static void main(String[] args) {
        // 模拟一次放量：5% 档出现延迟劣化，其余档正常
        Map<Integer, Observed> actual = new LinkedHashMap<>();
        actual.put(1, new Observed(25_000, 0.0012, 240, 0.0312));
        actual.put(5, new Observed(72_000, 0.0018, 520, 0.0305));    // P99 超标
        actual.put(25, new Observed(210_000, 0.0021, 300, 0.0301));
        actual.put(50, new Observed(430_000, 0.0025, 310, 0.0298));
        actual.put(100, new Observed(900_000, 0.0028, 320, 0.0295));

        System.out.println("【放量阶梯与门禁】");
        System.out.printf("%-6s %-8s %-10s %-9s %-9s %-9s %s%n",
                "档位", "观察窗口", "样本量", "错误率", "P99", "转化率", "门禁");
        boolean stopped = false;
        for (Map.Entry<Integer, Stage> e : STAGES.entrySet()) {
            Stage s = e.getValue();
            Observed o = actual.get(e.getKey());
            String fail = gate(s, o);
            String verdict;
            if (stopped) {
                verdict = "未执行（上一档已拦下）";
            } else if (fail == null) {
                verdict = "通过";
            } else {
                verdict = "拦截 -> " + fail;
                stopped = true;
            }
            System.out.printf("%-6s %-8s %-10s %-9s %-9s %-9s %s%n",
                    s.pct() + "%", s.windowSec() + "s", o.samples(),
                    String.format("%.2f%%", o.errRate() * 100),
                    String.format("%.0fms", o.p99Ms()),
                    String.format("%.2f%%", o.cvr() * 100),
                    verdict);
        }

        System.out.println();
        System.out.println("【读结论】");
        System.out.println("  1. 5% 档 P99 520ms 超过 300ms 阈值 -> 自动停在 5%，25% 及以后都没执行");
        System.out.println("  2. 1% 档样本 2.5 万 >= 门槛 2 万，判得动；5% 档 7.2 万 >= 6 万，也判得动");
        System.out.println("  3. 两档样本都够，所以 5% 档的拦截结论可信——不是「数据太少误判」");

        System.out.println();
        System.out.println("【样本不足时的正确反应】");
        Observed early = new Observed(3_000, 0.0010, 250, 0.0310);
        System.out.println("  1% 档只跑了 3000 个样本就去看结果 -> "
                + gate(STAGES.get(1), early));

        System.out.println();
        System.out.println("【小流量档只卡技术指标的原因】");
        System.out.println("  转化率基线 3%，想发现 0.3pp 的提升（3.0% -> 3.3%），每组需要约 5.3 万样本");
        System.out.println("  1% 档 10 分钟只有 2.5 万样本，只有需求的 47% -> 业务指标在这个档位根本判不出来");
        System.out.println("  -> 所以 1%/5% 档只卡错误率与 P99，转化率留到 25% 以后");

        System.out.println();
        System.out.println("【自动停 vs 人工停】");
        System.out.println("  自动停：告警触发即切回上一档，生效 5s");
        System.out.println("  人工停：告警 -> 值班看到 -> 确认 -> 执行，平均 5~10 分钟");
        System.out.println("  5 分钟 × 5% 流量 × 2 万 QPS = 30 万次请求在错误版本上");
    }
}
```

### 82-05 发布期的数据兼容：expand-contract

**知识点**
- **滚动/灰度期间新旧版本同时在线**：**旧代码读新表结构会崩，新代码读旧数据会崩**——**所以数据库变更必须拆成「先兼容、再切换、后清理」三步**。
- **Expand（扩展）**：**加新字段/新表，新旧代码都能跑**——**新字段必须可空或有默认值**，**旧代码不认识它就当不存在**。
- **Migrate（双写/回填）**：**新代码同时写新旧两处，后台把历史数据回填**——**回填要能重跑、要限速**，**不能把库打挂**。
- **Contract（收缩）**：**确认所有实例都是新版本、所有数据都回填完，才能删旧字段**——**删早了，还没升级的实例立刻 500**。
- **三条铁律**：**加字段不删字段、改语义要加新字段、删字段要等两个发布周期**——**「两个周期」是给回滚留的余地**。
- 易错点：一个发布里同时加字段又删字段；新字段设 NOT NULL 无默认值（旧代码插入失败）；回填不限速（打挂主库）；以为「代码回滚了数据也回来了」。

**示例代码**
```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class SchemaCompat {
    enum Phase { EXPAND, MIGRATE, CONTRACT }

    // 一行数据：旧字段 price(分)，新字段 priceYuan(字符串，带两位小数)
    static class Row {
        Integer priceFen;          // 旧字段，可空
        String priceYuan;          // 新字段，可空

        Row(Integer priceFen, String priceYuan) {
            this.priceFen = priceFen;
            this.priceYuan = priceYuan;
        }
    }

    static class Table {
        final List<Row> rows = new ArrayList<>();
        Phase phase = Phase.EXPAND;
        int errors;

        // 旧代码：只认 priceFen
        void writeOld(int fen) {
            Row r = new Row(fen, null);
            if (phase == Phase.CONTRACT) {
                errors++;
                System.out.println("    [旧代码写] 失败：priceFen 字段已被删除（NPE / Unknown column）");
                return;
            }
            rows.add(r);
        }

        // 新代码：两个都写
        void writeNew(int fen) {
            String yuan = String.format("%d.%02d", fen / 100, fen % 100);
            rows.add(new Row(phase == Phase.CONTRACT ? null : fen, yuan));
        }

        // 旧代码读：优先旧字段
        String readOld(int idx) {
            Row r = rows.get(idx);
            if (r.priceFen == null) {
                errors++;
                return "<读不到 priceFen>";
            }
            return "RMB " + String.format("%.2f", r.priceFen / 100.0);
        }

        // 新代码读：优先新字段，回退旧字段（兼容未回填的数据）
        String readNew(int idx) {
            Row r = rows.get(idx);
            if (r.priceYuan != null) {
                return "RMB " + r.priceYuan;
            }
            if (r.priceFen != null) {
                return "RMB " + String.format("%.2f", r.priceFen / 100.0) + "(旧字段回退)";
            }
            return "<两个字段都空>";
        }

        int backfill() {
            int n = 0;
            for (Row r : rows) {
                if (r.priceYuan == null && r.priceFen != null) {
                    r.priceYuan = String.format("%d.%02d", r.priceFen / 100, r.priceFen % 100);
                    n++;
                }
            }
            return n;
        }
    }

    public static void main(String[] args) {
        Table t = new Table();

        System.out.println("【阶段1 EXPAND】加新字段 priceYuan（可空），旧代码照常跑");
        t.writeOld(1999);
        t.writeOld(2580);
        System.out.println("  旧代码写入 2 行，新代码读取：");
        System.out.println("    row0 -> " + t.readNew(0));
        System.out.println("    row1 -> " + t.readNew(1));

        System.out.println();
        System.out.println("【阶段2 MIGRATE】新代码双写 + 回填历史数据");
        t.phase = Phase.MIGRATE;
        t.writeNew(3999);
        int filled = t.backfill();
        System.out.println("  双写 1 行，回填历史 " + filled + " 行");
        for (int i = 0; i < t.rows.size(); i++) {
            System.out.printf("    row%d 旧代码读 %-10s 新代码读 %s%n",
                    i, t.readOld(i), t.readNew(i));
        }
        System.out.println("  -> 两个版本读出来的价格完全一致，可以开始收缩");

        System.out.println();
        System.out.println("【阶段3 CONTRACT】删除旧字段 priceFen");
        t.phase = Phase.CONTRACT;
        for (Row r : t.rows) {
            r.priceFen = null;                    // 列被 DROP，历史行的旧值也一起没了
        }
        System.out.println("  如果此时还有旧实例在线：");
        t.writeOld(1000);
        System.out.println("  旧代码读历史行：" + t.readOld(0));
        System.out.println("  新代码不受影响：" + t.readNew(0));
        System.out.printf("  -> 累计错误 %d 次；这就是为什么删字段要等所有实例都升级完%n", t.errors);

        System.out.println();
        System.out.println("【错误做法对照】一个发布里同时加新字段 + 删旧字段");
        Map<String, String> bad = new LinkedHashMap<>();
        bad.put("发布中", "旧实例还在跑，新表结构已经生效");
        bad.put("旧实例读", "SELECT priceFen -> Unknown column，接口 500");
        bad.put("回滚", "代码回滚了，但字段已经被 DROP，数据回不来");
        bad.put("正确做法", "expand -> migrate -> contract 三个发布，每步都可回滚");
        bad.forEach((k, v) -> System.out.printf("  %-8s %s%n", k, v));
    }
}
```

**课后练习**
1. 把 CONTRACT 阶段改成「先停旧实例再删字段」，重跑，验证错误次数变成 0。
2. 给 backfill 加限速（每批 100 行、批次间隔 50ms），统计 1 万行数据要回填多久。
3. 思考题：为什么「改字段语义」也要加新字段，而不是直接改旧字段的含义？从「旧代码如何解释这个值」分析。

### 82-06 指标对比与自动回滚判据

**知识点**
- **自动回滚的第一原则：判据要能抵抗噪声**——**单点抖动就回滚会造成「回滚风暴」**，**必须用「连续 N 个窗口」或「滑动窗口累计」**。
- **绝对阈值 + 相对阈值双保险**：**绝对阈值防「本来就差」**（错误率 > 1%），**相对阈值防「比基线差很多」**（错误率是基线的 3 倍）——**大促期间基线本身就高，只看绝对阈值会漏**。
- **业务指标的回滚要更保守**：**技术指标（错误率/延迟）可以秒级判定**，**业务指标（转化率）有天然波动，要等样本量够 + 连续 2~3 个窗口都差**才回滚。
- **回滚动作要分级**：**一级 = 关开关（亚秒）**、**二级 = 切流量回上一档（秒级）**、**三级 = 回滚代码（分钟级）**——**能用一级解决就别用三级**。
- **回滚后必须验证**：**回滚动作发出 ≠ 已恢复**，**要看指标真的回到基线**——**很多事故是「回滚了但没生效」，因为配置缓存没刷新**。
- 易错点：单窗口判定就回滚（噪声触发）；只看绝对阈值；回滚后不看指标确认；回滚了代码但缓存/连接池里还是旧配置。

**示例代码**
```java
import java.util.ArrayList;
import java.util.List;

public class AutoRollback {
    // 一个观测窗口的数据
    record Window(int idx, long requests, double errRate, double p99Ms, double cvr) {
    }

    record Baseline(double errRate, double p99Ms, double cvr) {
    }

    // 回滚判据：连续 N 个窗口不达标才回滚
    static class Judge {
        final Baseline base;
        final int consecutive;
        final List<String> history = new ArrayList<>();
        int badStreak;

        Judge(Baseline base, int consecutive) {
            this.base = base;
            this.consecutive = consecutive;
        }

        boolean fired;

        // 返回 null 表示继续观察，否则返回回滚原因
        String evaluate(Window w) {
            if (fired) {
                history.add("窗口" + w.idx() + "：已回滚，不再判定");
                return "已回滚";
            }
            List<String> reasons = new ArrayList<>();

            // 技术指标：绝对阈值
            if (w.errRate() > 0.01) {
                reasons.add(String.format("错误率 %.2f%% > 绝对阈值 1.00%%", w.errRate() * 100));
            }
            // 技术指标：相对阈值（基线 3 倍）
            if (w.errRate() > base.errRate() * 3) {
                reasons.add(String.format("错误率是基线 %.1f 倍（%.2f%% vs %.2f%%）",
                        w.errRate() / base.errRate(), w.errRate() * 100, base.errRate() * 100));
            }
            if (w.p99Ms() > base.p99Ms() * 2) {
                reasons.add(String.format("P99 是基线 %.1f 倍（%.0fms vs %.0fms）",
                        w.p99Ms() / base.p99Ms(), w.p99Ms(), base.p99Ms()));
            }
            // 业务指标：相对跌幅 > 20%
            if (w.cvr() < base.cvr() * 0.8) {
                reasons.add(String.format("转化率跌到基线的 %.0f%%（%.2f%% vs %.2f%%）",
                        w.cvr() / base.cvr() * 100, w.cvr() * 100, base.cvr() * 100));
            }

            if (reasons.isEmpty()) {
                badStreak = 0;
                history.add("窗口" + w.idx() + "：正常");
                return null;
            }
            badStreak++;
            String joined = String.join("；", reasons);
            if (badStreak >= consecutive) {
                fired = true;
                history.add("窗口" + w.idx() + "：连续 " + badStreak + " 个窗口不达标 -> 回滚");
                return joined + "（连续 " + badStreak + " 个窗口）";
            }
            history.add("窗口" + w.idx() + "：不达标但只连续 " + badStreak + " 个，继续观察");
            return null;
        }
    }

    public static void main(String[] args) {
        Baseline base = new Baseline(0.002, 250, 0.030);

        System.out.println("【场景1】单点抖动：第 3 个窗口 P99 突然飙到 900ms，随后立刻恢复");
        Judge j1 = new Judge(base, 2);
        List<Window> run1 = List.of(
                new Window(1, 50_000, 0.0020, 255, 0.0301),
                new Window(2, 50_000, 0.0022, 248, 0.0299),
                new Window(3, 50_000, 0.0021, 900, 0.0300),   // 抖动
                new Window(4, 50_000, 0.0019, 252, 0.0302),
                new Window(5, 50_000, 0.0020, 249, 0.0300));
        for (Window w : run1) {
            String r = j1.evaluate(w);
            System.out.printf("  窗口%d P99=%4.0fms -> %s%n", w.idx(), w.p99Ms(),
                    r == null ? "继续" : "回滚：" + r);
        }
        System.out.println("  结论：只抖动一个窗口，被「连续 2 个窗口」规则挡住了，不回滚");

        System.out.println();
        System.out.println("【场景2】真的坏了：从第 2 个窗口起错误率一直是基线的 3.7 倍以上");
        Judge j2 = new Judge(base, 2);
        List<Window> run2 = List.of(
                new Window(1, 50_000, 0.0020, 250, 0.0300),
                new Window(2, 50_000, 0.0075, 260, 0.0298),   // 3.75 倍
                new Window(3, 50_000, 0.0080, 265, 0.0295),   // 连续第 2 个
                new Window(4, 50_000, 0.0082, 270, 0.0290));
        for (Window w : run2) {
            String r = j2.evaluate(w);
            System.out.printf("  窗口%d 错误率=%.2f%% -> %s%n", w.idx(), w.errRate() * 100,
                    r == null ? "继续" : (r.equals("已回滚") ? "已回滚，后续窗口不再判定" : "回滚：" + r));
        }

        System.out.println();
        System.out.println("【场景3】业务指标跌了：转化率 3.00% -> 2.30%，技术指标全正常");
        Judge j3 = new Judge(base, 2);
        List<Window> run3 = List.of(
                new Window(1, 50_000, 0.0021, 251, 0.0230),
                new Window(2, 50_000, 0.0020, 249, 0.0228),
                new Window(3, 50_000, 0.0022, 253, 0.0231));
        for (Window w : run3) {
            String r = j3.evaluate(w);
            System.out.printf("  窗口%d 转化率=%.2f%% -> %s%n", w.idx(), w.cvr() * 100,
                    r == null ? "继续" : (r.equals("已回滚") ? "已回滚，后续窗口不再判定" : "回滚：" + r));
        }
        System.out.println("  结论：技术指标全绿也会回滚——「能跑但没人买」同样是事故");

        System.out.println();
        System.out.println("【回滚分级】");
        System.out.println("  一级 关开关    ：<1s，适用「新逻辑可以整体关掉」");
        System.out.println("  二级 切流量    ：~5s，适用「旧版本实例还在」");
        System.out.println("  三级 回滚代码  ：2~10min，适用「开关兜不住的结构性问题」");
        System.out.println("  原则：能一级解决就别用三级；每次回滚后必须确认指标真的回到基线");
    }
}
```

**课后练习**
1. 把 consecutive 从 2 改成 1，重跑场景1，观察抖动是否触发回滚，说明「回滚风暴」是怎么来的。
2. 给 Judge 加一条「连续 5 个窗口错误率缓慢上升」的漂移检测，说明为什么单窗口判定抓不到慢故障。
3. 思考题：为什么业务指标的回滚阈值要用「相对基线的百分比」而不是绝对值？从「不同业务的转化率量级不同」分析。

### 82-07 实验分层与正交设计

**知识点**
- **一个用户可能同时在多个实验里**：**推荐算法实验 + UI 改版实验 + 价格展示实验**——**如果都从同一份流量里随机切，实验之间会互相污染**。
- **分层（Layer）**：**把流量按维度切成互不重叠的层**，**不同层用不同的 hash 种子**——**同一层的实验互斥，不同层的实验正交**。
- **正交的含义**：**A 实验的对照组/实验组里，B 实验的分组比例都应该是 50/50**——**这样才能各自独立归因**，**用交叉表就能验证**。
- **互斥（同层）**：**同一层内流量只能进一个实验**——**否则两个改版叠加，你不知道是谁的功劳**，**但会浪费流量（流量不够时要做流量复用）**。
- **分层的代价**：**层数越多，每层能用的流量越少**——**层是「互斥换清晰」，正交是「复用换效率」**，**两者要按实验数量权衡**。
- 易错点：hash 的 key 里不带层名（同一个用户在所有层分组完全一致）；同层放两个实验（互相污染）；分层后忘了验证交叉表（以为正交其实不正交）。

**示例代码**
```java
import java.util.LinkedHashMap;
import java.util.Map;

public class ExperimentLayers {
    // 稳定分桶，种子不同 -> 不同层互相独立
    static int bucket(String userId, int seed, int mod) {
        int h = seed;
        for (int i = 0; i < userId.length(); i++) {
            h ^= userId.charAt(i);
            h *= 0x01000193;
        }
        return Math.floorMod(h, mod);
    }

    // 一层的分流：0 = 对照组，1 = 实验组。key 里带层名 -> 同一个人在不同层的分组互相独立
    static int assign(String userId, String layer, int seed) {
        return bucket(userId + ":" + layer, seed, 100) < 50 ? 1 : 0;
    }

    // 错误做法：key 里不带层名，同一个 seed 就会让两层完全相关
    static int assignSharedKey(String userId, int seed) {
        return bucket(userId, seed, 100) < 50 ? 1 : 0;
    }

    public static void main(String[] args) {
        String[] layers = {"推荐算法", "UI改版", "价格展示"};
        int[] seeds = {0x811C9DC5, 0x12345678, 0x9E3779B9};

        int n = 200_000;
        // 统计：每个用户在三层的分组组合
        Map<String, Integer> cross = new LinkedHashMap<>();
        int[] solo = new int[3];                 // 每层实验组人数
        for (int i = 0; i < n; i++) {
            String u = "u" + i;
            int a = assign(u, layers[0], seeds[0]);
            int b = assign(u, layers[1], seeds[1]);
            int c = assign(u, layers[2], seeds[2]);
            solo[0] += a;
            solo[1] += b;
            solo[2] += c;
            cross.merge("" + a + b + c, 1, Integer::sum);
        }

        System.out.println("【三层实验，各自 50/50】共 " + n + " 个用户");
        for (int i = 0; i < layers.length; i++) {
            System.out.printf("  %-10s 实验组 %6d (%.2f%%)%n",
                    layers[i], solo[i], solo[i] * 100.0 / n);
        }

        System.out.println();
        System.out.println("【正交验证：A 实验分组 × B 实验分组的交叉表】");
        System.out.println("  如果两层独立，每个格子的占比都应该接近 25%");
        Map<String, Integer> pair = new LinkedHashMap<>();
        for (int i = 0; i < n; i++) {
            String u = "u" + i;
            int a = assign(u, layers[0], seeds[0]);
            int b = assign(u, layers[1], seeds[1]);
            pair.merge("" + a + b, 1, Integer::sum);
        }
        System.out.printf("%-12s %-18s %-18s%n", "", "B=对照", "B=实验");
        for (int a = 0; a <= 1; a++) {
            System.out.printf("%-12s", "A=" + (a == 0 ? "对照" : "实验"));
            for (int b = 0; b <= 1; b++) {
                int cnt = pair.getOrDefault("" + a + b, 0);
                System.out.printf("%-18s", cnt + String.format(" (%.2f%%)", cnt * 100.0 / n));
            }
            System.out.println();
        }
        System.out.println("  -> 四个格子都在 25% 附近，说明两层正交，可以各自独立归因");

        System.out.println();
        System.out.println("【对照：key 不带层名 + 同一个种子 -> 完全相关，不正交】");
        Map<String, Integer> badPair = new LinkedHashMap<>();
        for (int i = 0; i < n; i++) {
            String u = "u" + i;
            int a = assignSharedKey(u, seeds[0]);
            int b = assignSharedKey(u, seeds[0]);     // 同一个 key + 同一个种子
            badPair.merge("" + a + b, 1, Integer::sum);
        }
        System.out.printf("%-12s %-18s %-18s%n", "", "B=对照", "B=实验");
        for (int a = 0; a <= 1; a++) {
            System.out.printf("%-12s", "A=" + (a == 0 ? "对照" : "实验"));
            for (int b = 0; b <= 1; b++) {
                int cnt = badPair.getOrDefault("" + a + b, 0);
                System.out.printf("%-18s", cnt + String.format(" (%.2f%%)", cnt * 100.0 / n));
            }
            System.out.println();
        }
        System.out.println("  -> 只有对角两个格子有数据：进了 A 实验的人必然也进 B 实验");
        System.out.println("     这时 B 的效果里混着 A 的效果，两个实验的结论都不可信");
        System.out.println("     修法：bucket 的 key 里带上层名（本课 assign 的写法），或每层换一个种子");

        System.out.println();
        System.out.println("【8 种组合的分布】三层全交叉，应该均匀分成 8 份（各 12.5%）");
        cross.forEach((k, v) -> System.out.printf("  A/B/C=%s : %6d (%.2f%%)%n", k, v, v * 100.0 / n));

        System.out.println();
        System.out.println("【结论】层内互斥保证「同一份流量不打架」，跨层换种子保证「互不相关」；");
        System.out.println("  验证手段就是交叉表——格子均匀才叫正交，不均匀说明种子或分组逻辑有问题。");
    }
}
```

### 82-08 样本量与显著性：什么时候才算「真的涨了」

**知识点**
- **点估计不是结论**：**转化率 3.00% vs 3.30%** 看着「涨了 0.3 个点」，**但样本只有 2 万时这可能只是噪声**——**必须做假设检验，看「这个差异有多大可能是巧合」**。
- **两比例 z 检验**：**把两组转化率之差除以标准误得到 z**，**|z| > 1.96 时 p < 0.05**（双侧），**才能说「在 5% 显著性水平下差异显著」**。
- **样本量与效应大小成平方反比**：**想发现的差异缩小一半，样本量要涨 4 倍**——**想验证 0.1pp 的提升，样本量是验证 0.5pp 的 20 多倍**，**这是「小改动测不出来」的根本原因**。
- **最小样本量公式**：**n = (z_α/2 + z_β)² × [p₁(1-p₁) + p₂(1-p₂)] / (p₂-p₁)²**——**α 管「别乱报」，β 管「别漏报」**，**功效 0.8 意味着真有差异时 80% 能测出来**。
- **置信区间比 p 值信息量大**：**p < 0.05 只说「不为零」，置信区间告诉你「大概在 0.19~0.41 个点之间」**——**业务决策要看区间下界够不够覆盖成本**。
- 易错点：样本不够就下结论；只报 p 值不报区间；用「提升 10%」这种相对说法掩盖绝对值很小；功效不足却说「没差异」（应该是「没测出来」）。

**示例代码**
```java
public class SampleSize {
    // 正态分布 CDF：Abramowitz-Stegun 近似，误差 < 2e-7
    static double normalCdf(double z) {
        return 0.5 * (1 + erf(z / Math.sqrt(2)));
    }

    static double erf(double x) {
        double sign = x < 0 ? -1 : 1;
        double ax = Math.abs(x);
        double p = 0.3275911;
        double a1 = 0.254829592, a2 = -0.284496736, a3 = 1.421413741,
               a4 = -1.453152027, a5 = 1.061405429;
        double t = 1.0 / (1.0 + p * ax);
        double y = 1 - (((((a5 * t + a4) * t) + a3) * t + a2) * t + a1) * t * Math.exp(-ax * ax);
        return sign * y;
    }

    static final double Z_ALPHA = 1.959964;   // 双侧 alpha = 0.05
    static final double Z_BETA = 0.841621;    // 功效 = 0.8

    // 两比例检验，每组所需样本量
    static long sampleSizePerGroup(double p1, double p2) {
        double d = Math.abs(p2 - p1);
        double num = Math.pow(Z_ALPHA + Z_BETA, 2) * (p1 * (1 - p1) + p2 * (1 - p2));
        return (long) Math.ceil(num / (d * d));
    }

    // 两比例 z 检验（合并方差）
    static double zScore(long n1, long c1, long n2, long c2) {
        double p1 = (double) c1 / n1;
        double p2 = (double) c2 / n2;
        double pooled = (double) (c1 + c2) / (n1 + n2);
        double se = Math.sqrt(pooled * (1 - pooled) * (1.0 / n1 + 1.0 / n2));
        return (p2 - p1) / se;
    }

    static double pValue(double z) {
        return 2 * (1 - normalCdf(Math.abs(z)));
    }

    // 差值置信区间（非合并方差）
    static double[] diffCi(long n1, long c1, long n2, long c2) {
        double p1 = (double) c1 / n1;
        double p2 = (double) c2 / n2;
        double se = Math.sqrt(p1 * (1 - p1) / n1 + p2 * (1 - p2) / n2);
        double d = p2 - p1;
        return new double[]{d - Z_ALPHA * se, d + Z_ALPHA * se};
    }

    static void report(String label, long n1, long c1, long n2, long c2) {
        double p1 = (double) c1 / n1;
        double p2 = (double) c2 / n2;
        double z = zScore(n1, c1, n2, c2);
        double p = pValue(z);
        double[] ci = diffCi(n1, c1, n2, c2);
        System.out.printf("【%s】每组 %d 人%n", label, n1);
        System.out.printf("  对照组 %d/%d = %.2f%%   实验组 %d/%d = %.2f%%   差 %+.2fpp%n",
                c1, n1, p1 * 100, c2, n2, p2 * 100, (p2 - p1) * 100);
        System.out.printf("  z = %.3f   p = %.4f   95%%CI = [%+.3fpp, %+.3fpp]%n",
                z, p, ci[0] * 100, ci[1] * 100);
        if (p < 0.05) {
            System.out.println("  -> 显著：区间不含 0，可以下「有提升」的结论");
        } else {
            System.out.println("  -> 不显著：区间含 0，只能说「没测出差异」，不能说「没差异」");
        }
        System.out.println();
    }

    public static void main(String[] args) {
        double base = 0.030;

        System.out.println("【1. 最小样本量：效应越小，样本越贵】基线转化率 3.00%");
        System.out.printf("%-14s %-16s %-12s %s%n", "要发现的提升", "实验组转化率", "每组样本量", "相对 0.5pp");
        long ref = sampleSizePerGroup(base, base + 0.005);
        double[] deltas = {0.001, 0.003, 0.005};
        for (double d : deltas) {
            long n = sampleSizePerGroup(base, base + d);
            System.out.printf("%-14s %-16s %-12d %.1f 倍%n",
                    String.format("%.1fpp", d * 100),
                    String.format("%.2f%%", (base + d) * 100),
                    n, (double) n / ref);
        }
        System.out.println("  -> 效应缩到 1/5（0.5pp -> 0.1pp），样本量涨到 23 倍：这就是「小改动测不出来」");
        System.out.println();

        System.out.println("【2. 同样涨 0.3 个点，样本量决定结论】");
        report("2 万样本", 20_000, 600, 20_000, 660);
        report("20 万样本", 200_000, 6_000, 200_000, 6_600);

        System.out.println("【3. 样本量够不够，用公式核对】");
        long need = sampleSizePerGroup(base, base + 0.003);
        System.out.printf("  想以 80%% 功效发现 0.3pp 提升，每组需要 %d 人%n", need);
        System.out.printf("  2 万样本只有需求的 %.0f%% -> 难怪测不出来%n", 20_000 * 100.0 / need);
        System.out.printf("  20 万样本是需求的 %.1f 倍 -> 有富余，结论稳%n", 200_000.0 / need);
        System.out.println();

        System.out.println("【4. 决策看区间下界，不看 p 值】");
        double[] ci = diffCi(200_000, 6_000, 200_000, 6_600);
        System.out.printf("  20 万样本的 95%%CI 下界 = %+.3fpp%n", ci[0] * 100);
        System.out.println("  如果改造成本要求「至少涨 0.25pp 才回本」，下界 0.19pp < 0.25pp");
        System.out.println("  -> 虽然显著，但收益可能覆盖不了成本，这个结论要交给业务判断");
    }
}
```

### 82-09 SRM：先证明分流没偏，再谈实验结论

**知识点**
- **SRM（Sample Ratio Mismatch）**：**实际分流比例和设计比例显著不符**——**设计 50/50，实测 49.6/50.4**，**说明分流逻辑有 bug，后面所有结论都不可信**。
- **SRM 是实验的第一道体检**：**不通过 SRM 就直接看效果，等于在脏数据上做统计**——**很多「实验效果惊人」最后都查出来是分流偏差**。
- **卡方检验判 SRM**：**χ² = Σ(观测-期望)²/期望**，**自由度 1 时 χ² > 3.84 对应 p < 0.05**——**样本越大，能抓出的偏差越小**。
- **常见的 SRM 根因**：**分桶字段有 null/空值**（全部落到默认组）、**分流依赖的字段在新版本里变了**、**埋点丢失导致某组数据少**、**缓存了分组结果但配置改了**。
- **SRM 与「效果不好」的区别**：**SRM 是「数据本身不可信」**（要先修分流），**效果不好是「数据可信但结论是负的」**（要认）——**两者处理方式完全不同**。
- 易错点：只看总比例不看分组明细；样本小的时候 SRM 抓不出来就以为没问题；SRM 通过但埋点缺失（每组数据都少同样比例，比例正常但绝对值错）。

**示例代码**
```java
import java.util.ArrayList;
import java.util.List;

public class SrmCheck {
    static double normalCdf(double z) {
        return 0.5 * (1 + erf(z / Math.sqrt(2)));
    }

    static double erf(double x) {
        double sign = x < 0 ? -1 : 1;
        double ax = Math.abs(x);
        double p = 0.3275911;
        double a1 = 0.254829592, a2 = -0.284496736, a3 = 1.421413741,
               a4 = -1.453152027, a5 = 1.061405429;
        double t = 1.0 / (1.0 + p * ax);
        double y = 1 - (((((a5 * t + a4) * t) + a3) * t + a2) * t + a1) * t * Math.exp(-ax * ax);
        return sign * y;
    }

    // 两组卡方（期望比例 0.5/0.5）
    static double chi2(long o1, long o2) {
        double total = o1 + o2;
        double e = total / 2.0;
        return Math.pow(o1 - e, 2) / e + Math.pow(o2 - e, 2) / e;
    }

    // df = 1 时，chi2 = z^2
    static double pValueDf1(double chi2) {
        return 2 * (1 - normalCdf(Math.sqrt(chi2)));
    }

    static final double CRITICAL_005 = 3.8415;

    static void check(String label, long control, long treatment) {
        double x2 = chi2(control, treatment);
        double p = pValueDf1(x2);
        double total = control + treatment;
        double actual = control * 100.0 / total;
        String verdict = x2 > CRITICAL_005 ? "SRM 告警：分流有偏，结论不可信" : "通过";
        System.out.printf("【%s】对照 %d / 实验 %d（%.2f%% : %.2f%%）%n",
                label, control, treatment, actual, 100 - actual);
        System.out.printf("  chi^2 = %.3f   p = %.5f   临界值 3.8415   -> %s%n", x2, p, verdict);
        System.out.println();
    }

    public static void main(String[] args) {
        long total = 1_000_000;

        System.out.println("【1. 三种分流结果的卡方判定】共 " + total + " 人，设计 50:50");
        check("完美分流", 500_000, 500_000);
        check("轻微偏差 0.1%", 499_500, 500_500);
        check("明显偏差 0.36%", 498_200, 501_800);

        System.out.println("【2. 根因复现：null userId 全落对照组】");
        long nullUsers = 3_600;                  // 0.36% 的用户 userId 为空
        long normal = total - nullUsers;         // 996,400 人正常 hash
        long ctrl = normal / 2 + nullUsers;      // null 全进对照组
        long trt = normal - normal / 2;
        System.out.printf("  %d 个 userId 为 null 的用户，hash 拿不到值，默认走对照组%n", nullUsers);
        check("模拟 bug 后的分流", ctrl, trt);
        System.out.println("  -> 卡方把 0.36% 的偏差抓了出来；如果只看「大概一半一半」，根本发现不了");
        System.out.println();

        System.out.println("【3. 样本量决定 SRM 的灵敏度】设计 50:50，真实偏差固定为 0.36%");
        long[] totals = {20_000, 100_000, 1_000_000};
        for (long t : totals) {
            long dev = Math.round(t * 0.0036);       // 偏差占比固定，绝对人数随样本涨
            long o1 = t / 2 - dev / 2;
            long o2 = t / 2 + dev / 2;
            double x2 = chi2(o1, o2);
            System.out.printf("  总样本 %-10d 偏差 %6d 人（0.36%%）  chi^2 = %7.3f  -> %s%n",
                    t, dev, x2, x2 > CRITICAL_005 ? "抓到 SRM" : "抓不到");
        }
        System.out.println("  -> 同样是 0.36% 的偏差：2 万样本 chi^2 = 0.26、10 万样本 1.30 都抓不到，");
        System.out.println("     100 万样本 chi^2 = 12.96 才越过 3.84 的临界值");
        System.out.println("     所以「小样本阶段 SRM 通过」不等于分流真的没偏，只能说「这个量级看不出来」");
        System.out.println();

        System.out.println("【4. 排查清单】SRM 告警后按顺序查");
        List<String> steps = new ArrayList<>();
        steps.add("分流字段是否有 null / 空串 / 默认值（最常见）");
        steps.add("新旧版本的分流逻辑是否一致（灰度期间两套代码同时在跑）");
        steps.add("埋点上报是否某组丢失（客户端版本差异）");
        steps.add("分组结果是否被缓存、缓存 key 是否漏了实验 id");
        steps.add("上游流量本身是否有偏（某个渠道只命中某组）");
        for (int i = 0; i < steps.size(); i++) {
            System.out.printf("  %d. %s%n", i + 1, steps.get(i));
        }

        System.out.println();
        System.out.println("【结论】SRM 是实验的「体检」：先证明分流没偏，再谈效果好坏。");
        System.out.println("  比例不对 -> 修分流、重跑实验；比例对但效果差 -> 认这个结论。");
    }
}
```

2. 给 check 加第三个分组（三组 33.3/33.3/33.3），说明卡方检验怎么扩展到多组。

### 82-10 实验陷阱：多重比较、偷看与新奇效应

**知识点**
- **多重比较**：**一次实验看 10 个指标，每个都用 α=0.05 判**，**至少一个假阳性的概率是 1-0.95¹⁰ ≈ 40%**——**「总有一个指标涨了」不是好消息，是数学必然**。
- **Bonferroni 校正**：**看 m 个指标就把阈值降到 α/m**——**10 个指标用 0.005**，**代价是更难测出真实效应**（要更大样本）。
- **偷看（peeking）**：**实验没跑完就反复看 p 值，看到显著就停**——**每次看都是一次独立检验，看 10 次假阳性率从 5% 涨到 40%**，**这叫「p-hacking」**。
- **新奇效应（novelty effect）**：**用户对新 UI 好奇，首周数据虚高**，**第 2~4 周回落到真实水平**——**只看 3 天就下结论，会把「好奇」当成「价值」**。
- **对策**：**指标预先登记**（只看事先说好的 1 个主指标 + 少量护栏指标）、**固定样本量/固定时长再揭盲**、**至少跑满一个完整周（覆盖工作日与周末）**。
- 易错点：事后挑指标（先看哪个涨了再讲故事）；看 5 次数据就停；用首日数据决策；把「相对提升 20%」当成绝对值（基线 0.1% 涨到 0.12%）。

**示例代码**
```java
import java.util.Random;

public class ExperimentTraps {
    // 12 个均匀分布求和近似标准正态
    static double gaussian(Random r) {
        double s = 0;
        for (int i = 0; i < 12; i++) {
            s += r.nextDouble();
        }
        return s - 6;
    }

    public static void main(String[] args) {
        System.out.println("【1. 多重比较：10 个指标、真实无差异】");
        int metrics = 10;
        double fwer = 1 - Math.pow(0.95, metrics);
        System.out.printf("  每个指标 α=0.05，至少一个假阳性的概率 = 1 - 0.95^%d = %.2f%%%n",
                metrics, fwer * 100);
        System.out.printf("  Bonferroni 校正后阈值 = 0.05/%d = %.4f%n", metrics, 0.05 / metrics);
        System.out.println("  -> 校正前「总能挑出一个涨了的指标」，校正后基本挑不出来（这就是它该有的样子）");

        // 固定种子模拟：2000 个实验，每个实验看 10 个无差异指标
        Random rnd = new Random(20261120L);
        int expCount = 2000;
        int flagged = 0;
        int flaggedCorrected = 0;
        for (int e = 0; e < expCount; e++) {
            boolean any = false;
            boolean anyCorrected = false;
            for (int m = 0; m < metrics; m++) {
                double z = gaussian(rnd);
                double p = 2 * (1 - normalCdf(Math.abs(z)));
                if (p < 0.05) {
                    any = true;
                }
                if (p < 0.05 / metrics) {
                    anyCorrected = true;
                }
            }
            if (any) {
                flagged++;
            }
            if (anyCorrected) {
                flaggedCorrected++;
            }
        }
        System.out.printf("  固定种子模拟 %d 个无差异实验：未校正命中 %d 个（%.1f%%），"
                        + "校正后 %d 个（%.1f%%）%n",
                expCount, flagged, flagged * 100.0 / expCount,
                flaggedCorrected, flaggedCorrected * 100.0 / expCount);
        System.out.println();

        System.out.println("【2. 偷看：看 10 次 vs 只看 1 次】");
        Random r2 = new Random(20261120L);
        int looks = 10;
        int peekFlagged = 0;
        int onceFlagged = 0;
        int runs = 2000;
        for (int i = 0; i < runs; i++) {
            boolean any = false;
            for (int k = 0; k < looks; k++) {
                if (Math.abs(gaussian(r2)) > 1.96) {
                    any = true;
                }
            }
            if (any) {
                peekFlagged++;
            }
            if (Math.abs(gaussian(r2)) > 1.96) {
                onceFlagged++;
            }
        }
        System.out.printf("  A/A 实验（真实无差异）跑 %d 次：%n", runs);
        System.out.printf("    只看 1 次就停   -> 假阳性 %.1f%%（符合设计的 5%%）%n",
                onceFlagged * 100.0 / runs);
        System.out.printf("    看 10 次取最显著 -> 假阳性 %.1f%%（理论值 1-0.95^10 = %.1f%%）%n",
                peekFlagged * 100.0 / runs, (1 - Math.pow(0.95, looks)) * 100);
        System.out.println("  -> 多看的每一次都在给自己「中奖」的机会，必须预先固定样本量");

        System.out.println();
        System.out.println("【3. 新奇效应：首周数据会骗人】");
        double[] daily = {+1.20, +0.85, +0.42, +0.18, +0.05, -0.02, -0.08};
        System.out.println("  上线后每天相对基线的转化率变化（pp）：");
        double sum = 0;
        for (int d = 0; d < daily.length; d++) {
            System.out.printf("    第 %d 天 %+.2fpp%n", d + 1, daily[d]);
            sum += daily[d];
        }
        System.out.printf("  首日均值 %+.2fpp -> 七天均值 %+.2fpp，衰减了 %.0f%%%n",
                daily[0], sum / daily.length,
                (1 - (sum / daily.length) / daily[0]) * 100);
        System.out.println("  -> 只看前 3 天会得出「提升 0.82pp」；跑满一周只有「提升 0.37pp」");
        System.out.println("     如果收益线是 0.5pp，前三天的结论会直接让你上线一个亏钱的功能");

        System.out.println();
        System.out.println("【4. 三条纪律】");
        System.out.println("  1. 指标预先登记：1 个主指标 + 2~3 个护栏指标，其余只做参考不下结论");
        System.out.println("  2. 样本量/时长预先固定，到点才揭盲，中间不看 p 值");
        System.out.println("  3. 至少跑满 7 天（覆盖工作日与周末），警惕首周虚高");
    }

    static double normalCdf(double z) {
        return 0.5 * (1 + erf(z / Math.sqrt(2)));
    }

    static double erf(double x) {
        double sign = x < 0 ? -1 : 1;
        double ax = Math.abs(x);
        double p = 0.3275911;
        double a1 = 0.254829592, a2 = -0.284496736, a3 = 1.421413741,
               a4 = -1.453152027, a5 = 1.061405429;
        double t = 1.0 / (1.0 + p * ax);
        double y = 1 - (((((a5 * t + a4) * t) + a3) * t + a2) * t + a1) * t * Math.exp(-ax * ax);
        return sign * y;
    }
}
```

### 82-11 综合案例：大促前的一次灰度发布

**知识点**
- **案例背景**：**商品详情页要同时上线「新版价格展示」和「推荐算法换模型」**——**日活 800 万、峰值 QPS 2 万**，**要求 3 分钟内可回滚，两个改动各自独立评估**。
- **第一步选形态**：**价格展示是前端渲染逻辑 → 功能开关（秒级回滚）**；**推荐模型是后端服务 → 金丝雀 + 规则分流**——**能用开关的别用蓝绿，能切流量的别回滚代码**。
- **第二步定节奏**：**1%(10min) → 5%(15min) → 25%(30min) → 50%(30min) → 100%**，**每档检查错误率/P99/转化率**——**小档只卡技术指标，大档才判业务指标**（样本量不够）。
- **第三步设门禁**：**P99 > 400ms 或错误率 > 1% 或错误率 > 基线 3 倍 → 自动回退到上一档**——**连续 2 个 5 分钟窗口不达标才动手**，**防单点抖动造成回滚风暴**。
- **第四步判效果**：**推荐算法用两比例 z 检验 + SRM 校验**，**价格展示样本不够就说「测不出来」**——**不能因为「感觉变好了」就全量**。
- **复盘价值**：**这次 25% 档被 P99 拦下，暴露了连接池配置问题**——**如果没有门禁，这个问题会在 100% 流量下持续 30 分钟**，**影响面差 24 倍**。

**示例代码**
```java
public class GrayReleaseCase {
    // 放量档位
    record Stage(String name, int pct, int windowMin, double qps,
                 double errRate, double p99Ms, double cvr, String verdict) {
    }

    static final double PEAK_QPS = 20_000;
    static final double ERR_LIMIT = 0.010;
    static final double P99_LIMIT = 400;
    static final double BASE_ERR = 0.002;
    static final double BASE_CVR = 0.030;

    // 门禁判定
    static String gate(Stage s) {
        if (s.errRate() > ERR_LIMIT) {
            return "拦截：错误率 " + String.format("%.2f%%", s.errRate() * 100) + " > 1.00%";
        }
        if (s.errRate() > BASE_ERR * 3) {
            return "拦截：错误率是基线 " + String.format("%.1f 倍", s.errRate() / BASE_ERR);
        }
        if (s.p99Ms() > P99_LIMIT) {
            return "拦截：P99 " + String.format("%.0fms", s.p99Ms()) + " > 400ms";
        }
        return "通过";
    }

    static double requests(Stage s) {
        return s.qps() * s.windowMin() * 60;
    }

    public static void main(String[] args) {
        System.out.println("【案例】商品详情页灰度：日活 800 万，峰值 QPS 2 万");
        System.out.println();

        // 25% 档开始出现连接池竞争，P99 劣化
        Stage[] plan = {
                new Stage("1%", 1, 10, PEAK_QPS * 0.01, 0.0021, 262, 0.0302, ""),
                new Stage("5%", 5, 15, PEAK_QPS * 0.05, 0.0024, 271, 0.0301, ""),
                new Stage("25%", 25, 30, PEAK_QPS * 0.25, 0.0031, 480, 0.0299, ""),
                new Stage("50%", 50, 30, PEAK_QPS * 0.50, 0.0062, 760, 0.0290, ""),
                new Stage("100%", 100, 30, PEAK_QPS, 0.0200, 940, 0.0271, ""),
        };

        System.out.println("【放量时间线】");
        System.out.printf("%-6s %-8s %-12s %-10s %-9s %-9s %-9s %s%n",
                "档位", "窗口", "请求数", "错误率", "P99", "转化率", "门禁", "说明");
        boolean stopped = false;
        double blockedRequests = 0;
        int blockedIdx = -1;
        for (int i = 0; i < plan.length; i++) {
            Stage s = plan[i];
            String g;
            String note;
            if (stopped) {
                g = "—";
                note = "未执行（已回退）";
            } else {
                g = gate(s);
                if (g.equals("通过")) {
                    note = "继续放量";
                } else {
                    note = "自动回退到上一档";
                    stopped = true;
                    blockedIdx = i;
                    // 每 5 分钟检查一次，第一个检查点就拦下
                    blockedRequests = s.qps() * 5 * 60;
                }
            }
            System.out.printf("%-6s %-8s %-12.0f %-10s %-9s %-9s %-9s %s%n",
                    s.name(), s.windowMin() + "min", requests(s),
                    String.format("%.2f%%", s.errRate() * 100),
                    String.format("%.0fms", s.p99Ms()),
                    String.format("%.2f%%", s.cvr() * 100),
                    g, note);
        }

        System.out.println();
        System.out.println("【拦截点分析】");
        Stage bad = plan[blockedIdx];
        System.out.printf("  25%% 档 P99 %.0fms 超过 400ms 阈值，自动回退到 5%%%n", bad.p99Ms());
        System.out.println("  根因：新版本加了价格计算逻辑，连接池没扩容，25% 流量下开始排队");
        System.out.println("  修复：连接池 50 -> 200，重新从 1% 开始放量");
        System.out.println();

        System.out.println("【有门禁 vs 无门禁：影响面对比】");
        System.out.println("  假设没有门禁：25% 档的 P99 问题被忽略，一路放到 100%，问题在 100% 流量下暴露");
        double withGate = blockedRequests;
        Stage full = plan[plan.length - 1];
        double withoutGate = requests(full);
        System.out.printf("  无门禁：一路放到 100%%，跑满 30 分钟 -> %.0f 次请求，错误率 2.00%%%n",
                withoutGate);
        System.out.printf("          失败请求 %.0f 次%n", withoutGate * full.errRate());
        System.out.printf("  有门禁：25%% 档 5 分钟内拦下 -> %.0f 次请求，错误率 0.31%%%n",
                withGate);
        System.out.printf("          失败请求 %.0f 次%n", withGate * bad.errRate());
        System.out.printf("  -> 请求量差 %.0f 倍，失败量差 %.0f 倍%n",
                withoutGate / withGate,
                (withoutGate * full.errRate()) / (withGate * bad.errRate()));
        System.out.println();

        System.out.println("【实验判定：推荐算法（后端服务，金丝雀 + 分层实验）】");
        long n = 200_000;
        long c1 = 6_000;
        long c2 = 6_600;
        double p1 = (double) c1 / n;
        double p2 = (double) c2 / n;
        double pooled = (double) (c1 + c2) / (2 * n);
        double se = Math.sqrt(pooled * (1 - pooled) * 2.0 / n);
        double z = (p2 - p1) / se;
        double seCi = Math.sqrt(p1 * (1 - p1) / n + p2 * (1 - p2) / n);
        double lo = (p2 - p1) - 1.959964 * seCi;
        double hi = (p2 - p1) + 1.959964 * seCi;
        System.out.printf("  对照 %.2f%% vs 实验 %.2f%%，每组 %d 人%n", p1 * 100, p2 * 100, n);
        System.out.printf("  z = %.3f -> p < 0.0001，95%%CI = [%+.3fpp, %+.3fpp]%n",
                z, lo * 100, hi * 100);
        System.out.println("  SRM 校验：200000 / 200000，chi^2 = 0.000 -> 通过");
        System.out.println("  -> 显著且下界 0.19pp > 0，可以全量；但要盯第 2~4 周是否衰减");
        System.out.println();

        System.out.println("【实验判定：价格展示（前端，样本不够）】");
        long n2 = 40_000;
        long d1 = 1_200;
        long d2 = 1_220;
        double q1 = (double) d1 / n2;
        double q2 = (double) d2 / n2;
        double pooled2 = (double) (d1 + d2) / (2 * n2);
        double se2 = Math.sqrt(pooled2 * (1 - pooled2) * 2.0 / n2);
        double z2 = (q2 - q1) / se2;
        System.out.printf("  对照 %.2f%% vs 实验 %.2f%%，每组 %d 人%n", q1 * 100, q2 * 100, n2);
        System.out.printf("  z = %.3f -> 不显著（|z| < 1.96），只能说「没测出差异」%n", z2);
        System.out.printf("  想验证 0.05pp 的提升需要每组约 %.0f 万人%n",
                Math.ceil(Math.pow(1.959964 + 0.841621, 2)
                        * (q1 * (1 - q1) + q2 * (1 - q2))
                        / Math.pow(0.0005, 2)) / 10_000);
        System.out.println("  -> 结论：价格展示继续观察，不因为「看起来涨了」就全量");
        System.out.println();

        System.out.println("【复盘：这次灰度做对的三件事】");
        System.out.println("  1. 形态选对：前端用开关、后端用金丝雀，回滚都是秒级");
        System.out.println("  2. 门禁拦住了：25% 档 P99 超阈值自动回退，影响面缩小 24 倍");
        System.out.println("  3. 结论分开：推荐算法显著可全量，价格展示样本不够就不下结论");
        System.out.println();
        System.out.println("【下次要改的】");
        System.out.println("  1. 连接池容量要进发布前检查清单（这次是靠门禁兜住的）");
        System.out.println("  2. 价格展示实验的样本量要提前算，避免跑了两周才发现不够");
        System.out.println("  3. 全量后要留 7 天观察窗口，警惕新奇效应衰减");
    }
}
```
