# 第6章 原理篇

本章从 Java 程序的运行机制讲起，带你认识内存与内存地址，搞清楚变量、方法、数组到底存在栈里还是堆里，学会用"内存图"分析代码行为，为后面的学习打下扎实的底层基础。

### 6-01 Java的运行机制

**知识点**
- Java 程序分两步走：先用 `javac` 编译，再用 `java` 命令运行
- 我们写的 `.java` 文件叫源文件（给人看的），编译后生成 `.class` 字节码文件（给 JVM 看的）
- JVM（Java 虚拟机）屏蔽了 Windows、Mac、Linux 底层的差异，同一份 `.class` 文件在哪个系统都能跑
- 这就是 Java 的核心优势："一次编译，到处运行"——跨平台靠的是 JVM，而不是字节码本身
- JDK 包含编译等开发工具，JRE 包含运行环境（内含 JVM）；只运行程序装 JRE 就够，要开发就装 JDK
- 易错点：文件扩展名被系统隐藏导致编译失败；public 类的类名必须与文件名完全一致

**示例代码**
```java
// 编译运行演示（在命令行中操作）：
// 第一步：javac RuntimeDemo.java   —— 编译，生成 RuntimeDemo.class
// 第二步：java  RuntimeDemo        —— 运行，由 JVM 执行字节码
public class RuntimeDemo {
    public static void main(String[] args) {
        // RuntimeDemo.java 是源文件，RuntimeDemo.class 是字节码文件
        // 字节码不直接面向某个操作系统，而是面向 JVM
        System.out.println("在 Windows 上编译出的 class 文件");
        System.out.println("拷到 Mac、Linux 上用 java 命令同样能运行");
        System.out.println("这就是 JVM 带来的跨平台特性");
    }
}
```

**课后练习**
1. 编写一个类 `SayHi`，运行后输出"我的第一个 Java 程序"，并在命令行手动完成编译、运行两步，把用到的命令记录下来。
2. 把编译生成的 `.class` 文件复制到另一个目录（有条件的话复制到另一台电脑或虚拟机），只用 `java` 命令运行它，观察是否依然成功，思考为什么不需要重新编译。
3. 把源文件改名为与类名不一致的文件再编译，观察报错信息，思考 `public` 类名与文件名的关系。

### 6-02 内存和内存地址

**知识点**
- 内存是程序运行时的临时存储空间：程序运行中的数据都放在内存里，程序结束或断电数据就消失
- 每一块内存都有一个编号，这个编号就是内存地址，可以类比成小区里的门牌号——按号找人、按地址找数据
- Java 把常用的内存区域分为两块：栈内存和堆内存
- 栈内存：方法运行时进入栈执行，方法内的局部变量存放在这里
- 堆内存：凡是 `new` 出来的东西（数组、对象）都存放在堆里，堆中的地址可以被多个变量记录
- 画内存图时用 `0x11`、`0x66` 这样的假想地址表示即可，真实地址对程序员是不可见的

**示例代码**
```java
public class MemoryDemo {
    public static void main(String[] args) {
        // 内存就像一排带门牌号的房间，存数据先开房间，靠地址找到它
        int a = 10; // 在 main 的栈空间里开一个格子，存值 10
        int b = 20; // 再开一个格子，存值 20

        int[] arr = new int[3];
        // new 出来的数组在【堆】中开辟 3 个连续格子（假设地址是 0x11）
        // 栈中的变量 arr 里存的不是数据，而是堆地址 0x11（引用）
        arr[0] = 66; // 通过地址 0x11 找到堆中的数组，给 0 号位置赋值

        System.out.println(a + "," + b + "," + arr[0]);

        /*
         * 执行完的内存示意图：
         * 栈：| a=10 | b=20 | arr=0x11 |
         * 堆：0x11 -> [66, 0, 0]
         */
    }
}
```

**课后练习**

2. 读代码预测输出：`int m = 1; int[] arr = {m, m}; arr[0] = 99;` 之后 `m` 和 `arr[0]` 分别是多少？结合内存图解释原因。

### 6-03 变量和方法的内存分配

**知识点**
- 基本类型变量（int、double、char、boolean 等）在栈上直接存"值"本身
- 方法被调用时才会进栈：在栈中开辟一块独立的栈帧，方法里的局部变量都存在自己的栈帧里
- 执行顺序：main 方法最先压栈，main 里调用谁，谁就压在 main 上面；谁先执行完谁先出栈
- 方法执行完立即出栈，栈帧连同里面的局部变量一起销毁——这就是局部变量"出了方法就没了"的原因
- 方法出栈前会把返回值交回给调用处，由调用处的变量接收
- 易错点：每个方法的变量只在自己栈帧里，方法之间互相访问不到对方的局部变量

**示例代码**
```java
public class StackDemo {
    public static void main(String[] args) {
        System.out.println("main 进栈，开始执行");
        int x = 10; // x 存在 main 自己的栈帧里
        int result = add(x, 20); // 调用 add：add 压在 main 上面进栈
        System.out.println("result = " + result); // add 出栈后，返回值交给了 result
        System.out.println("main 即将出栈，程序结束");
    }

    // 每次调用 add 都会在栈中开一个新栈帧，用完立刻销毁
    public static int add(int a, int b) {
        int sum = a + b; // sum 存在 add 的栈帧里，main 中的代码访问不到它
        System.out.println("add 进栈执行：" + a + " + " + b);
        return sum; // 返回后 add 出栈，sum 随之消失
    }
}
```

**课后练习**
1. 有三个方法 A、B、C，main 中先调用 A，A 内部调用 B，B 返回后 A 又调用 C。画出每一步的栈变化图，并标出 A、B、C 的出栈顺序。
2. 读代码预测输出（或指出编译错误）：方法 `add` 内部直接使用 `main` 中定义的变量 `x`，程序能否编译通过？为什么？

### 6-04 数组的内存分配

**知识点**
- `new int[3]` 会在堆中申请一块连续空间，存放数组的所有元素
- 栈中的数组变量存的是数组在堆中的地址，这个变量叫"引用"
- 数组元素有默认值：int 型是 0，double 型是 0.0，boolean 型是 false，引用类型是 null
- `arr.length` 是数组的长度属性，创建后长度固定不变
- 把一个数组变量赋值给另一个变量，只是复制了地址：两个引用指向同一个堆数组，通过任何一个修改都会互相影响
- 易错点：访问不存在的索引会抛出 `ArrayIndexOutOfBoundsException`（数组越界异常）

**示例代码**
```java
public class ArrayMemoryDemo {
    public static void main(String[] args) {
        int[] arr1 = new int[3];
        // 堆中开 3 个连续格子，默认值全是 0；arr1 的栈里存堆地址（假设 0x66）
        arr1[0] = 11;
        arr1[1] = 22;

        int[] arr2 = arr1; // 关键：没有 new！只是把 arr1 里的地址复制给了 arr2
        arr2[2] = 33;      // 通过 arr2 找到的和 arr1 是同一个数组

        System.out.println(arr1[2]); // 33 —— arr1 去看也被改了，因为是同一块内存
        System.out.println(arr2[0]); // 11

        int[] arr3 = new int[4];     // new 才会真正开辟新数组，元素默认值 0
        System.out.println(arr3[0]); // 0
        System.out.println(arr3.length); // 4

        /*
         * 内存示意图：
         * 栈                 堆
         * arr1 = 0x66 ──┐
         *               ├──> 0x66: [11, 22, 33]   （同一个数组）
         * arr2 = 0x66 ──┘
         * arr3 = 0x88 ────> 0x88: [0, 0, 0, 0]
         */
    }
}
```

### 6-05 数组在方法中传递

**知识点**
- 数组作为方法参数传递时，传的是堆中的地址（引用传递效果），并不会把数组复制一份
- 调用方法后，实参和形参两个变量记录的是同一个堆数组的地址
- 因此方法内通过形参修改数组元素，方法结束后外面的原数组也跟着变了
- 对比：基本类型传参传的是"值的副本"，方法内修改副本，不影响外面的原变量
- 如果方法内对形参重新赋值（如 `arr = new int[5]`），只是改变了形参自己的指向，与外面的原数组再无关系
- 易错点口诀："改元素"有效（操作同一块堆内存），"换数组"无效（只是换了形参的指向）

**示例代码**
```java
public class ArrayPassDemo {
    public static void main(String[] args) {
        int[] arr = {1, 2, 3};

        changeValue(arr); // 传的是地址：main 的 arr 和方法的 arr 指向同一个堆数组
        System.out.println(arr[0]); // 100 —— 原数组真的被改了

        int num = 10;
        changeNum(num); // 基本类型传的是值的副本
        System.out.println(num); // 10 —— 原值纹丝不动

        newArray(arr); // 方法里重新 new 了一个新数组
        System.out.println(arr[0]); // 还是 100 —— 换的是方法内形参的指向

        /*
         * 内存变化：main: arr=0x99 ──> 0x99: [100, 2, 3]
         * changeValue/newArray 的形参 arr 同样 = 0x99（newArray 中最后改成 0xAA 指向新数组）
         */
    }

    public static void changeValue(int[] arr) {
        arr[0] = 100; // 通过地址直接修改堆中的数据，对调用方可见
    }

    public static void changeNum(int num) {
        num = 100; // 改的只是副本，影响不到 main 里的 num
    }

    public static void newArray(int[] arr) {
        arr = new int[5]; // 形参改指新数组，原数组毫发无损
        arr[0] = 999;     // 改的也是新数组
    }
}
```
