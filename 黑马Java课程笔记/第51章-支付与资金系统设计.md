# 第51章 支付与资金系统设计

全书反复出现"支付"，本章把它拆开做完整设计。支付系统是资金的路由器：状态机保证只进不退、三层幂等键防重复扣款、渠道对接有验签与熔断路由、对账是最后防线、退款比支付复杂一个量级、复式记账让每一分钱有去向——**资金域的一切错误都以钱为单位**，36 章安全、39 章一致性、41 章发布、42 章观测在这里全部强化到资金级。本章按「支付全景 → 渠道对接验签 → 状态机与幂等 → 回调可靠 → 对账闭环 → 退款链路 → 资金安全三防线 → 清结算复式记账 → 分布式事务 → 高可用降级 → 端到端时序案例」的顺序讲。所有示例仍是纯 JDK：状态机竞态裁决真跑，三层幂等去重真执行，分录借贷平衡真实校验，对账四类差异真跑闭环，不需要真实支付渠道。

### 51-01 支付系统全景

**知识点**
- **支付系统是"资金的路由器"**：用户 -> 商户收银台 -> 支付网关（自己）-> 支付渠道（微信/支付宝/银行）-> 清结算 -> 商户账户。**每一跳都是资金**，每一跳的错误都以钱为单位——这就是为什么支付系统有全书最严格的质量标准（36 章安全、39 章一致性、44-09 权限在这里全部强化）。
- **核心域划分**：**收银**（面向用户：聚合支付方式）、**支付核心**（状态机+渠道路由）、**渠道网关**（对接外部支付渠道）、**账务**（复式记账，51-08）、**对账**（51-05）、**清算结算**（资金划拨）、**风控**（51-07）。**域与域之间事件驱动**（49-03），资金路径上强一致。
- **支付系统的三高要求**：**一致性**（一分钱都不能错——39-09 的本地消息表在资金域是标配）、**可靠性**（渠道抖动不能影响用户支付——降级路由多渠道）、**可审计**（每笔资金变动可追溯——事件溯源 49-06 的天然场景）。
- **钱的单位纪律**：全部用**分（long/int）**存储与计算，绝不用 double/float（14 章 BigDecimal 在支付域的纪律升级：整数分单位是行业标准）；展示层才转元。
- **与订单域的关系**：订单域发"待支付"事件 -> 支付域创建支付单 -> 渠道回调 -> 支付域发"支付成功"事件 -> 订单域推进状态。**支付单与订单单分离**（一笔订单可能多笔支付尝试）——单据模型是设计第一课。
- 易错点：金额用浮点（对账差分）；支付单与订单混用（重试语义混乱）；没有幂等键体系（重复扣款）；渠道返回"处理中"被当成失败（状态机断裂）。

### 51-02 渠道对接与签名验签

**知识点**
- **渠道对接的三件事**：① **请求签名**（用商户私钥对参数签名，渠道验签防篡改）；② **回调验签**（渠道用其私钥回调，你用渠道公钥验签——**验签不过一律拒绝**，36 章安全原则的资金级执行）；③ **证书/密钥管理**（密钥不入库不入 git，KMS/Vault 管理，36 章供应链教训）。
- **渠道协议的共性**：下单接口（返回支付凭据如 prepay_id）、查询接口（主动查单补状态）、回调通知（异步告知结果）、退款接口、对账文件下载（51-05）。**抽象成统一渠道网关接口**（49-04 端口），各渠道适配器实现——新增渠道=新增适配器。
- **渠道返回码的语义分级**：成功 / 处理中（未知态！）/ 失败 ——**"处理中"必须转查询轮询**，绝不能当失败（51-03 状态机）。渠道码翻译进防腐层（49-07），领域只见自己的状态。
- **主动查询补状态**：回调可能丢（渠道侧事故）——**支付单超时未终态 -> 定时查渠道**（1s/5s/30s 退避，指数退避 40-02），查询结果与回调结果幂等合并（先到先得，状态机只进不退）。
- **渠道路由**：多渠道可用时按**成功率/费率/限额**路由——渠道熔断（连续失败摘除，47-03 电路思想）+ 降级到备用渠道（44-08 阶梯）。渠道故障是支付系统最常见的生产事故。
- 易错点：回调不验签直接处理（伪造回调=资金损失）；"处理中"当失败关单（渠道随后成功 -> 已关单但扣了钱 -> 客诉+资损）；密钥进代码库（36 章教训）；渠道超时与支付单超时不匹配（渠道还在处理你已关单）。

**示例代码**

```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class ChannelIntegration {
    /** 渠道返回码 -> 领域状态（防腐层 49-07） */
    enum PaymentStatus {
        SUCCESS, PENDING, FAILED
    }

    record ChannelResult(PaymentStatus status, String channelTxId, String rawCode) {
    }

    static class ChannelAdapter {
        private static final Map<String, PaymentStatus> CODE_MAP = Map.of(
                "SUCCESS", PaymentStatus.SUCCESS,
                "PROCESSING", PaymentStatus.PENDING,
                "USERPAYING", PaymentStatus.PENDING,
                "FAIL", PaymentStatus.FAILED);

        ChannelResult normalize(String code, String txId, String signature, boolean signatureValid) {
            if (!signatureValid) {
                throw new IllegalStateException("回调验签失败 -> 拒绝处理（防伪造）");
            }
            PaymentStatus s = CODE_MAP.getOrDefault(code, PaymentStatus.PENDING);   // 未知码按 PENDING 走查询
            return new ChannelResult(s, txId, code);
        }
    }

    static void normalizeDemo() {
        System.out.println("【渠道码归一：未知码按 PENDING 处理】");
        ChannelAdapter adapter = new ChannelAdapter();
        for (String[] raw : new String[][]{{"SUCCESS", "ok"}, {"PROCESSING", "ok"},
                {"USERPAYING", "ok"}, {"NEWCODE_X", "ok（未映射）"}}) {
            ChannelResult r = adapter.normalize(raw[0], "ch-tx-1", "", true);
            System.out.printf("  渠道码 %-12s -> %s（txId=%s）%n", raw[0], r.status(), r.channelTxId());
        }
        try {
            adapter.normalize("SUCCESS", "ch-tx-2", "", false);
        } catch (IllegalStateException e) {
            System.out.println("  验签失败：" + e.getMessage());
        }
        System.out.println("  关键：PENDING 不是终态 -> 进入查询轮询（下一段代码）");
        System.out.println();
    }

    static void queryPolling() {
        System.out.println("【主动查询：回调丢失时的补状态机制】");
        long[] backoffs = {1000, 5000, 30000, 60000};
        String current = "PENDING";
        for (long backoff : backoffs) {
            if (current.equals("PENDING")) {
                // 模拟第 3 次查询渠道返回成功
                current = backoff == 30000 ? "SUCCESS" : "PENDING";
                System.out.printf("  等待 %ds 后查询渠道 -> %s%n", backoff / 1000, current);
            }
        }
        System.out.println("  终态后停止轮询；全部轮询用尽 -> 差异单进人工（51-05）");
        System.out.println("  幂等合并：查询与回调谁先到都一样（状态机只进不退，51-03）");
        System.out.println();
    }

    static void routing() {
        System.out.println("【渠道路由：成功率/费率/熔断】");
        record Channel(String name, double feeRate, double successRate, boolean circuitOpen) {
        }
        List<Channel> channels = List.of(
                new Channel("wechat", 0.006, 0.999, false),
                new Channel("alipay", 0.006, 0.998, false),
                new Channel("union-b", 0.005, 0.97, true));   // 熔断中：连续失败被摘除
        for (Channel c : channels) {
            System.out.printf("  %-8s 费率=%.1f%% 成功率=%.1f%% 熔断=%s%n",
                    c.name(), c.feeRate() * 100, c.successRate() * 100,
                    c.circuitOpen() ? "开（摘除）" : "关");
        }
        System.out.println("  路由决策：过滤熔断渠道 -> 剩余按费率/成功率加权选择");
        System.out.println("  熔断恢复：半开探测成功 -> 重新纳入（47-03 同款三态）");
    }

    public static void main(String[] args) {
        normalizeDemo();
        queryPolling();
        routing();
    }
}
```

### 51-03 支付状态机与幂等

**知识点**
- **支付单状态机是支付核心的骨架**：`CREATED -> PAYING -> SUCCESS / FAILED / CLOSED`，**只进不退**（SUCCESS 不可回 FAILED）；每个转移有前置条件与触发事件——**状态机保证并发回调/查询/关单的合并结果正确**。
- **并发场景的状态机裁决**：回调（成功）与关单任务（超时关闭）同时到达——**用状态机 + 数据库行锁（乐观版本号）串行化**：先到者赢，后到者按当前状态裁决（已 SUCCESS 则关单无效；已 CLOSED 则回调触发"已关闭但有款"差异单进人工/自动退款）。
- **幂等键体系是防重复扣款的根基**：三层——**业务幂等键**（orderId+支付渠道尝试号）、**渠道交易号**（channelTxId 唯一约束）、**回调幂等**（渠道通知 ID 去重表）。**同一支付请求无论重放多少次，最多扣一次款**（39/43 章幂等原则的资金级执行）。
- **创建支付单的幂等**：用户双击支付按钮 -> 两次创建请求 -> **以 orderId+场景为幂等键**返回同一支付单（而不是创建两张）；过期支付单自动关闭（延迟队列 28 章）后允许新建。
- **状态转移的持久化原子性**：状态更新 + 账务记账 + 事件发出必须原子（39-09）——支付域内用**本地事务**（同库）或 outbox；跨域靠事件最终一致。
- 易错点：状态机用 if-else 散落实现（转移规则无法审计，49 章状态建模退步）；重复回调重复记账（幂等缺失，直接资损）；关单与回调竞态未处理（已关单但扣款成功无人处理）；乐观锁缺失（两个并发回调都成功）。

**示例代码**
```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class PaymentStateMachine {
    enum Status {
        CREATED, PAYING, SUCCESS, FAILED, CLOSED
    }

    /** 状态机：合法转移表（只进不退） */
    static final Map<Status, List<Status>> TRANSITIONS = Map.of(
            Status.CREATED, List.of(Status.PAYING, Status.CLOSED),
            Status.PAYING, List.of(Status.SUCCESS, Status.FAILED, Status.CLOSED));

    static class Payment {
        String id;
        Status status = Status.CREATED;
        long version = 0;                       // 乐观锁版本

        Payment(String id) {
            this.id = id;
        }

        /** CAS 式转移：先到者赢，后到者按当前状态裁决 */
        synchronized boolean transition(Status target, String trigger) {
            List<Status> allowed = TRANSITIONS.get(status);
            if (allowed == null || !allowed.contains(target)) {
                System.out.printf("  [%s] %s --%s--> %s 被拒绝（当前 %s 无此转移）%n",
                        id, status, trigger, target, status);
                return false;
            }
            status = target;
            version++;
            System.out.printf("  [%s] %s --%s--> %s (v%d)%n", id, status, trigger, target, version);
            return true;
        }
    }

    static void raceAdjudication() {
        System.out.println("【竞态裁决：回调成功 vs 超时关单同时到达】");
        Payment p = new Payment("PAY-1");
        p.transition(Status.PAYING, "用户发起");
        boolean closed = p.transition(Status.CLOSED, "关单任务（超时）");
        boolean paid = p.transition(Status.SUCCESS, "渠道回调（晚到）");
        System.out.println("  终态：" + p.status);
        if (closed && paid) {
            System.out.println("  竞态结果：先关单后回调成功 -> 已关单但有款");
            System.out.println("  处置：差异单 -> 自动原路退款 + 告警（51-05 差异闭环）");
        }
        System.out.println("  状态机只进不退：CLOSED 拒绝 SUCCESS 转移 -> 数据不被打乱");
        System.out.println();
    }

    static void idempotencyLayers() {
        System.out.println("【三层幂等键：重复请求最多扣一次款】");
        String[][] layers = {
                {"业务幂等键", "orderId+attemptNo -> 建单接口返回同一支付单", "防用户双击重复建单"},
                {"渠道交易号", "channelTxId 唯一索引", "防回调重放重复记账"},
                {"回调通知 ID", "notifyId 去重表", "渠道同一通知发多次"},
        };
        for (String[] l : layers) {
            System.out.printf("  %-10s %-38s %s%n", l[0], l[1], l[2]);
        }
        Map<String, Integer> dedupe = new LinkedHashMap<>();
        dedupe.put("notify-n1", 1);
        Integer seen = dedupe.putIfAbsent("notify-n1", 2);
        System.out.println("  模拟：同一 notifyId 第二次到达 -> putIfAbsent 发现已存在 -> 忽略（返回首次结果）");
        System.out.println();
    }

    static void atomicity() {
        System.out.println("【状态转移的原子性打包】");
        List<String> bundle = List.of(
                "① 支付单状态更新（乐观锁 version 校验）",
                "② 账务分录插入（51-08 借贷平衡）",
                "③ 事件写入 outbox（PaymentSucceeded）",
                "以上在同一数据库事务内提交 —— 39-09 本地事务的资金级应用");
        for (String s : bundle) {
            System.out.println("  " + s);
        }
        System.out.println("  反例：状态改了事件没发 -> 订单永远待支付（对账发现，51-05）");
    }

    public static void main(String[] args) {
        raceAdjudication();
        idempotencyLayers();
        atomicity();
    }
}
```

### 51-04 异步回调与通知可靠

**知识点**
- **回调是支付结果的主通道，但不可靠**：渠道回调可能重复（多次通知）、乱序（查单与回调交错）、丢失（渠道事故）——**回调处理必须幂等 + 查询兜底**（51-02），回调只是"加速器"，不是"唯一事实来源"。
- **回调处理的黄金流程**：验签 -> 幂等检查（notifyId/channelTxId）-> 状态机裁决 -> 本地事务（状态+账务+outbox）-> 返回渠道应答（success）——**任何一步失败都返回失败应答**让渠道重试（渠道会按退避重发）。
- **应答协议要严格遵守**：微信返回 XML/JSON success、支付宝返回 "success" 字符串——**应答格式错误渠道会无限重发**（打爆接口）；应答 success 但处理失败 = 静默丢事件（对账才能发现）。
- **对外通知（商户侧回调）同样要可靠**：支付成功后通知下游商户——**同样的重试 + 幂等 + 签名**（你是渠道，商户是你的下游），通知失败进重试队列（28 章延迟队列）。
- **回调风暴防护**：渠道重试风暴（网络故障恢复后积压回调齐发）——限流 + 去重后处理；**去重表先行**（验签前先查已处理，省验签开销可权衡）。
- 易错点：处理失败也返回 success（丢事件）；验签前先改状态（伪造回调直接改钱）；回调处理超时（渠道判定失败重发 -> 重复处理，幂等救场）；通知商户不带签名（商户侧无法验真）。

**示例代码**
```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class CallbackReliability {
    static class CallbackHandler {
        final Map<String, String> processed = new LinkedHashMap<>();    // notifyId -> 应答
        final Map<String, String> payments = new LinkedHashMap<>();     // txId -> 状态

        String handle(String notifyId, String txId, String event,
                      boolean signatureValid, boolean processWillFail) {
            // 1) 幂等前置：同 notifyId 已处理 -> 直接返回首次应答
            String prior = processed.get(notifyId);
            if (prior != null) {
                System.out.printf("  notify=%s 重复 -> 返回首次应答 %s（不重复处理）%n",
                        notifyId, prior);
                return prior;
            }
            // 2) 验签
            if (!signatureValid) {
                return "FAIL:invalid-signature";
            }
            // 3) 处理（状态机 + 记账 + outbox）
            String ack;
            if (processWillFail) {
                ack = "FAIL:processing-error";      // 处理失败 -> 返回失败，渠道会重试
            } else {
                payments.put(txId, event);
                ack = "success";
                processed.put(notifyId, ack);
                System.out.printf("  notify=%s 处理成功：txId=%s -> %s%n", notifyId, txId, event);
            }
            return ack;
        }
    }

    static void flowDemo() {
        System.out.println("【回调处理黄金流程与失败重试】");
        CallbackHandler handler = new CallbackHandler();
        System.out.println("  第一次回调（处理成功）：");
        System.out.println("    应答：" + handler.handle("n-1", "ch-1", "SUCCESS", true, false));
        System.out.println("  渠道重发同通知（网络原因）：");
        System.out.println("    应答：" + handler.handle("n-1", "ch-1", "SUCCESS", true, false));
        System.out.println("  处理中途故障的回调：");
        String ack = handler.handle("n-2", "ch-2", "SUCCESS", true, true);
        System.out.println("    应答：" + ack + " -> 渠道按退避重试 -> 下次成功");
        System.out.println("  关键：失败必须返回失败应答，绝不能返回 success 掩盖问题");
        System.out.println();
    }

    static void ackProtocol() {
        System.out.println("【应答协议：格式错误 = 无限重发】");
        String[][] rows = {
                {"微信支付", "返回 XML/JSON success 标记", "格式错 -> 渠道按退避持续重发"},
                {"支付宝", "纯文本 success", "多余空格都算失败"},
                {"通用原则", "成功才 success；失败返回失败标记", "让渠道的重试机制工作"},
        };
        for (String[] r : rows) {
            System.out.printf("  %-10s %-32s %s%n", r[0], r[1], r[2]);
        }
        System.out.println("  事故对照：处理失败却返回 success -> 渠道认为完成 -> 事件永久丢失");
        System.out.println("  兜底：即便如此，51-05 对账仍能发现（对账是最后防线）");
        System.out.println();
    }

    static void notifyDownstream() {
        System.out.println("【对外通知商户：你是渠道的角色】");
        List<String> duties = List.of(
                "通知内容签名（商户可验真，51-02 反向）",
                "重试策略：指数退避 + 最大次数 + 死信人工（28 章队列语义）",
                "商户确认应答校验（商户回 success 才算送达）",
                "通知查询接口：商户可主动拉取（回调丢失的兜底，对称 51-02）",
                "审计：每次通知的请求/应答/耗时全落库（41-10 台账思想）");
        for (String d : duties) {
            System.out.println("  - " + d);
        }
        System.out.println("  对称性：渠道如何对你，你就如何对商户 —— 协议镜像原则");
    }

    public static void main(String[] args) {

        ackProtocol();
        notifyDownstream();
```

### 51-05 对账系统

**知识点**
- **对账是资金安全的最后防线**：回调丢失、状态机 bug、渠道异常——所有上游失误最终都会体现在"渠道账单 vs 本地流水"的差异里。**每天 T+1 对账一次是底线**（高频交易可小时级），对账发现的问题必须有闭环处理流程。
- **对账的输入与流程**：渠道账单文件（下载/解析/入库）-> 与本地支付流水按**渠道交易号**对齐 -> 三态分类：**两边一致**（通过）、**长款**（渠道有本地无——回调丢失/处理失败）、**短款**（本地有渠道无——重复记账/伪造）-> 差异单进处理流程。
- **差异处理的分级闭环**：长款（渠道成功本地未处理）-> 自动补处理（查单 -> 状态机推进 -> 补记账）；短款（本地成功渠道无）-> 严重问题（可能资损/伪造）-> 立即冻结 + 人工排查；金额不一致 -> 精确到分的差异记录 -> 人工裁决。**差异单是工单，有 SLA 有责任人**（41-10 台账思想）。
- **对账文件本身的可靠性**：渠道账单可能分片、有总额行（校验行数与金额合计）、字符集/分隔符差异（46-09 数据集成的老问题）——**文件级校验先行**（总额对不上不进明细对账，先查文件解析）。
- **对账的粒度与时效**：日对账（T+1）兜底 + **准实时对账**（小时级增量）缩短发现窗口——**发现延迟决定资损敞口**（凌晨丢 1000 笔回调，第二天才对账 = 敞口一天）。
- 易错点：对账结果只出报表无闭环（差异单无人处理）；只对金额不对状态（状态漏推发现不了）；渠道账单字段假设过强（渠道改版解析崩）；差异单无 SLA（积压一个月）。

**示例代码**
```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class ReconciliationSystem {
    record LocalTx(String channelTxId, long amountCents, String status) {
    }

    record ChannelTx(String channelTxId, long amountCents, String status) {
    }

    enum DiffType {
        MATCH, LONG, SHORT, AMOUNT_MISMATCH
    }

    record Diff(DiffType type, String channelTxId, String detail, String action) {
    }

    static void reconcile() {
        System.out.println("【日终对账：渠道账单 vs 本地流水】");
        Map<String, LocalTx> local = new LinkedHashMap<>();
        local.put("ch-1", new LocalTx("ch-1", 6900, "SUCCESS"));
        local.put("ch-2", new LocalTx("ch-2", 3900, "SUCCESS"));
        local.put("ch-3", new LocalTx("ch-3", 5900, "SUCCESS"));
        Map<String, ChannelTx> channel = new LinkedHashMap<>();
        channel.put("ch-1", new ChannelTx("ch-1", 6900, "SUCCESS"));
        channel.put("ch-2", new ChannelTx("ch-2", 3900, "SUCCESS"));
        channel.put("ch-4", new ChannelTx("ch-4", 12900, "SUCCESS"));   // 渠道有本地无（回调丢失）
        channel.put("ch-3", new ChannelTx("ch-3", 590, "SUCCESS"));     // 金额不一致
        List<Diff> diffs = new ArrayList<>();
        for (Map.Entry<String, ChannelTx> e : channel.entrySet()) {
            LocalTx lt = local.get(e.getKey());
            if (lt == null) {
                diffs.add(new Diff(DiffType.LONG, e.getKey(),
                        "渠道成功本地缺失", "查单补处理：推进状态机 + 补记账"));
            } else if (lt.amountCents() != e.getValue().amountCents()) {
                diffs.add(new Diff(DiffType.AMOUNT_MISMATCH, e.getKey(),
                        "本地 " + lt.amountCents() + " vs 渠道 " + e.getValue().amountCents(),
                        "冻结 + 人工裁决（精确到分）"));
            } else {
                diffs.add(new Diff(DiffType.MATCH, e.getKey(), "一致", "通过"));
            }
        }
        for (String id : local.keySet()) {
            if (!channel.containsKey(id)) {
                diffs.add(new Diff(DiffType.SHORT, id, "本地成功渠道无",
                        "严重：疑似伪造/重复记账 -> 冻结 + 立即排查"));
            }
        }
        for (Diff d : diffs) {
            System.out.printf("  [%-15s] %-6s %s%n    处置：%s%n", d.type(), d.channelTxId(),
                    d.detail(), d.action());
        }
        System.out.println();
    }

    static void fileValidation() {
        System.out.println("【账单文件先校验，再进明细对账】");
        record Check(String item, String method, String result) {
        }
        List<Check> checks = List.of(
                new Check("总行数", "文件行数 = 明细行 + 头尾行", "PASS"),
                new Check("金额合计", "明细金额合计 = 汇总行金额", "FAIL：差 12900 分"),
                new Check("处理", "总额不平 -> 不进明细对账", "FAIL：先查解析/分片"));
        for (Check c : checks) {
            System.out.printf("  %-8s %-30s %s%n", c.item(), c.method(), c.result());
        }
        System.out.println("  原因：文件分片下载漏了一段 -> 明细对账会误报海量短款");
        System.out.println("  文件级校验把「解析问题」与「真实差异」分开 —— 排障不混线");
        System.out.println();
    }

    static void slaLoop() {
        System.out.println("【差异单的 SLA 闭环】");
        List<String> loop = List.of(
                "差异单生成 -> 分级：长款（自动可处理）/ 短款（冻结人工）/ 金额差（人工）",
                "长款自动补处理：查单 -> 状态机推进 -> 补记账 -> 复核",
                "短款冻结：相关支付单挂起，禁止后续操作，4 小时内响应",
                "月度差异分析：分类统计根因（回调丢失/状态机 bug/渠道异常）-> 进改进项",
                "目标：差异单平均处理时长 < 24h，长款自动处理率 > 90%");
        for (String s : loop) {
            System.out.println("  " + s);
        }
        System.out.println("  对账不是报表，是闭环流程 —— 42-11 复盘思想在资金域的常态运行");
    }

    public static void main(String[] args) {
        reconcile();
        fileValidation();
        slaLoop();
    }
}
```

### 51-06 退款链路

**知识点**
- **退款比支付复杂一个量级**：支付是单向流转，退款涉及**部分退款、多次退款、退款上限、原路退回、退款失败重试**——每一项都能引出错账。**退款总额不可超实付**是不变量（聚合校验 49-02 的资金版）。
- **部分退款的分摊**：退 30 元从哪些明细扣？**按明细分摊 + 尾差规则**（49-09 的分摊算法在退款复用）；优惠分摊退回规则（优惠券部分退还还是作废）是业务契约（46-08），必须在创建订单时就定义。
- **原路退回的渠道约束**：退回原支付渠道（微信付的退微信）——**渠道退款单号幂等**、退款可能 PENDING（渠道处理中）、退款失败要重试（渠道余额不足等临时错）；**退款也有对账**（渠道退款账单 vs 本地退款流水）。
- **退款状态机**：`REFUND_CREATED -> REFUNDING -> SUCCESS / FAILED`——与支付状态机同构（51-03 原则复用），**退款不可超实付**的校验在"创建退款单"时以剩余可退金额计算。
- **退款与履约的联动**：退款成功 -> 触发库存回补（事件）、优惠券是否返还（规则）、发票红冲（合规）——**退款是跨域事件源**（49-03 的发出方）。
- 易错点：可退金额计算不含已退款（超退资损）；部分退款分摊不一致（对账差分）；退款 PENDING 当失败重发（渠道重复退款）；退款成功后不回补库存（超卖数据错乱）。

**示例代码**
```java
import java.util.ArrayList;
import java.util.List;

public class RefundComplexity {
    /** 订单聚合视角：可退金额 = 实付 - 已退（不变量） */
    static class Order {
        final String orderId;
        final long paidCents;
        long refundedCents = 0;
        final List<String> refundIds = new ArrayList<>();

        Order(String orderId, long paidCents) {
            this.orderId = orderId;
            this.paidCents = paidCents;
        }

        long refundableCents() {
            return paidCents - refundedCents;
        }

        /** 创建退款单：不变量校验在聚合内 */
        String applyRefund(long amountCents, String refundId) {
            if (amountCents <= 0) {
                throw new IllegalArgumentException("退款金额必须为正");
            }
            if (amountCents > refundableCents()) {
                throw new IllegalArgumentException(
                        "可退 " + refundableCents() + " 分，申请 " + amountCents + " 分 -> 超退拒绝");
            }
            refundedCents += amountCents;
            refundIds.add(refundId);
            System.out.printf("  退款单 %s：%d 分（剩余可退 %d 分）%n",
                    refundId, amountCents, refundableCents());
            return refundId;
        }
    }

    static void refundFlow() {
        System.out.println("【部分退款与超退拦截】");
        Order order = new Order("9001", 6900);
        order.applyRefund(2000, "RF-1");        // 部分退 20 元
        order.applyRefund(4900, "RF-2");        // 再退剩余
        try {
            order.applyRefund(100, "RF-3");     // 已退满 -> 超退
        } catch (IllegalArgumentException e) {
            System.out.println("  超退被聚合拒绝：" + e.getMessage());
        }
        System.out.println("  不变量「累计退款 ≤ 实付」在聚合内闭环 —— 49-02 的资金应用");
        System.out.println();
    }

    static void refundStateMachine() {
        System.out.println("【退款单状态机与 PENDING 处理】");
        String[][] flow = {
                {"REFUND_CREATED", "校验可退额 -> 发起渠道退款", "本地事务"},
                {"REFUNDING", "渠道受理中（PENDING）", "查询轮询（51-02 同款）"},
                {"REFUND_SUCCESS", "渠道确认退款", "触发库存回补/券返还事件"},
                {"REFUND_FAILED", "渠道明确失败", "重试或人工；可退额度恢复"},
        };
        for (String[] f : flow) {
            System.out.printf("  %-16s %-28s %s%n", f[0], f[1], f[2]);
        }
        System.out.println("  关键：REFUNDING 不当失败重发（渠道重复退款）—— 查询确认终态");
        System.out.println();
    }

    static void refundAllocation() {
        System.out.println("【部分退款的分摊：明细级扣减】");
        long[] linePaid = {3000, 2000, 1900};      // 三明细实付（分）
        long refund = 3000;
        long remaining = refund;
        List<Long> alloc = new ArrayList<>();
        for (int i = 0; i < linePaid.length; i++) {
            long take = Math.min(remaining, linePaid[i]);
            alloc.add(take);
            remaining -= take;
        }
        for (int i = 0; i < alloc.size(); i++) {
            System.out.printf("  明细%d 实付 %d -> 退 %d（剩余可退 %d）%n",
                    i + 1, linePaid[i], alloc.get(i), linePaid[i] - alloc.get(i));
        }
        System.out.println("  尾差规则与 49-09 相同：契约定义，最后行吸收");
        System.out.println("  优惠券分摊退回规则在订单创建时即定义（46-08 契约）");
    }

    public static void main(String[] args) {
        refundFlow();
        refundStateMachine();
        refundAllocation();
    }
}
```

### 51-07 资金安全与风控

**知识点**
- **资金安全的三道防线**：**事前风控**（交易前识别风险：限流/拦截/增强验证）、**事中校验**（支付链路的参数与权限校验，44-09 四道闸的资金版）、**事后对账与审计**（51-05 + 操作审计不可抵赖）。**任何一道都不能独立兜底**。
- **风控的规则与模型**：规则层（单用户限额、频次、黑名单、地域异常——确定性高、可解释）；模型层（评分/异常检测——覆盖规则盲区）；**决策动作分级**：放行 / 增强验证（二次确认/短信）/ 拦截（44-09 的分级思想）。
- **操作审计与最小权限**：后台的退款/调价/改单操作——**操作人+审批+全量审计日志**（44-09 trace 的资金版）；退款审批走双人（41-10 紧急通道的资金版）；**系统账号与人工操作权限分离**。
- **防内部作恶**：改金额接口只允许服务调用（外部不可达）、金额以数据库为准（模型输出仅参考 40-06）、敏感操作二次确认（独立确认通道）——**信任边界在资金域一寸不让**（36 章原则）。

### 51-08 清结算与复式记账

**知识点**
- **账务的基石是复式记账**：每笔资金变动记**借贷两方**（借：应收/银行存款，贷：收入/应付）——**有借必有贷，借贷必相等**；任何时刻试算平衡（借方合计 = 贷方合计）是账务正确性的硬校验。**"钱去哪了"每一分都可追**。
- **账户体系**：用户账户、商户账户、平台收入账户、渠道清算户——**账户只是记账的维度**，余额 = 该账户分录的合计。内部户（平台收入）与外部户（用户/商户）分账簿。
- **清算与结算**：**清算**算清楚谁欠谁多少（渠道 T+1 账单 -> 应结算金额，扣除手续费）；**结算**实际资金划拨（打款给商户）。**结算依赖对账通过**（51-05 未平的差异暂停结算）。
- **分账与手续费**：平台型业务（用户付 100 -> 商户 90 + 平台 10）的分账分录——每笔交易拆多条分录，**手续费、退款、调价都影响分账**——分账规则是商户契约（46-08）。
- **账务与业务事件的原子性**：支付成功事件 -> 账务分录（51-03 同事务打包）——**账务落后于业务 = 账实不符**，日终"业务流水 vs 账务分录"再对一遍（第二层对账）。
- 易错点：单式记账（只有流水没有借贷，对不平）；分录与业务事件不同事务（丢分录）；手续费计算舍入不一致（渠道与本地差分）；退款分录方向搞反（试算失衡）。

```java
import java.util.ArrayList;
import java.util.List;

public class ClearingLedger {
    /** 分录：复式记账（借贷相等） */
    record Entry(String account, String direction, long amountCents) {
        boolean isDebit() {
            return "DEBIT".equals(direction);
        }
    }

    record Voucher(String voucherId, List<Entry> entries, String bizType) {
        boolean balanced() {
            long debit = entries.stream().filter(Entry::isDebit).mapToLong(Entry::amountCents).sum();
            long credit = entries.stream().filter(e -> !e.isDebit()).mapToLong(Entry::amountCents).sum();
            return debit == credit;
        }
    }

    static void voucherDemo() {
        System.out.println("【一笔支付的分录：用户付 100 元，手续费 0.6 元，商户入账 99.4 元】");
        List<Entry> entries = List.of(
                new Entry("渠道清算户", "DEBIT", 10000),          // 借：收到渠道资金
                new Entry("商户应付户", "CREDIT", 9940),          // 贷：应付商户
                new Entry("平台收入户", "CREDIT", 60));           // 贷：手续费收入
        Voucher v = new Voucher("V-1", entries, "PAYMENT");
        for (Entry e : entries) {
            System.out.printf("  %-6s %-8s %d 分%n", e.account(), e.isDebit() ? "借" : "贷", e.amountCents());
        }
        System.out.printf("  借方合计 %d = 贷方合计 %d -> 试算平衡：%b%n",
                entries.stream().filter(Entry::isDebit).mapToLong(Entry::amountCents).sum(),
                entries.stream().filter(e -> !e.isDebit()).mapToLong(Entry::amountCents).sum(),
                v.balanced());
        System.out.println("  10000 = 9940 + 60 —— 每一分钱都有去向");
        System.out.println();
    }

    static void refundVoucher() {
        System.out.println("【退款分录：反向冲正】");
        List<Entry> entries = List.of(
                new Entry("商户应付户", "DEBIT", 2000),           // 借：冲减应付商户
                new Entry("渠道清算户", "CREDIT", 2000));         // 贷：资金退回用户
        Voucher v = new Voucher("V-2", entries, "REFUND");
        System.out.printf("  退款 20 元：借商户应付 %d = 贷渠道清算 %d -> 平衡：%b%n",
                2000, 2000, v.balanced());
        System.out.println("  方向搞反 -> 试算失衡当场发现 —— 复式记账自带纠错检测");
        System.out.println();
    }

    static void clearingFlow() {
        System.out.println("【清算结算：从渠道账单到打款】");
        List<String> flow = List.of(
                "T+1 渠道账单 -> 对账通过（51-05）",
                "清算：应收渠道金额 - 手续费 = 应结算商户额（分账规则）",
                "结算批次生成 -> 财务复核 -> 打款指令",
                "差异未平的商户 -> 暂停结算（差额进待处理）",
                "结算完成 -> 分录核销 -> 商户余额可查");
        for (String s : flow) {
            System.out.println("  " + s);
        }
        System.out.println("  对账是结算的前置闸门：差异未平不放款 —— 资金安全顺序不可颠倒");
    }

    public static void main(String[] args) {
        voucherDemo();

    }
}
```

### 51-09 分布式事务在支付

**知识点**
- **支付域内的一致性分层**：**强一致**（支付单状态+账务分录+outbox 同库同事务，51-03）；**最终一致**（跨域：订单/履约/积分，事件驱动 49-03）；**对账兜底**（51-05 收口）——39-09 的方案光谱在资金域的取舍：**XA 不用（锁与吞吐）、TCC 用于资金冻结场景、本地消息表是主力**。
- **TCC 在支付的真实场景**：**余额冻结**（账户系统：Try 冻结额度、Confirm 扣减、Cancel 解冻）——预扣资源的场景 TCC 语义最自然；**空回滚与悬挂的防护**（44 章同款三态纪律）在资金上绝对不能省。
- **本地消息表的支付版细节**：outbox 与支付单同库（同事务）-> 投递 PaymentSucceeded；**消息按订单号分区保序**（39-08）；**消费幂等键 = 事件 ID**；投递失败指数退避 + 死信告警——**"事件丢了"在支付域等于"订单永远待支付"**，可靠级别最高。
- **反向补偿**：支付成功但下游履约失败——**支付不回滚**（钱已到账），下游走补偿（重发履约/人工）——**"钱的事实不可逆，业务流程可补偿"**是支付域分布式事务的核心认知。
- **一致性监控**：业务流水 vs 账务分录日终核对（51-08 第二层对账）、outbox 积压告警、事件消费 lag——**一致性指标进告警**（42 章方法论）。
- 易错点：跨域用同步调用串联（一条链断全链断，49-08 分布式单体）；消息无分区保序（状态乱序回退）；消费幂等缺失（重复履约/重复发货）；把"支付成功"事件的消费失败当可丢（必须死信+人工）。

**示例代码**
```java
import java.util.ArrayList;
import java.util.List;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

public class PaymentTransactions {
    /** TCC：账户余额冻结（资金域最自然的 TCC 场景） */
    static class AccountTcc {
        final Map<String, long[]> accounts = new ConcurrentHashMap<>();   // user -> {可用, 冻结}

        AccountTcc() {
            accounts.put("u1", new long[]{100_000, 0});
        }

        boolean tryFreeze(String user, long amount) {
            long[] a = accounts.get(user);
            if (a[0] < amount) {
                return false;
            }
            a[0] -= amount;
            a[1] += amount;
            System.out.printf("  Try：冻结 %d 分（可用 %d / 冻结 %d）%n", amount, a[0], a[1]);
            return true;
        }

        void confirm(String user, long amount) {
            long[] a = accounts.get(user);
            a[1] -= amount;
            System.out.printf("  Confirm：扣除冻结 %d 分（冻结剩 %d）%n", amount, a[1]);
        }

        void cancel(String user, long amount) {
            long[] a = accounts.get(user);
            a[1] -= amount;
            a[0] += amount;
            System.out.printf("  Cancel：解冻 %d 分（可用恢复 %d）%n", amount, a[0]);
        }
    }

    static void tccFlow() {
        System.out.println("【TCC 三阶段与空回滚防护】");
        AccountTcc tcc = new AccountTcc();
        boolean ok = tcc.tryFreeze("u1", 6900);
        if (ok) {
            tcc.confirm("u1", 6900);
        } else {
            tcc.cancel("u1", 6900);
        }
        System.out.println("  空回滚场景：Try 网络丢失，Cancel 先到 -> 记空标记，Cancel 成功返回");
        System.out.println("  悬挂场景：Cancel 之后 Try 才到 -> 检查空标记直接拒绝");
        System.out.println("  幂等键 = 事务 xid（44-09 同款），三接口全部幂等");
        System.out.println();
    }

    static void outboxDelivery() {
        System.out.println("【outbox 投递与分区保序】");
        record OutboxEvent(String eventId, String orderId, String type) {
        }
        List<OutboxEvent> outbox = List.of(
                new OutboxEvent("e1", "9001", "PaymentSucceeded"),
                new OutboxEvent("e2", "9001", "RefundSucceeded"),
                new OutboxEvent("e3", "9002", "PaymentSucceeded"));
        System.out.println("  投递路由：按 orderId 分区（同一订单事件保序）");
        Map<String, List<String>> partitioned = new java.util.LinkedHashMap<>();
        for (OutboxEvent e : outbox) {
            partitioned.computeIfAbsent(e.orderId(), k -> new ArrayList<>()).add(e.type());
        }
        for (Map.Entry<String, List<String>> e : partitioned.entrySet()) {
            System.out.printf("  分区[%s] -> %s%n", e.getKey(), e.getValue());
        }
        System.out.println("  消费幂等：eventId 去重表（51-03 三层幂等的跨域层）");
        System.out.println("  监控：outbox 积压 >0 持续 5min 告警（42 章）");
        System.out.println();
    }

    static void compensatationPrinciple() {
        System.out.println("【反向补偿：钱不可逆，流程可补偿】");
        List<String> cases = List.of(
                "支付成功但履约失败 -> 钱不退（支付事实成立），履约重试/人工补发",
                "支付成功但用户申请退款 -> 走退款链路（51-06），不是回滚支付",
                "积分发放失败 -> 补偿队列重发，不影响支付状态",
                "原则：支付状态机是事实锚点，其他域围绕它补偿（49-03）");
        for (String c : cases) {
            System.out.println("  " + c);
        }
        System.out.println("  对照错误做法：履约失败把支付状态回滚 FAILED -> 账实不符 + 客诉");
    }

    public static void main(String[] args) {
        tccFlow();
        outboxDelivery();
        compensatationPrinciple();
    }
```

### 51-10 支付高可用与降级

**知识点**
- **支付不可用的代价是 GMV 直接损失**——支付可用性目标通常是 99.99%（全年 53 分钟）。**单渠道故障 = 降级路由；渠道全故障 = 收银台降级（引导用户稍后/线下）；自己的支付核心故障 = 最严重事故**——每一层都有预案。
- **渠道路由的容灾设计**：主备渠道（主渠道熔断自动切备）、渠道配额与限额监控（渠道侧限额临近告警）、**渠道健康度实时看板**（47-05 拓扑思想）——**渠道故障演练**（47-10：模拟主渠道全挂，验证自动切换时长）。
- **支付核心的降级阶梯**：L1 正常 -> L2 关闭非核心功能（营销支付方式/分期）保核心 -> L3 排队限流（收银台提示排队）-> L4 线下预案（二维码轮询/延长订单有效期）。**预案要业务可执行**（值班手册粒度）。
- **核心链路的资源隔离**：支付核心的 DB/缓存与营销等系统隔离（39/47 章资源隔离思想）——**大促营销活动不能挤垮支付**；接口级限流（秒杀支付并发保护）。
- **演练清单**：渠道熔断切换、回调风暴、DB 主从切换（39-04）、对账文件缺失、时钟异常——**支付演练频率高于普通系统**（季度 -> 月度）。
- 易错点：只有单渠道（无容灾，渠道挂=全站停付）；降级预案纸面化（未演练）；营销活动共享支付资源（挤兑）；值班手册不含支付特有动作（查单/差异单处理流程）。

### 51-11 综合案例：一笔支付的端到端时序

**知识点**
- **把全章串成一笔支付的完整生命**：用户下单 -> 收银台 -> 支付单创建（幂等）-> 渠道下单（路由+签名）-> 用户支付 -> 渠道回调（验签+幂等+状态机）-> outbox 事件 -> 订单推进/账务分录/履约 -> 对账核销 ->（可选）退款。**51 章每一课在这条时序上各就各位**。
- **时序中的每一跳都有"失败分支"**：渠道下单失败（路由切备）、用户中途放弃（支付单超时关闭）、回调丢失（查询轮询）、重复回调（幂等去重）、退款申请（可退校验）——**主流程 8 步，失败分支 12 个**，每个分支都有明确处置。
- **验收清单**：幂等三键、状态机全覆盖、验签全通过、对账零差异、演练全达标——**支付系统上线前的最后关卡**（41 章发布工程的资金特化）。
- **复盘文化**：每笔资金差异单都是一次微型复盘（42-11），根因分类进改进项；**支付系统的成熟度由它处理过的异常种类决定**。
- 易错点：只测主流程（失败分支无测试覆盖）；时序图与代码漂移（文档过时）；新渠道接入无全分支用例（异常分支漏处理）；支付链路无 trace_id 贯通（排障翻多个系统日志）。
